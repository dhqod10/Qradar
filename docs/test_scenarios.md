## 0. 사용법 / 자동화 태그

각 시나리오는 **전제 → 단계 → 기대 결과 → 우선순위** 형식이다. 각 단계 끝의 태그는 자동화 실행 방식을 뜻한다.

| 태그 | 의미 |
|------|------|
| `[자동]` | Claude 가 iOS 시뮬레이터 접근성 라벨 기반(`tools/ios_sim.py`)으로 탭/이동/검증 가능 |
| `[수동-한글]` | 한글 텍스트 입력이 필요 — idb 가 ASCII 만 입력하므로 **사용자가 직접 입력** 후 Claude 가 이어받음 |
| `[결제-공동]` | 실결제/PG 구간 — **사용자와 함께** 진행 (자동화 제외) |
| `[확인]` | 화면 상태·문구·금액을 스크린샷 + 접근성 트리로 검증하는 단계 |

**우선순위**: 🔴 출시 필수 (happy path + 보안 가드) / 🟡 권장 (주요 분기) / ⚪ 선택 (엣지)

**실행 환경 전제**
- iOS 시뮬레이터 접근성 ON (`ApplicationAccessibilityEnabled=1`), 앱 포그라운드
- Android 는 adb 탭이 Flutter 버튼에서 불안정 → 보조 수단, 1차는 iOS
- DEV 시드 데이터 로딩됨 (MorePage long-press 트리거)

### G-01 가격 불일치 차단 (PRICE_MISMATCH) `[결제-공동]` 🔴
- 전제: 구버전 클라이언트(재가격 없음) 또는 조작으로 stale 금액 전송
- 단계: 메뉴 가격이 서버에서 다른 상태로 결제 시도 `[결제-공동]` `[확인]`
- 기대: 서버가 금액 재계산 후 **거절**, `paymentGateRejections` 에 `PRICE_MISMATCH`(shadow 키 없음, delta/serverExpected 기록). 고객은 결제 미청구 + `최신 가격으로 다시 담기` 버튼
- 우선순위: 🔴

### G-02 품절 / 판매중단 차단 `[결제-공동]` 🔴
- 전제: 점주가 품절 처리(O-04)한 메뉴를 카트에 담아둠
- 단계: 그 상태로 결제 시도 `[결제-공동]` `[확인]`
- 기대: 서버 거절(품절/판매중단 갈래), 거절 기록
- 우선순위: 🔴

### G-03 매장 상태 불가 차단 `[결제-공동]` 🔴
- 전제: 매장이 비승인/영업외 상태
- 단계: 결제 시도 `[결제-공동]` `[확인]`
- 기대: 서버가 매장 상태 재확인 후 거절
- 우선순위: 🔴

### G-04 옵션 불가 차단 (OPTION_UNAVAILABLE) `[결제-공동]` 🟡
- 전제: 선택한 옵션이 비활성/범위밖
- 단계: 결제 시도 `[결제-공동]` `[확인]`
- 기대: 서버 거절 `OPTION_UNAVAILABLE`
- 우선순위: 🟡

### G-05 brandKey 비공개 — 클라이언트 직접 쿼리 불가 `[자동]` 🟡
- 단계: 클라이언트에서 `brands.brandKey` 로 쿼리 시도(코드/규칙 레벨) `[확인]`
- 기대: 비공개라 조회 불가, 매칭은 `lookupBrandByKey` CF 로만
- 우선순위: 🟡

### G-06 점주 매장 삭제 불가 `[자동]` 🟡
- 단계: 점주 화면에서 삭제 경로 탐색 `[자동]`
- 기대: 삭제 버튼 없음(payment_server_authority D1), 안내 문구만
- 우선순위: 🟡
