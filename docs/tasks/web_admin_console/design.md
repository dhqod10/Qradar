- 입력: `docs/tasks/web_admin_console/spec.md` (Q1=B 새 웹 SPA / Q2=읽기 넓게+쓰기 좁게 / Q3=A `landing/console/`)
- 대상 산출물: `landing/console/index.html` + `landing/console/assets/console.css` + `admin.js` (HTML/CSS/JS. Flutter 위젯이 아니다)
- 디자인 레퍼런스: `docs/design/screens/` 에는 `home` 만 있고(모바일 앱 홈) 관리자 콘솔용 Figma 는 **없다**. `docs/design/components/` 에는 `bottom_nav.md` 뿐이라 재사용할 데스크톱 컴포넌트가 **없다**. 따라서 이 문서가 데스크톱 레이아웃의 최초 정의다.
- 기능 흐름 참조(모바일, 분기 조건만 확인, 레이아웃은 가져오지 않음): `lib/presentation/admin/approval/**`, `lib/presentation/common/widgets/reject_reason_dialog.dart`
- 진입점: `docs/processes/role_flows.md` §admin — 진입 수단이 "앱의 `AdminScaffold`" 에서 "앱 + 웹(`/console/index.html`)" 으로 하나 늘어난다. 새 역할 흐름은 없다. landing 에서 이 콘솔로 가는 링크는 **만들지 않는다**(Q3 조건 ②).

## 0. 먼저 읽을 것 — 결정이 필요한 불일치 2건

### 0-1. 브랜드 승인에는 `issueBrandKey` CF 호출이 따라붙는다 (spec 과 앱 코드가 어긋남)

spec §7.1 은 "1차는 CF 호출이 없다", §9.4 는 "상세에 '키 발급은 앱에서' 안내" 라고 적었다. 그러나 현재 앱의 `brand_repository_impl.dart` `approveBrand` 는 **`issueBrandKey` CF 를 먼저 호출해 성공한 뒤에만** `status='approved'` 를 쓴다(`role_flows.md` §4.4 도 동일하게 기술). 웹이 `status` 만 쓰면 **브랜드 키가 없는 approved 브랜드**가 생기고, 앱의 승인 화면은 pending 에서만 동작하므로 앱에서 키를 발급할 길이 없다.

이 문서는 **앱과 동일하게 "키 발급 성공 → 승인 기록" 2단계**로 설계했다(§6-3). 이 경우 1차의 CF 호출이 1건(`issueBrandKey`, 멱등, 리전 `asia-northeast3`) 생긴다. 대안은 "웹에서는 브랜드 반려만 허용하고 승인은 앱으로 안내"이며 §6-9 에 축소안을 적었다. **사용자/architect 결정 필요 (D1).**

### 0-2. 마스터 메뉴 / 매장 커스텀 큐는 읽기 전용이다

Q2 에 따라 쓰기는 브랜드·매장 2쌍뿐이다. 두 큐는 목록과 건수만 보여주고 **승인/반려 버튼을 두지 않는다.** "앱에서 처리" 안내만 둔다.

## 1. 디자인 원칙 (이 콘솔 한정)

1. **밝은 캔버스 + 미드나잇 네이비 포인트.** 랜딩/앱과 같은 톤. 네이비(`--primary`)는 주 행동과 활성 항목에만 쓴다.
2. **한 화면 한 결정.** 승인/반려는 상세 화면에서만, 한 번에 1건. 체크박스 다중 선택·일괄 처리 없음(spec §8-5).
3. **결과는 서버가 말한다.** 낙관적 UI 금지. 쓰기 응답을 받기 전에는 목록·배지·건수 어느 것도 바꾸지 않는다.
4. **실패는 제자리에서 보인다.** 실패하면 항목은 목록에 그대로 있고, 입력한 값(반려 사유)도 보존된다.
5. **숨김은 편의다.** 버튼 비활성화·화면 미렌더는 사용자 혼동을 줄이는 UX 이고 보안 장치가 아니다. 화면 문구 어디에도 "차단했습니다 / 보호됩니다 / 접근이 막혔습니다" 같이 UI 가 보안을 수행하는 듯한 표현을 쓰지 않는다(§9 문구 규칙).
6. **되돌릴 수 없는 일처럼 보이지 않게, 그러나 가볍게도 보이지 않게.** 승인/반려 모두 확인 모달을 거친다.

## 2. 디자인 토큰

> 색은 전부 `landing/assets/style.css` `:root` 변수를 **이름으로** 쓴다. 이 문서에 새 색상 값은 없다. `admin.css` 는 `style.css` 를 `<link>` 로 먼저 불러 변수를 상속한다(복붙 금지).

### 2-1. 사용 가능한 변수 (style.css 에서 확인)

| 분류 | 변수 | 값(설명용) |
|---|---|---|
| Brand | `--primary` `--primary-light` `--primary-bright` `--primary-deep` `--on-primary` `--accent` | 네이비 / 슬레이트 / 하늘 / 딥 / 흰색 / 골드 |
| Surface | `--background` `--surface` `--surface-elevated` `--border` | 흰 / 연회색 / 흰 / 회색선 |
| Text | `--text-heading` `--text-body` `--text-muted` | |
| Semantic | `--success` `--error` `--warning` `--info` | |
| 기타 | `--radius`(14px) `--shadow` `--wrap`(1080px) | |

### 2-2. 사용 금지 — 변수가 아닌 하드코딩 색

`style.css` 의 푸터·고객센터 블록에는 변수 없이 쓴 hex(`#CBD5E1` `#94A3B8` `#1E293B` `#64748B` `#E2E8F0` `#475569`)와 히어로 그라디언트 `#F8FAFC` 가 있다. **이 값들은 토큰이 아니므로 콘솔에서 복사하지 않는다.** 어두운 면 위의 보조 텍스트가 필요하면 `--on-primary` 에 `opacity: .72` 를 쓴다.

### 2-3. 색 용도 매핑

| 용도 | 변수 | 주의 |
|---|---|---|
| 페이지 배경 | `--background` | |
| 사이드바 배경 | `--surface` | 어두운 사이드바를 쓰지 않는다(네이비는 강조에만) |
| 카드·모달·표 | `--surface-elevated` + `1px solid var(--border)` + `--radius` | 그림자는 `var(--shadow)` 그대로 |
| 입력창 배경 | `--surface-elevated`, 테두리 `--border` | 포커스: `2px solid var(--primary-bright)` 링 |
| 제목 | `--text-heading` | |
| 본문 | `--text-body` | |
| 보조·캡션·라벨 | `--text-muted` | 14px 미만 + `--text-muted` 는 본문 정보에 쓰지 않는다(§2-6) |
| 주 행동(승인) 버튼 | 배경 `--primary` / 글자 `--on-primary` | |
| 보조 행동(반려, 취소, 새로고침) | 배경 `--surface-elevated` / 테두리 `--border` / 글자 `--text-heading` | **반려를 빨강으로 칠하지 않는다**(§6-1) |
| 활성 네비 항목 | 배경 `--primary` / 글자 `--on-primary` | |
| 링크 | 글자 `--primary` + 밑줄 | `--primary-bright` 는 흰 배경 위 텍스트로 쓰지 않는다 |
| 포커스 링, 선택 표시선, 로딩바 | `--primary-bright` | 텍스트 색으로는 금지(§2-6) |
| 에러 | 글자·아이콘 `--error`, 좌측 4px 바 `--error` | |
| 경고 | 좌측 4px 바 `--warning`, 글자는 `--text-heading` | |
| 정보 | 좌측 4px 바 `--primary-bright`(landing `.callout` 와 동일) | |
| 성공 | 점·아이콘 `--success`, 글자는 `--text-heading` | |
| Qoin 표식(아이콘/점) | `--accent` | 텍스트 색으로 쓰지 않는다 |

### 2-4. 파생 색 (새 값 아님)

연한 배경이 필요한 상태 배지·배너는 **변수끼리 섞는다**:

```
background: color-mix(in srgb, var(--warning) 14%, var(--surface-elevated));
```

`--warning` / `--error` / `--success` / `--primary-bright` 에 대해 같은 식(14%)만 허용한다. 퍼센트 외에 새 hex 를 만들지 않는다. `color-mix` 미지원 브라우저는 `--surface` 로 대체한다(`@supports not (background: color-mix(...))`).

### 2-5. 타이포그래피 (style.css 의 값과 맞춤)

폰트: `style.css` `body` 의 Pretendard 스택 상속. `word-break: keep-all` 유지. 제목 `letter-spacing: -.02em`.

| 역할 | 크기 | 굵기 | 색 | 줄높이 | style.css 대응 |
|---|---|---|---|---|---|
| 통계 숫자 | 34px | 800 | `--text-heading` | 1.2 | `.doc h1` 34px |
| 페이지 제목 `h1` | 26px | 800 | `--text-heading` | 1.35 | `.doc h1` 모바일 26px |
| 섹션 제목 `h2` | 18px | 700 | `--text-heading` | 1.35 | `.card h3` 18px |
| 카드/모달 제목 | 16px | 700 | `--text-heading` | 1.4 | |
| 본문 | 15px | 400 | `--text-body` | 1.6 | `.card p` 15px |
| 표 본문 | 14px | 400 | `--text-body` | 1.5 | 표는 `font-variant-numeric: tabular-nums` |
| 표 헤더 / 폼 라벨 | 13.5px | 700 | `--text-heading` | 1.4 | `.badge` 13.5px |
| 캡션·메타 | 13px | 400 | `--text-muted` | 1.5 | `.eyebrow` 13px |
| 버튼 | 14.5px | 600 | (버튼별) | 1 | 네비 링크 14.5px |

`body` 의 `line-height: 1.75` 는 문서용이라 콘솔 본문·표에는 위 값으로 **덮어쓴다**(새 색이 아니라 밀도 조정이므로 허용). 대문자 `eyebrow` 스타일은 쓰지 않는다.

### 2-6. 접근성 (색 대비) — 변수 선택의 제약

흰 배경 위 대비 기준으로 `--warning`(#F59E0B) · `--success`(#16A34A) · `--primary-bright`(#38BDF8) 는 **작은 텍스트로는 WCAG AA 에 미달**한다. 따라서:

- 상태 배지의 **글자는 항상 `--text-heading`**, 의미는 앞의 **6px 점(`--warning`/`--success`/`--error`)** 과 **글자(대기/승인/반려)** 로 전달한다. 색만으로 구분하지 않는다.
- `--error` 는 텍스트로 써도 된다(대비 충분). 단 굵기 600 이상.
- `--text-muted` 는 13px 이상, 부가 정보에만.

  Qoin 현황
```

읽기 전용 두 항목은 항목 우측에 "읽기" 13px 칩(테두리 `--border`, 글자 `--text-muted`)을 둔다. 건수 배지와 같이 있을 땐 배지가 칩 오른쪽.

### 3-3. 1024px 미만 (깨지지 않을 정도만)

- 사이드바 → 상단 가로 바(높이 56px, 로고 + 가로 스크롤 네비, 계정/로그아웃은 우측 끝).
- 본문 패딩 `24px 16px`. 표는 `.table-wrap` 의 `overflow-x:auto` 재사용. 상세의 우측 행동 패널은 정보 아래로 쌓이고 **고정(sticky) 해제**.
- 모달은 폭 `calc(100vw - 32px)`.
- 이 이하 폭에 대한 별도 화면 설계는 하지 않는다.

### 3-4. 다크 모드

`style.css` 에 다크 변수가 없다. 지원하지 않는다(스펙 범위 밖).

## 4. 공통 컴포넌트

### 4-1. 버튼

| 종류 | 용도 | 배경 | 테두리 | 글자 | hover | disabled |
|---|---|---|---|---|---|---|
| Primary | 승인, 로그인, 승인 확정 | `--primary` | 없음 | `--on-primary` | `--primary-light` | 배경 `--surface`, 글자 `--text-muted`, 테두리 `--border`, `cursor:not-allowed` |
| Secondary | 반려, 새로고침, 취소, 로그아웃, 다시 시도 | `--surface-elevated` | `1px --border` | `--text-heading` | 배경 `--surface` | 글자 `--text-muted`, 투명도 .6 |
| Reject-confirm | 반려 모달의 "반려 확정" | `--surface-elevated` | `1.5px --text-heading` | `--text-heading` | 배경 `--surface` | Secondary 와 동일 |
| Link | 표 안 "자세히", 건수 카드 이동 | 없음 | 없음 | `--primary` 밑줄 | | |

- 크기: 높이 40px, 패딩 `0 18px`, 라운드 10px, 14.5px / 600. 모달 확정 버튼은 높이 44px.
- 포커스: `outline: 2px solid var(--primary-bright); outline-offset: 2px`. 모든 인터랙티브 요소.
- **진행 중(in-flight)**: 눌린 버튼 글자를 "처리 중…" 으로 바꾸고 좌측에 14px 스피너(border `--border`, 상단 `--primary-bright` 회전. Primary 위에서는 border `--primary-light`, 상단 `--on-primary`). 같은 영역의 다른 버튼 전부 `disabled` + `aria-busy="true"`. 더블 클릭 방지.
- 빨간 채움 버튼은 **콘솔에 존재하지 않는다**(삭제 같은 파괴 액션이 비범위이므로). `--error` 는 실패 표시에만 쓴다.

### 4-2. 상태 배지

높이 24px, 패딩 `0 10px`, 라운드 999px, 13px / 700, 글자 `--text-heading`, 앞 6px 원.

| 상태 | 문구 | 점 색 | 배경 |
|---|---|---|---|
| pending | 대기 | `--warning` | warning 14% 파생 |
| approved | 승인됨 | `--success` | success 14% 파생 |
| rejected | 반려됨 | `--error` | error 14% 파생 |

### 4-3. 배너 (Callout)

`style.css` `.callout` 재사용: 좌측 4px 바, 배경 `--surface`, 패딩 `14px 18px`, 우측 라운드 `--radius`, 15px.

| 종류 | 바 색 | 아이콘/접두 | 용도 |
|---|---|---|---|
| info | `--primary-bright` | (없음) | 안내, 읽기 전용 알림 |
| warn | `--warning` | "주의" 굵게 | 비상 정지, 이전 반려 이력 |
| error | `--error` | "실패" 굵게 | 쓰기 실패, 로드 실패 |
| success | `--success` | "완료" 굵게 | (토스트 외) 완료 메모 |

`role`: error → `role="alert"`, 나머지 `role="status"`.

### 4-4. 토스트

우측 하단, 폭 360px, 배경 `--primary`, 글자 `--on-primary`, 라운드 10px, 패딩 `12px 16px`, 6초 후 사라짐(`aria-live="polite"`). **성공 알림 전용.** 실패는 토스트로 보내지 않는다(사라지면 놓치므로 §6-5 의 영구 배너/모달 내 오류 사용).

### 4-5. 스켈레톤

배경 `--surface`, 라운드 8px, 1.4s 좌→우 하이라이트(`--surface-elevated`) 이동. `prefers-reduced-motion: reduce` 에서는 애니메이션 제거(정적 `--surface`). 스켈레톤 블록 영역에 `aria-busy="true"` + 시각 숨김 텍스트 "불러오는 중".

### 4-6. 에러 블록 (영역 단위)

카드/표 영역 안에 들어가는 구성. 영역 전체를 대체하되 **다른 영역은 건드리지 않는다**(spec §10 "해당 카드만").

```
┌──────────────────────────────────────────────┐
│ ▌ 불러오지 못했어요                           │   <- 좌측 4px --error 바, 제목 16px/700
│ ▌ 연결을 확인한 뒤 다시 시도해주세요.         │   <- 원인별 문구(§8), 15px --text-body
│ ▌ [다시 시도]                                 │   <- Secondary 버튼
└──────────────────────────────────────────────┘
```

### 4-7. 빈 상태 블록 (영역 단위)

에러와 **시각적으로 구분**한다: 바(막대)·`--error` 를 쓰지 않고, 중앙 정렬, 아이콘 없음(텍스트만), 제목 16px/700 `--text-heading`, 설명 14px `--text-muted`.

```
┌──────────────────────────────────────────────┐
│                                              │
│            검토 대기 중인 브랜드가 없어요     │
│          새 제출이 들어오면 여기에 나타나요.  │
│                                              │
└──────────────────────────────────────────────┘
```

패딩 `48px 24px`, 배경 `--surface-elevated`, 테두리 `--border`, 라운드 `--radius`. 동작 버튼 없음(재시도 대상이 아님). 단 필터/검색 결과 없음은 "필터 지우기" Link 버튼 제공.

### 4-8. 모달

- 오버레이: `--primary` 의 투명도 .45 (`background: var(--primary); opacity` 가 아니라 별도 오버레이 요소에 `background: color-mix(in srgb, var(--primary) 45%, transparent)`).
- 패널: 폭 480px, 배경 `--surface-elevated`, 라운드 `--radius`, 패딩 `24px`, `var(--shadow)`, 테두리 `--border`.
- 구조: 제목(16px/700) → 대상 블록 → 본문/입력 → 하단 우측 정렬 버튼 2개(gap 8px). 취소 좌, 확정 우.
- `role="dialog" aria-modal="true" aria-labelledby`. 열릴 때 포커스 **취소 버튼**에(Enter 한 번에 확정되지 않게). 포커스 트랩. 닫을 때 원래 트리거로 복귀.
- Esc / 오버레이 클릭으로 닫힘 — 단 **in-flight 중에는 둘 다 무시**한다. 반려 모달에서 사유 입력 값이 있을 때 오버레이 클릭으로 닫지 않는다(실수로 입력 손실 방지; Esc 와 취소 버튼만 허용).

### 4-9. 정보 행 (Key–Value)

```
라벨 (13.5px/700 --text-heading, 폭 132px 고정)   값 (15px --text-body, 줄바꿈 허용)
```

행 간 12px, 행 사이 구분선 없음. 값이 없으면 `-` (`--text-muted`). 긴 UID 는 `font-variant-numeric: tabular-nums`, `word-break: break-all`, 우측에 "복사" Link 버튼(복사 성공 시 1.5초간 "복사됨").

### 4-10. 표

`style.css` 의 `.table-wrap` / `table` / `thead th` 재사용. 행 높이 52px, 패딩 `12px 16px`. 행 전체가 링크처럼 동작하는 큐 표는 첫 셀(이름)에 `<a>` 를 두고 행 hover 배경 `--surface`. 키보드로 이름 링크에 포커스 가능해야 한다.

### A0. 인증 게이트

공통 레이아웃: 배경 `--background`, 세로·가로 중앙 카드. 카드 폭 400px(모바일 `calc(100vw - 32px)`), 패딩 `32px`, 테두리 `--border`, 라운드 `--radius`, `var(--shadow)`.

#### A0-d. `users/{uid}` 읽기 실패 (fail-closed)

`permission-denied`, 네트워크 오류, 타임아웃, 응답 형식 이상 전부 **admin 아님으로 취급**하여 셸을 열지 않는다(spec §6-3).

```
          ┌────────────────────────────┐
          │        [Q 로고 48px]        │
          │ 권한을 확인하지 못했어요    │   <- 18px/700
          │                            │
          │ ▌ 계정 정보를 불러오지 못해 │   <- error 배너 (좌측 --error 바)
          │ ▌ 콘솔을 열 수 없어요.      │
          │ ▌ (사유: 네트워크 / 읽기 거부│
          │ ▌  / 알 수 없음)            │
          │                            │
          │ [   다시 시도   ] [로그아웃] │   <- Secondary 2개
          └────────────────────────────┘
```

- "다시 시도"는 `users/{uid}` 읽기를 다시 한다. **성공했고 admin 일 때만** 셸을 연다. 실패를 "일단 열어주고 실패한 카드만 에러" 로 처리하지 않는다.
- 사유 라벨은 개발 단서용 짧은 한 줄(13px muted). 원본 에러 메시지·스택은 노출하지 않는다.
- 네트워크 오류와 권한 거부를 같은 화면에서 사유 문구만 다르게 한다. 어느 쪽이든 동작은 동일(닫힘 유지).

| 상태 | 표시 |
|---|---|
| loading | "다시 시도" in-flight: 버튼 "확인 중…" + 스피너 |
| error | 이 화면 자체 |
| empty | 해당 없음 |

#### A0-e. 세션 만료 (이용 중 `unauthenticated`)

셸 이용 중 토큰이 만료/로그아웃되면 즉시 A0-a 로 전환하고 로그인 카드 상단에 info 배너 "세션이 만료되었어요. 다시 로그인해주세요." 표시. 처리 중이던 반려 사유 입력 등은 보존하지 않는다(재로그인 후 같은 admin 이 아닐 수 있음).

| 영역 | loading | error | empty |
|---|---|---|---|
| **매장 문서 전체** | A3 와 동일 | 중앙 에러 블록 | `not-found`: "찾을 수 없는 매장이에요 / 이미 삭제되었거나 주소가 잘못됐을 수 있어요." (**삭제된 매장일 수 있다**: 삭제는 앱에서 가능) |
| **연결 브랜드 카드** | 행 스켈레톤 | 카드 안 warn 배너 "브랜드를 확인하지 못했어요" + 다시 시도 | 개인 매장(브랜드 없음): "브랜드 없이 등록된 매장이에요" info 배너 |
| **이미지** | 썸네일 스켈레톤 | 개별 이미지 깨짐 → `--surface` 플레이스홀더 | 이미지 없음 → "등록된 이미지가 없어요"(13px muted) |

이미 처리된 건(approved/rejected): A3 와 동일하게 패널을 상태 배너로 대체.

 [매장 이름·주소 검색 ____________]  상태: (전체)(대기)(승인됨)(반려됨)   <- 필터 칩

 ├──────────────────────────────────────────────────────────────────────────┤

```

- 필터 칩: 선택됨 = 배경 `--primary` / 글자 `--on-primary`, 미선택 = `--surface-elevated` + `--border`. 높이 32px, 패딩 `0 14px`, 13.5px/600, 라운드 999. `role="radiogroup"`.
- 페이지네이션: 클라이언트 25건/페이지. 전체 건수가 많아질 경우 서버 페이지네이션이 필요하나 1차는 전량 로드(**DV-7**: 건수 임계 초과 시 알림).
- 행은 **링크 아님**(읽기 전용). 매장 상세 보기는 비범위. 단 `pending` 매장 행에는 "승인 상세 →" Link 를 둔다(A5 로 이동). 이는 읽기 화면에서 쓰기 화면으로의 이동일 뿐이다.
- "승인 메타" 열: approved 면 처리자 UID(말줄임)·`approvedAt`, rejected 면 처리자·`rejectedAt`(라벨 접두 "반려 "), pending 이면 `-`. **반려 매장에 `approvedAt` 을 표시하지 않는다** (R8 필드 분리와 일치).

| 상태 | 표시 |
|---|---|
| **loading** | 검색·칩은 비활성(disabled)으로 표시 + 스켈레톤 행 8개 |
| **error** | 검색·칩 숨기고 에러 블록 |
| **empty** | (a) 매장 0건: "등록된 매장이 없어요" (b) 필터/검색 결과 없음: "조건에 맞는 매장이 없어요" + "필터 지우기" Link — 두 empty 는 문구 다름. 둘 다 에러 아님 |

## 6. 승인·반려 인터랙션 (A3 / A5)

### 6-1. 시각 위계

| 요소 | 설계 | 이유 |
|---|---|---|
| 승인 | 패널 최상단, Primary(`--primary`), 전폭 44px | 주 행동. 가장 눈에 띄는 요소 |
| 반려 | 승인 아래, Secondary(테두리 `--border`), 전폭 44px, 라벨 **"반려…"** (말줄임표 = 후속 입력 필요) | 빨강 채움을 쓰지 않는다. 삭제 같은 파괴 액션이 아니라 "이번 제출에 대한 결정"이다 |
| 취소(모달) | Secondary, 좌측 | 포커스 기본 위치 |
| 확정(모달) | 승인: Primary / 반려: Reject-confirm(§4-1) | 두 확정 버튼의 모양이 달라 헷갈리지 않는다 |
| `--error` | 실패 메시지에만 | 반려 = 에러 아님. 빨강과 연상되지 않게 |

**"승인 취소"로 오해되지 않게 하는 장치 (매장 반려, spec 요구):**
1. 버튼/모달/토스트 문구에 "취소", "철회", "해제", "되돌리기" 를 쓰지 않는다. 쓰는 말은 **"반려"**.
2. 반려 대상은 "이번 제출 건"으로 명시: 모달 제목 "이 제출 건 반려".
3. 패널·모달에 "반려는 이번 제출 건에 대한 결정이에요. 이미 승인된 매장의 승인을 되돌리는 동작이 아니에요." 안내(재심사 건에서 노출, 일반 pending 건에서는 첫 문장만).
4. 성공 토스트: "반려했어요" (매장 "취소됐어요" 금지).
5. 반려 버튼은 **`status==='pending'` 일 때만** 그린다. approved 매장의 상세에는 반려/승인 버튼이 아예 없다.

### 6-2. 흐름 개관

```
[상세 화면 - 결정 패널]
   │  승인 클릭                       반려… 클릭
   ▼                                  ▼
[승인 확인 모달]                 [반려 모달: 사유 입력 + 확정]
   │ 취소 → 닫힘                      │ 취소/Esc → 닫힘
   │ 승인 확정                        │ 반려 확정 (사유 검증 통과 시)
   ▼                                  ▼
 (최신 상태 재조회: pending 인가?)  ← 아니면 '이미 처리됨' 안내, 쓰기 안 함
   │ pending
   ▼
 서버에 쓰기 (in-flight, 모달 유지)
   │
   ├─ 성공 응답 ──► 모달 닫기 → 큐 목록으로 이동 → 목록 서버 재조회 → 토스트
   └─ 실패 응답 ──► 모달 유지 + 모달 내 error 배너 + 항목은 목록/상세에 그대로
```

### 6-3. 승인 확인 모달

```
┌──────────────────────────────────────────────┐
│ 브랜드 승인                                   │  16px/700
│                                              │
│ ┌ 대상 ────────────────────────────────────┐ │  --surface 박스, 라운드 10, 패딩 12 16
│ │ 모카하우스                                │ │  15px/700
│ │ 제출 2026-10-27 14:20 · ID a1b2c3…        │ │  13px muted
│ └───────────────────────────────────────────┘ │
│                                              │
│ 이 브랜드를 승인할까요?                       │  15px
│ 승인하면 브랜드 키가 함께 발급돼요.            │  14px muted (브랜드만; D1)
│                                              │
│ (조건부 warn 배너: 매장의 연결 브랜드 이상 등)│
│                                              │
│                         [취소]  [ 승인 확정 ] │
└──────────────────────────────────────────────┘
```

- 제목: "브랜드 승인" / "매장 승인".
- 대상 블록은 상세 화면의 이름을 **그대로 다시 보여준다**(spec F7). 이름이 길면 2줄 말줄임.
- 매장 승인 모달에서 `missing` 연결 브랜드 시 warn 배너 한 줄: "연결된 브랜드를 찾을 수 없어요. 그래도 승인할까요?".
- **in-flight 표시** — 브랜드 승인은 2단계(D1):
  1. 확정 버튼 "브랜드 키 발급 중…" → 2. "승인 기록 중…". 모달 본문 하단에 단계 표시 2칸 인디케이터(완료=`--success` 점, 진행=스피너, 대기=`--border` 점).
  - 매장 승인은 1단계: "승인 중…".
- 이 모달에는 Qoin 필드·적립률 입력이 **없다**(spec: 승인 payload 에 Qoin 관리 필드 금지). 금액/적립률을 암시하는 문구도 두지 않는다.

### 6-4. 반려 모달 (사유 입력 = 확인 단계)

```
┌──────────────────────────────────────────────┐
│ 이 제출 건 반려                               │  16px/700
│                                              │
│ ┌ 대상 ────────────────────────────────────┐ │
│ │ 모카 강남점                               │ │
│ │ 제출 2026-10-27 14:20 · ID a1b2c3…        │ │
│ └───────────────────────────────────────────┘ │
│                                              │
│ 반려 사유 (필수)                              │  13.5px/700
│ ┌──────────────────────────────────────────┐ │
│ │                                          │ │  textarea 높이 112px (4줄), 리사이즈 불가
│ │                                          │ │
│ └──────────────────────────────────────────┘ │
│ 제출자에게 전달되는 내용이에요.      12 / 200 │  13px muted / 글자수
│                                              │
│ 반려는 이번 제출 건에 대한 결정이에요.        │  13px muted (매장·재심사 건: 2번째 문장 추가)
│                                              │
│                        [취소]  [ 반려 확정 ]  │
└──────────────────────────────────────────────┘
```

**검증 규칙**

| 규칙 | 동작 |
|---|---|
| 필수 | 앞뒤 공백 제거(trim) 후 길이 1 이상. 공백만 입력 = 빈 값 |
| 최대 길이 | 200자(글자 수 카운터 `n / 200`, 초과 입력 불가 `maxlength=200`). **D2: 앱에는 상한이 없다** — 아래 "사용자 확인" 참조 |
| 확정 버튼 | 검증 통과 전까지 `disabled`(Secondary disabled 스타일). `aria-disabled` + 사유 필드 `aria-describedby` 로 이유 연결 |
| 오류 표시 시점 | 처음 열 때는 오류를 보이지 않는다. 필드를 한 번 벗어나거나(blur) 확정을 시도했을 때 빈 값이면 필드 테두리 `--error` + 아래 13px `--error` 600 "반려 사유를 입력해주세요" |
| 저장 값 | trim 한 문자열을 `rejectedReason` 으로 쓴다 |
| 붙여넣기 | 줄바꿈 허용(최대 5줄 표시). 저장 시 줄바꿈 유지 |

- 키보드: 모달이 열리면 포커스는 **취소**가 아니라 이 모달에서만 **사유 입력창**에 둔다(입력이 목적이므로). `Ctrl/⌘+Enter` = 확정(검증 통과 시). 단일 `Enter` 는 줄바꿈이다.
- 사유 입력 중 오버레이 클릭으로 닫지 않는다(§4-8).

### 6-5. 실패 시 복귀 (낙관적 UI 금지)

원칙: **서버 성공 응답 전에는 어떤 화면 요소도 "처리됨"으로 바꾸지 않는다.** 건수 배지·목록 행·상태 배지는 응답 후 서버 재조회 결과로만 바뀐다.

실패 시:

| 순서 | 동작 |
|---|---|
| 1 | 확정 버튼/취소 버튼 복원(재활성). 모달은 **닫지 않는다** |
| 2 | 모달 본문 상단(대상 블록 아래)에 error 배너 삽입, `role="alert"`, 포커스 이동. 문구는 §8 표 |
| 3 | 반려 사유 입력 값 **그대로 보존**(재시도 시 다시 쓰지 않게) |
| 4 | 확정 버튼 라벨은 "다시 시도" 로 바뀌지 않는다 — 같은 라벨 "승인 확정"/"반려 확정"을 유지(같은 행동을 다시 하는 것이므로) |
| 5 | 모달을 취소로 닫으면: 상세 화면의 결정 패널 위에 **영구 error 배너** 잔류(닫기 가능한 X 버튼) — "마지막 시도는 저장되지 않았어요(HH:MM). 항목은 아직 대기 중이에요." |
| 6 | 목록·사이드바 건수·상태 배지는 **변경 없음.** 항목은 목록에 그대로 있다 |

```
┌──────────────────────────────────────────────┐
│ 매장 승인                                     │
│ ┌ 대상 ────────────────────────────────────┐ │
│ │ 모카 강남점                               │ │
│ └───────────────────────────────────────────┘ │
│ ▌ 실패  저장되지 않았어요.                    │  <- --error 바, role=alert
│ ▌ 권한이 없어 승인이 거부되었어요.            │
│ ▌ 항목은 아직 대기 중이에요.                  │
│                                              │
│                        [취소]  [ 승인 확정 ]  │  <- 재활성
└──────────────────────────────────────────────┘
```

**불확실한 결과 (응답 유실/타임아웃)**: 쓰기가 서버에 반영됐는지 모른다. 이 경우 성공으로도 실패로도 단정하지 않는다.
- 문구: "응답을 확인하지 못했어요. 처리됐는지 확실하지 않아요. 목록을 새로 고쳐 상태를 확인해주세요."
- 모달 하단에 Secondary "상태 확인하기"(= 해당 문서를 서버에서 다시 읽어 현재 status 표시). 확정 버튼은 상태 확인 전까지 disabled(중복 쓰기 방지).

**성공 후**:
1. 모달 닫기 → `#/brands`(또는 `#/stores/pending`)로 이동.
2. 해당 큐를 **서버에서 재조회**. 재조회가 끝나기 전까지 그 항목 행은 유지하되 상태 칸에 "반영 확인 중…"(13px muted + 스피너) 표시.
3. 재조회 성공 → 항목이 목록에서 사라지고, 사이드바·대시보드 건수가 재조회 값으로 갱신, 토스트 "승인했어요" / "반려했어요".
4. 재조회 실패 → 토스트는 띄우되 목록 위에 warn 배너 "처리는 저장되었지만 목록을 새로 고치지 못했어요. 새로고침을 눌러주세요." 항목은 "반영 확인 중…" 대신 "처리됨(새로고침 필요)" 로 표시. (쓰기 성공 응답을 받았으므로 이 문구가 사실이다.)

### 6-6. 동시성 / 이미 처리된 건

확정 클릭 시 쓰기 직전에 문서를 서버에서 다시 읽어 `status==='pending'` 인지 확인한다. 아니면 쓰기를 하지 않고 모달에 info 배너 "이미 처리된 건이에요 (현재: 승인됨/반려됨). 목록을 새로 고쳐주세요." + 확정 버튼 disabled + "목록으로" Secondary. (다른 admin 또는 앱에서 먼저 처리한 경우의 덮어쓰기 방지.)

### 6-7. 키보드 / 접근성

- 결정 패널의 두 버튼은 Tab 순서에서 승인 → 반려.
- 모달 포커스 트랩 + 닫을 때 트리거 복귀. 제목 `aria-labelledby`, in-flight `aria-busy`.
- 상태 변화(성공 토스트, 실패 배너)는 `aria-live` 로 읽힌다.
- 이전/다음 건 단축키는 두지 않는다(오조작 시 승인 단축키와 혼동 우려).

### 6-8. 승인/반려가 보내는 필드와 UI 의 관계 (참고, 구현은 developer)

| 액션 | 보내는 필드 (spec §7.2) | UI 에서 입력받는 것 |
|---|---|---|
| 브랜드 승인 | `status:'approved'` `approvedBy` `approvedAt` `rejectedReason:null` `updatedAt` (+ 먼저 `issueBrandKey`) | 없음 |
| 브랜드 반려 | `status:'rejected'` `approvedBy` `rejectedReason` `updatedAt` | 사유 |
| 매장 승인 | `status:'approved'` `approvedBy` `approvedAt` `rejectedReason:null` `updatedAt` | 없음 |
| 매장 반려 | `status:'rejected'` `approvedBy` **`rejectedAt`** `rejectedReason` `updatedAt` (`approvedAt` 금지) | 사유 |

UI 는 위 외의 필드를 입력받는 컨트롤을 두지 않는다. 특히 Qoin 관련 입력(적립률, 스위치)은 **어떤 모달에도 없다.**

### 6-9. D1 축소안 (브랜드 승인에 CF 호출을 허용하지 않는 경우)

- 브랜드 상세의 승인 버튼을 그리지 않고 패널에 info 배너 "브랜드 승인은 앱에서 처리해주세요(브랜드 키 발급이 함께 필요해요)." 표시, **반려만** 제공.
- 반려 모달/실패/성공 흐름은 §6-4~6-6 그대로.
- 이 경우 매장 승인/반려는 영향 없음.

## 7. 라우팅·전환 상태 (공통)

- 해시 변경 시 본문만 교체, 사이드바 유지. 활성 항목 `aria-current`.
- 목록 → 상세 전환 시 상세는 즉시 스켈레톤 렌더(목록에서 받은 값을 임시로 보여주지 않음 — 낡은 값을 최신처럼 보이지 않게).
- 알 수 없는 해시: 대시보드로 이동.
- 페이지 이탈 시 모달이 열려 있으면 닫고 입력은 버린다(뒤로가기 포함). in-flight 중에는 `beforeunload` 확인을 건다.

## 8. 오류 문구 표 (spec §10 대응)

영역 단위 읽기 오류:

| 원인 | 제목 | 설명 |
|---|---|---|
| 네트워크/오프라인 | 불러오지 못했어요 | 연결을 확인한 뒤 다시 시도해주세요. |
| `permission-denied` (읽기) | 권한이 없어 불러올 수 없어요 | 이 데이터를 볼 수 있는 권한이 없어요. 계정을 확인해주세요. (해당 카드/영역만, 전체 화면 유지) |
| 색인 필요 (`failed-precondition`) | 불러오지 못했어요 | 인덱스 설정이 필요할 수 있어요. |
| 응답 형식 이상(파싱 실패) | 불러오지 못했어요 | 데이터 형식이 예상과 달라요. 건수를 0 으로 표시하지 않았어요. |
| 기타 | 불러오지 못했어요 | 잠시 후 다시 시도해주세요. |

| 원인 | 배너 본문 | 추가 동작 |
|---|---|---|
| `permission-denied` (Rules 거부) | 저장되지 않았어요. 권한이 없어 거부되었어요. 항목은 아직 대기 중이에요. | 없음 |
| `unauthenticated` | 로그인이 만료되었어요. | 3초 후 A0-e 로 전환(입력 폐기 안내 포함) |
| 네트워크 | 저장되지 않았어요. 연결을 확인해주세요. 항목은 아직 대기 중이에요. | |
| 응답 유실/타임아웃 | 응답을 확인하지 못했어요. 처리됐는지 확실하지 않아요. | "상태 확인하기" |

원문 에러 메시지, 스택, 문서 경로는 화면에 노출하지 않는다(콘솔 로그로만).

## 12. developer 전달 특이사항

- **DV-1 (보안 문구)**: 코드 주석·UI 문구 어디에도 "버튼을 숨기므로 안전" 같은 설명을 쓰지 않는다. 권위는 Rules/CF. 셸을 admin 확인 전에 렌더하지 않는 것은 혼동 방지일 뿐.
- **DV-2 (셸 렌더 시점)**: A0 상태에서는 사이드바/본문 DOM 자체를 만들지 않는다(`display:none` 으로 숨긴 채 데이터를 가져오지 않는다). `users/{uid}` 읽기 성공 + `role==='admin'` 일 때만 셸을 만들고 그 후에 데이터 요청을 시작한다. 읽기 실패·타임아웃·형식 이상은 모두 닫힘.
- **DV-3 (낙관적 UI 금지)**: 쓰기 `await` 성공 전에 DOM/상태/건수를 바꾸지 않는다. 성공 후에도 로컬에서 항목을 지우지 말고 **서버 재조회 결과**로 목록을 다시 그린다(§6-5).
- **DV-4 (쓰기 직전 상태 확인)**: 확정 시점에 문서를 다시 읽어 `pending` 확인(§6-6). 가능하면 트랜잭션/조건부 쓰기로 같은 보장을 얻는다(구현 선택은 developer).
- **DV-5 (payload 금지선)**: 승인/반려 payload 에 Qoin 관리 필드(`accrualRate`, 스위치, 일괄 적용 포인터 등) 금지. 매장 반려는 `rejectedAt` 만, `approvedAt` 금지. `approvedBy` 는 항상 로그인 uid. `create` 금지. 필드 집합은 spec §7.2 / `store_model.dart` `approveFields`·`rejectFields` / `brand_repository_impl.dart` 를 그대로 옮긴다.
- **DV-6 (메뉴 큐 필드)**: A6/A7 열 구성은 실제 `menuItems`/`menuOverrides` 필드를 확인해 맞춘다. 앱의 `admin_pending_menus_by_brand_page` / `admin_pending_menu_overrides_page` 가 참고용. 컬렉션 그룹 쿼리 색인 필요 시 에러 상태 문구 사용.
- **DV-7 (규모)**: 매장 목록은 1차 전량 로드 + 클라이언트 페이징. 건수가 커지면 서버 페이지네이션이 필요하므로 목록 데이터 함수는 페이징 인자를 받을 수 있게 분리해 둔다.
- **DV-8 (CSS)**: `admin.css` 는 `style.css` 를 먼저 로드하고 변수를 상속. 색은 `var(--…)` 만, hex 금지. 파생색은 `color-mix` 로 변수끼리만. `style.css` 의 비변수 hex(푸터/고객센터)는 복사하지 않는다. `style.css` 자체는 수정하지 않는다(읽기 전용, 랜딩 회귀 방지).
- **DV-9 (접근성)**: 상태 배지는 글자+점. 색만으로 구분하지 않는다. 모달 포커스 트랩, `role="alert"`/`aria-live`, `prefers-reduced-motion` 대응.
- **DV-10 (로고)**: `landing/index.html` 의 인라인 SVG 를 그대로 복제(색은 `currentColor` + `--primary-bright`). 새 이미지 자산을 만들지 않는다.
- **DV-11 (역할 부여 UI 없음)**: `users` 문서를 쓰는 코드·컨트롤이 존재하지 않아야 한다. 검색 키워드 `role`, `users` 쓰기 호출 0건 확인.
- **DV-12 (D1)**: 브랜드 승인 = `issueBrandKey`(리전 `asia-northeast3`) 성공 후 `update`. 결정에 따라 §6-9 축소안으로 전환.
- **DV-13 (복사 버튼)**: UID "복사"는 `navigator.clipboard` 실패 시(비보안 컨텍스트 등) 조용히 실패하지 않고 "복사하지 못했어요" 1.5초 표시.
- **DV-14 (배포 제약)**: 배포는 PG 심사 종료 후 사용자가 수행. landing 에서 `/admin` 링크 없음. 접근은 `/console/index.html`, 해시 라우팅.
