| # | 결정 | 사유 |
|---|---|---|
| 1 | **범위가 화면이다.** 편집은 `전역 / 브랜드 / 매장` 각자 **별도 화면**에서만 한다. 모든 편집 화면 맨 위에 같은 모양의 **범위 밴드**(`QoinScopeBand`)를 고정한다 | 100배 오입력보다 위험한 건 범위 오입력(매장에 주려던 10% 를 전역에). 한 화면에 섞으면 "지금 어디를 바꾸는 중인지" 가 흐려진다 |

## 색상 사용 (토큰 전부 기존)

| 용도 | 토큰 |
|---|---|
| 카드 / 테두리 | `AppColors.surfaceElevated` / `AppColors.border` |
| plate / skeleton / 비활성 | `AppColors.surface` |
| 명시 값(숫자), 범위 줄 | `AppColors.textHeading` |
| 상속 값(숫자), 보조 문구, 비교 `현재` 열 | `AppColors.textMuted` |
| 본문, **배지 글자(전부)** | `AppColors.textBody` |
| 배지 틴트 — 매장/브랜드 설정 | `AppColors.primary` alpha 0.10, 아이콘 `primary` |
| 배지 틴트 — 브랜드 상속 | `AppColors.primaryBright` alpha 0.15, 아이콘 `primary` (sky 아이콘은 흰 배경 대비가 낮아 아이콘만 navy) |
| 배지 틴트 — 전역 상속 | `AppColors.textMuted` alpha 0.12, 아이콘 `textMuted` |
| 배지 틴트 — 적립 안 함 | `AppColors.warning` alpha 0.18 + 테두리 `warning` alpha 0.5 1px, 아이콘 `warning` |
| 배지 틴트 — 설정 확인 필요 | `AppColors.error` alpha 0.10, 아이콘 `error` (유일한 error 사용처. 데이터가 실제로 깨진 상태이기 때문) |
| 경고 plate (인상 / 덮어쓰기 / partial / 전체 중단) | `AppColors.warning` alpha 0.10 + 아이콘 `warning`, **글자는 `textBody`** |
| 선택된 라디오 카드 테두리 | `AppColors.primary` 1.5px. 선택된 `적립 안 함` 카드만 테두리 `warning` |
| 필드 에러 문구 / 로드 실패 아이콘 | `AppColors.error` (1차와 동일) |
| 주 버튼 | `AppColors.primary` / `AppColors.onPrimary` |

- 배지의 **글자는 틴트 색이 아니라 `textBody`**. 기존 `StoreScopeBadge` 는 글자를 틴트 색으로 칠하는데 sky(`info`)·gold·warning 은 흰 배경 위 11px 글자로 대비가 부족하다. 새 배지는 **의미를 글자·아이콘이 지고 색은 보조**라서 색을 못 봐도 5상태가 구분된다.
- `AppColors.accent`(gold)는 이 기능에서 사용하지 않는다. `success` 도 사용하지 않는다 (1차 결정 5).

# 1. 출처 표기 체계 (4상태 + 1) — `QoinRateSourceBadge`

## 1-a. 상태 정의

적립률이 **어디서 왔는지** 를 한 단어로 말한다. 해석 결과(`EffectiveQoinRate.source` + 값)에서 결정된다.

| 상태 | 조건 | 배지 라벨 | 아이콘 | 값 표기 | 값 위계 |
|---|---|---|---|---|---|
| 매장 설정 | `source == store` 이고 rate > 0 | `매장 설정` | `Icons.tune_rounded` | `5%` | 명시: `textHeading` w800 |
| 브랜드 설정 | (브랜드 화면에서만) 브랜드 자신의 값이 명시 | `브랜드 설정` | `Icons.tune_rounded` | `5%` | 명시 |
| 브랜드 상속 | `source == brand` 이고 대상이 매장 | `브랜드 상속` | `Icons.subdirectory_arrow_right_rounded` | `5%` | 상속: `textMuted` w600 |
| 전역 상속 | `source == global` | `전역 상속` | `Icons.subdirectory_arrow_right_rounded` | `3%` | 상속 |
| **적립 안 함** | 해석 결과 rate == 0 (store 또는 brand 의 명시적 0) | `적립 안 함` | `Icons.pause_circle_outline_rounded` | `0%` | 명시: `textHeading` w800 |
| 설정 확인 필요 | 해석 결과 INVALID (§6 fail-closed) | `설정 확인 필요` | `Icons.error_outline_rounded` | `—` (대시) | `textMuted` |

- "`브랜드 설정`" 은 브랜드 목록·브랜드 편집·`brand_info_page` 에서 **브랜드 자신의 값**에 쓰고, 매장 쪽에서 같은 값이 흘러오면 `브랜드 상속` 이다. 같은 5% 가 보는 위치에 따라 이름이 다르다 (대상 기준).
- 출처 라벨 4개(`매장 설정 / 브랜드 상속 / 전역 상속 / 적립 안 함`)는 요청서의 4상태와 1:1. `브랜드 설정` 과 `설정 확인 필요` 는 같은 위젯의 파생이다.
- `적립 안 함` 이 **어느 단계에서** 나왔는지는 배지가 아니라 보조 캡션이 말한다: `매장에서 설정` / `브랜드에서 설정`. 목록처럼 공간이 좁은 곳에서는 접근성 라벨에만 넣는다.

## 1-b. 시각 규격

- 높이 22, 가로 패딩 8, **radius 6 (모서리 사각형)**, 아이콘 12 + gap 4 + 라벨 11/w600/`textBody`.
- `StoreScopeBadge` 는 radius 999 알약이다. **모양을 일부러 다르게** 해서 한 타일에 두 배지가 같이 있어도 "종류(알약) / 출처(태그)" 로 구분된다.
- 틴트·아이콘 색은 위 "색상 사용" 표.

## 1-c. "설정 없음(상속)" 과 "적립 안 함(0%)" 이 다르게 보이는 방법 — 한눈 비교

| | 상속 (필드 부재) | 적립 안 함 (명시 0) |
|---|---|---|
| 값 | **상위 값이 그대로 보인다** (`5%`) | `0%` |
| 값 색·굵기 | `textMuted` / w600 | `textHeading` / w800 |
| 배지 | 화살표 아이콘 + 회색/하늘 태그 | 일시정지 아이콘 + 노란 태그 + 테두리 |
| 편집 라디오 카드 | `상위 설정 따르기` — 설명에 **따르게 될 실제 값**(`브랜드 "Q" 의 5% 를 따라요`) | `적립 안 함 (0%)` — 선택 시 카드 전체가 warning 틴트 |
| 우선순위 사슬(§5-b) | 해당 줄이 `설정 없음` 으로 흐리게 | 해당 줄이 `0% · 적립 안 함` 으로 굵게, `적용 중` 표시 |
| 스크린리더 | `5퍼센트, 브랜드 상속` | `적립 안 함, 0퍼센트` |

- **admin 화면 어디에서도 "비어 있는 칸" 을 만들지 않는다.** 상속 상태에도 항상 상위 값이 보이고, 0 에도 항상 `0%` 가 보인다. 대시(`—`)는 해석이 불가능한 INVALID 와 로딩 후 데이터 부재에만 쓴다.

## 1-d. 기존 배지 재사용 판단 — **재사용하지 않는다 (기하만 참고)**

| 기존 | 판단 | 사유 |
|---|---|---|
| `BrandScopeBadge(brandId)` | **재사용 불가** | brandId 로 브랜드명을 비동기 조회해 `브랜드: {이름}` 을 그리는 위젯. "매장이 어떤 브랜드 소속인가" 를 말한다. 적립률 출처와 의미 축이 다르고, 타일마다 브랜드 스트림을 구독하는 비용도 있다 |
| `StoreScopeBadge` (기본 생성자는 label/icon/color 를 받는 범용) | **기하 계승, 위젯 재사용은 안 함** | ① 라벨이 `브랜드: X` 이면 `브랜드 상속` 과 한 화면에 나란히 놓였을 때 혼동된다 ② 글자를 틴트 색으로 칠해 sky/warning 틴트에서 가독성이 낮다 ③ 위치가 `admin/widgets/` 인데 owner·brand 화면이 이미 import 중이다 (1차 test_report ⑩ 이 지적한 역할 간 import 문제). 신규 배지는 owner/brand/admin 이 모두 쓰므로 **`presentation/common/widgets/qoin/`** 에 둔다 |
| `ApprovalStatusBadge` | 그대로 병용 | 승인 상태 표시용. 목록 행에서 승인 전 항목에만 보조로 노출 |

- `BrandScopeBadge` 의 **브랜드명 조회 provider**(`brandByIdProvider`)는 점주 읽기 행의 `브랜드 "{이름}" 의 설정을 따르고 있어요` 문장에서 **재사용**한다.

# 2. 공용 위젯 경계 (1차 화면에서 추출)

> 원칙: **"입력·검증·확인·표기"는 전부 공용**, **"어느 대상을 어떤 UseCase 로 저장하나"만 페이지 소유.** 페이지에는 검증 카피·경고 조건·환산 문구가 한 줄도 남지 않는다.

# 5. 공용 편집 구성요소

## 5-a. 범위 밴드 `QoinScopeBand`

편집 화면 3개의 **첫 번째 요소**. 스크롤되어 사라진다 — 대신 AppBar 제목이 범위를 항상 말한다 (`전역 기본값` / `브랜드 적립률` / `매장 적립률`).

```
┌──────────────────────────────────┐
│ (아이콘 원 40)  적용 범위           │  11 muted
│                브랜드 "Q브루어리" 전체 │  17/w800 heading, 최대 2줄
│                산하 매장 12곳 · 개별 설정 3곳 │  12 muted
└──────────────────────────────────┘
```

- 컨테이너: `surface`(전역만 warning 0.10), radius 14, padding `h16 v14`.
- 아이콘 원 40: 배경 `surfaceElevated`, 글리프 22 `primary`. 범위별 아이콘은 §4 와 동일.
- **중간 줄은 §5-d 확인 다이얼로그 첫 줄과 글자 그대로 같은 문자열**이다 (`QoinScopeLabel.of(scope, name)` 한 함수에서 생성). 밴드에서 본 문장이 다이얼로그에서 그대로 다시 나온다.
- 범위 줄 문자열:

| 범위 | 문자열 |
|---|---|
| 전역 | `전역 기본값` |
| 브랜드 | `브랜드 "{브랜드명}" 전체` |
| 매장 | `매장 "{매장명}"` |

- 셋째 줄:

| 범위 | 셋째 줄 |
|---|---|
| 전역 | `따로 설정하지 않은 모든 브랜드·매장에 적용돼요` |
| 브랜드 | `산하 매장 {N}곳` + (개별 설정 M>0 이면) ` · 개별 설정 {M}곳` |
| 매장 | 브랜드 매장 `{브랜드명} 소속 매장` / 개인 매장 `개인 매장` |

- 따옴표는 **직선 큰따옴표 `"`**. 이름에 `"` 가 들어 있으면 그대로 둔다 (표시만 한다).
- 이름이 길면 2줄까지 줄바꿈 후 말줄임. 중간에서 자르지 않는다 (같은 접두의 매장을 구분해야 하므로).
- 같은 이름의 매장이 여러 브랜드에 있을 수 있어(`강남점`) 매장 밴드는 **셋째 줄에 브랜드 소속을 반드시** 넣는다.

## 5-b. 우선순위 사슬 `QoinRateChain`

"왜 이 값이지?" 에 답한다. **매장 편집**은 3줄, **브랜드 편집**은 2줄(브랜드/전역), 전역 편집에는 없음.

```
┌ 지금 적용되는 값 ────────────────┐
│ 매장    설정 없음                  │  muted
│ 브랜드  5%                [적용 중] │  heading w800 + pill
│ 전역    3%                         │  muted (가려짐)
└──────────────────────────────────┘
```

- `surface` plate, radius 12, padding `h14 v12`, 행 간 gap 10. 행: 라벨(12 muted, 폭 44) + 값(14).
- **이기고 있는 줄 하나만** 굵게(`textHeading` w800) + 오른쪽 pill `적용 중`(높이 20, `primaryBright` alpha 0.15, 글자 11/w600/`textBody`). 나머지는 `textMuted` w500.
- 줄 값 표기 (**"비어 보임" 방어의 핵심**):
  - 필드 부재 → `설정 없음` (muted)
  - 명시 0 → `0% · 적립 안 함` (이기는 줄이면 굵게 + `적용 중`)
  - 유효 값 → `5%`
  - 무효 → `확인 필요` (muted + 11px `error` 아이콘)
- 브랜드 미소속(개인 매장): 브랜드 줄 **숨김**.
- **읽기 전용.** 줄이 눌려 보이지 않게 chevron·ripple 없음.

### 설정 방식 라디오 카드 (브랜드·매장)

섹션 라벨 `설정 방식` (12/w600 muted, gap 6) 아래 카드 3장, 카드 간 gap 8. 각 카드: `InkWell`, radius 12, padding `h16 v14`, 높이 ≥ 56, 왼쪽 `Radio` 22.

| 카드 | 제목 (15/w600 heading) | 설명 (12 / height 1.4) |
|---|---|---|
| ① 상위 설정 따르기 | `상위 설정 따르기` | 매장: `브랜드 "{이름}" 의 {rate}% 를 따라요` / (브랜드 미소속) `전역 기본값 {rate}% 를 따라요`. 브랜드: `전역 기본값 {rate}% 를 따라요`. **따르게 될 실제 값**을 보여준다. 상위 값이 무효면 `상위 설정을 확인할 수 없어요` 로 카드 **비활성** |
| ② 직접 설정 | `직접 설정` | 매장: `이 매장만의 적립률을 정해요` / 브랜드: `이 브랜드의 적립률을 정해요`. **선택되면 카드 안에 `QoinRateInputField` + 도움말 + `QoinRatePreview` 가 펼쳐진다** |
| ③ 적립 안 함 (0%) | `적립 안 함 (0%)` | 매장: `이 매장은 Qoin 을 적립하지 않아요` / 브랜드: `이 브랜드는 기본으로 Qoin 을 적립하지 않아요` + 줄바꿈 + `환불로 인한 회수는 계속돼요 (전체 중단과 달라요)` |

- 선택 표시: 테두리 `primary` 1.5px (미선택 `border` 1px). **③ 선택 시** 카드 배경 `warning` alpha 0.10 + 테두리 `warning` 1.5px + 제목 앞 `Icons.pause_circle_outline_rounded`(18, `warning`).
- 초기 선택 = 서버의 현재 상태 (필드 부재 → ①, 유효 값 → ② 에 그 값 채움, 0 → ③).
- ① 이 선택된 상태는 `QoinRateInputField` 를 **그리지 않는다** (비활성 입력란 금지 — "비어 있는 칸" 을 만들지 않는다).
- ③ 은 **입력란으로 0 을 입력하는 경로가 아니다.** ② 입력란에 `0` 을 쓰면 1차대로 `tooLow` 에러. 0 은 오직 ③ 카드로만.
- 라디오 변경 자체는 **저장하지 않는다.** 저장은 하단 버튼 → 확인 다이얼로그.
- 라디오 그룹 semantics: `inMutuallyExclusiveGroup`, 각 카드 `Semantics(checked, label: 제목 + 설명)`.

### 저장 버튼 활성 조건

| 선택 | 활성 조건 |
|---|---|
| ① | 서버 상태가 이미 ① 이 아닐 때 |
| ② | 입력이 `valid` 이고 서버 값(tenths)과 다를 때. 서버가 0/부재였다가 ② 로 바꿔 숫자를 넣으면 같은 숫자여도 "변경" |

### 하위 매장 처리 방식 (일괄 적용 1단)

표시 조건: **개별 설정이 있는 매장 수 M > 0** 이고 폼이 "변경" 상태(저장 가능 상태)일 때. M == 0 이면 섹션 자체를 숨기고(보존과 동일하므로) 확인 다이얼로그가 `산하 매장 {N}곳 모두에 적용돼요` 로 말한다.

섹션 라벨 `개별 설정이 있는 매장 처리` + 보조 `산하 매장 {N}곳 중 {M}곳이 자기 적립률을 따로 정해 두었어요` (12 muted).

| 카드 | 제목 | 설명 |
|---|---|---|
| ① (기본 선택) | `개별 설정 보존` | `따로 정해 둔 {M}곳은 그대로 두고, 나머지 {N−M}곳에 새 값을 적용해요` |
| ② | `개별 설정 덮어쓰기` | `따로 정해 둔 {M}곳의 설정을 지우고, {N}곳 모두 새 값을 따르게 해요` + 줄바꿈 + `되돌리려면 매장마다 다시 설정해야 해요` |

- **기본 선택은 보존** (비파괴). 덮어쓰기는 의식적으로 눌러야 한다.
- ② 선택 시 카드 테두리 `warning` 1.5px + 제목 앞 `Icons.warning_amber_rounded` 18 `warning`. (`error` 아님)
- 개별 설정 중 `적립 안 함(0%)` 매장이 Z>0 곳이면 ② 설명 아래 한 줄 추가: `그중 적립 안 함 {Z}곳도 다시 적립하게 돼요`.
- 하단 보조 한 줄(11 muted): `영향 매장 수는 이 화면 기준이에요. 실제 적용 결과는 완료 후 이력에서 확인할 수 있어요`.
- 숫자 M·Z 는 클라이언트가 `watchStoresByBrand` 로 센 **미리보기**다. 이력에 남는 값은 서버가 센 값 (spec §4-④).

## 6-c. 덮어쓰기 확인 (일괄 적용 2단) — 확인 다이얼로그 확장

`QoinRateConfirmDialog` 의 브랜드 · 덮어쓰기 변형. 헤더는 그대로 `브랜드 "Q브루어리" 전체`. 비교 블록 아래, 영향 블록 자리에 **무거운 블록**:

```
 ┌ warning 틴트 plate ───────────────┐
 │ ⚠ 개별 설정 3곳이 지워져요           │  14/w700 body
 │ 산하 매장 12곳 중 개별 설정이 있는 3곳의 │
 │ 설정이 지워지고, 12곳 모두 새 값을     │  13 body
 │ 따르게 돼요.                        │
 │ · 그중 적립 안 함 1곳도 다시 적립해요   │  (Z>0 일 때만)
 │ 되돌리려면 매장마다 다시 설정해야 해요   │  13/w600 body
 └───────────────────────────────────┘
 ☐ 개별 설정 3곳이 지워지는 것을 확인했어요   ← 체크박스 행 (터치 44+)
 [취소]   [덮어쓰고 적용] ← 체크 전 비활성
```

- **체크박스를 체크해야 `덮어쓰고 적용` 이 활성**된다. 체크박스 행 높이 ≥ 48. 다이얼로그를 열 때마다 미체크로 시작.
- 체크박스 문구의 숫자는 위 plate 와 같은 M. 숫자를 한 번 더 읽게 하는 것이 목적이다.
- 인상 경고, 사유, 하단 고정 문구는 순서대로 이어서 노출.
- 무게감 설계 원칙: ① 정보(숫자)로 무겁게 ② 마찰은 파괴적 경로 한 곳에만 ③ 색은 `warning` 까지만 (`error` 금지, 1차 톤).
- 보존 경로는 체크박스 없음 (영향 블록 문구 + 일반 확인).

## 6-d. 진행 · 결과 · partial (일괄 적용 3단)

### 실행 중

- 확인 직후 폼 위에 **전체 덮개**(반투명 `background` alpha 0.92) + 중앙: 20x20 → 28x28 `CircularProgressIndicator`(primary) + `Qoin 적립률을 적용하고 있어요` 15/w700 + `매장 수에 따라 시간이 걸릴 수 있어요. 끝나지 않은 경우 이력에서 이어서 적용할 수 있어요` 12 muted/중앙.
- 실행 중 뒤로가기·AppBar 뒤로 비활성 (`PopScope(canPop: false)`). `Semantics(liveRegion: true)` 로 문구 낭독.
- 보존·매장 0곳처럼 즉시 끝나는 경로는 덮개 없이 저장 버튼 인디케이터만 (1차와 동일).

### 완료 — 결과 카드 (폼 위, 닫기 전까지 유지)

```
 ┌ 결과 카드 (primaryBright 0.10 틴트 + 테두리 0.30) ┐
 │ ✓ 적용을 마쳤어요                     [×]     │  14/w700
 │ 새 적립률 5%                                  │
 │ 적용된 매장 12곳 · 초기화된 개별 설정 3곳        │  13 body
 │ [ 이력 보기 › ]                               │  텍스트 링크
 └──────────────────────────────────────────┘
```

- 숫자는 **서버가 돌려준 `affectedCount` / `clearedCount`** (클라이언트 미리보기가 아니다). 미리보기와 다르면 서버 값을 쓴다.
- 보존 모드는 `초기화된 개별 설정` 생략: `적용된 매장 {n}곳 · 개별 설정 {M}곳은 그대로예요`.
- 새 값이 `적립 안 함`/`상속` 이면 `새 적립률` 줄이 `새 설정 적립 안 함 (0%)` / `새 설정 상위 설정 따르기` 로 바뀐다.
- SnackBar 는 쓰지 않는다 (숫자가 3개라 사라지는 요소에 어울리지 않음).

### 부분 실패 — `status:'partial'` · `QoinPartialBanner`

세 곳에 같은 컴포넌트. **admin 이 해야 할 일을 화면이 말한다.**

```
 ┌ warning 틴트 plate ───────────────┐
 │ ⚠ 일부 매장에는 아직 적용되지 않았어요     │  14/w700 body
 │ 브랜드 "Q브루어리" 의 적립률은 이미 5% 로   │
 │ 바뀌었어요. 개별 설정 12곳 중 7곳까지      │  13 body
 │ 처리했고, 남은 5곳은 이전 개별 설정을      │
 │ 계속 쓰고 있어요.                        │
 │ 이어서 적용하면 남은 5곳만 처리돼요.        │  13/w600 body
 │ [ 이어서 적용 ]  [ 나중에 ]               │
 └───────────────────────────────────┘
```

- 말하는 순서가 중요하다: ① **무슨 일이 있었나**(일부 미적용) ② **안전한가**(브랜드 값은 바뀌었고, 남은 매장은 이전 값을 유지 — 이상한 중간 값을 받은 매장은 없다) ③ **무엇을 하면 되나**(이어서 적용). 이 순서가 admin 의 불안(어떤 매장이 어떤 값으로 적립되고 있나)을 먼저 가라앉힌다. spec §4-④ 가 보장하는 사실이다.
- `{12곳 중 7곳}` 은 이력의 `processedCount` 와 처리 대상 수. 대상 수를 모르면 `7곳까지 처리했고` 로 축약.
- 버튼: `이어서 적용`(primary 채움, 높이 44) → `QoinRateConfirmDialog`(동작 `이어서 적용`, 헤더 `브랜드 "Q브루어리" 전체`, 영향 블록 `남은 {n}곳의 개별 설정이 지워져요`, 체크박스는 다시 요구) → 실행 → 결과 카드 또는 다시 partial. `나중에`(텍스트 버튼) → 이번 세션에서 배너만 접음 (이력·허브 배너는 그대로).
- 이어서 적용 **재실패**: SnackBar `이어서 적용하지 못했어요. 잠시 후 다시 시도해주세요`, 배너 유지.
- `status:'in_progress'` 인데 오래 지난 건(고아): 이력 행에서 `적용 중` 대신 partial 과 같은 모양으로 취급한다. 판정 기준 시간은 한 상수로 (잔여 결정 6).

### 허브형 배너 (축약)

```
 ┌ warning 틴트 ────────────────────┐
 │ ⚠ 끝나지 않은 일괄 적용이 있어요        › │  14/w700
 │ 브랜드 "Q브루어리"                       │  12 muted
 └───────────────────────────────────┘
```

- 1건: `브랜드 "{이름}"`. 2건 이상: `브랜드 "{이름}" 외 {n−1}건`. 탭 → 이력 화면 `미완료` 필터. 이어서 적용은 이력 행/브랜드 편집에서 한다 (허브에서 바로 실행하지 않는다 — 허브에는 범위 맥락이 없다).

### 실패 SnackBar (전 범위)

| 상황 | 문구 |
|---|---|
| 확정 실패 (권한 없음 / 입력 무효 / 대상 없음) | `저장에 실패했어요. 다시 시도해주세요` (1차 문구) |
| **결과 불명** (타임아웃 / 네트워크 끊김 — 서버에서는 반영됐을 수 있음) | `결과를 확인하지 못했어요. 변경 이력에서 적용 여부를 확인해주세요` |
| 일괄 적용 확정 실패 | `적용하지 못했어요. 다시 시도해주세요` |
| 일괄 적용 결과 불명 | `결과를 확인하지 못했어요. 변경 이력에서 적용 여부를 확인해주세요` |

- 결과 불명 문구는 **재시도를 권하지 않는다**. 이미 적용됐는데 다시 누르면 같은 값의 중복 이력/덮어쓰기가 생긴다.

## 8-a. 공용 위젯 `QoinRateInfoRow` (variant 3개)

## 8-b. 점주 — `my_store_page` 의 `_StoreInfoSection`

`_StoreInfoSection` 카드(`surface` 배경, radius 16, padding 16)의 **마지막 요소**로 추가. 기존 행(주소·전화·영업시간·설명) 아래 **헤어라인(`border`, 상하 margin 16)** 으로 나누고, 그 아래 블록.

```
 … (주소 / 전화 / 영업시간 / 설명)
 ─────────────────────────────
 (toll 20)  Qoin 적립률                         12 muted
            5%  [↳ 브랜드 상속]                  20/w800 or muted + badge
            브랜드 "Q브루어리" 의 설정을 따르고 있어요  12 muted
            변경이 필요하면 관리자에게 문의해 주세요   12 muted
            [⏲ 적립률 변경 이력 보기  ›]            13/w600 primary, 높이 44
```

- 아이콘 `Icons.toll_rounded` 20 `textMuted` (기존 `_InfoRow` 아이콘 규격). 텍스트 열은 기존 `_InfoRow` 와 같은 좌측 정렬(아이콘 + gap 12).
- 라벨 `Qoin 적립률`(12 muted) → 값(20) → 출처 문장(12 muted, 행간 4) → 안내(12 muted).
- **출처 문장** (상태별):

| 상태 | 문장 |
|---|---|
| 매장 설정 | `이 매장에 직접 설정된 값이에요` |
| 브랜드 상속 | `브랜드 "{브랜드명}" 의 설정을 따르고 있어요` (`brandByIdProvider` 재사용. 이름 로딩 중이면 `브랜드의 설정을 따르고 있어요`) |
| 전역 상속 | `기본 적립률을 따르고 있어요` |
| 적립 안 함 (매장 설정) | `이 매장은 Qoin 을 적립하지 않아요` |
| 적립 안 함 (브랜드 설정) | `브랜드 설정에 따라 이 매장은 Qoin 을 적립하지 않아요` |
| 설정 확인 필요 | `적립률 설정에 문제가 있어 적립이 되지 않을 수 있어요` |

- **안내(고정)**: `변경이 필요하면 관리자에게 문의해 주세요`. (설정 확인 필요일 때도 동일)
- **이력 링크**: `Icons.history_rounded` 16 + `적립률 변경 이력 보기` 13/w600/`primary` + `chevron_right_rounded` 16. 높이 44, 좌측 정렬. 탭 → `QoinRateHistoryPage(scope: store, targetId: storeId)`.
  - 링크 색은 `primary`(navy). `primaryBright` 의 "커스텀 관리" 류 액션 링크와 구분하지 않아도 되지만 **밑줄·버튼 모양은 쓰지 않는다.**
- **전체 중단 중(`enabled == false`)**: 값 블록 아래에 plate 1개 — `surface` 위이므로 `warning` alpha 0.10 + `Icons.pause_circle_outline_rounded` 16 `warning` + `현재 전체 적립이 중단되어 있어요` 12/w600 `textBody`. 값은 그대로 보여준다 (자기 적립률 5% 인데 적립이 안 되는 상황의 오해를 막는다).
- 브랜드 매장 / 개인 매장 상세 모두 `_StoreInfoSection` 을 쓰므로 **한 번 추가로 두 뷰에 반영**된다.

## 8-c. 브랜드 — `brand_info_page`

`_BrandCard` 와 `_SubmitInfoSection` **사이**에 독립 카드로 추가 (승인된 브랜드에서만 노출. 승인 전·반려 브랜드는 아직 적립이 일어나지 않으므로 행 없음). 카드 규격은 `_SubmitInfoSection` 과 동일(`surfaceElevated`, border, radius 12, padding 16), 위아래 gap 16.

```
 ┌──────────────────────────────────┐
 │ Qoin 적립률                  5%  [↳ 전역 상속] │  라벨 12 muted | 값 18/w800
 │ 기본 적립률을 따르고 있어요                     │  12 muted
 │ 매장이 따로 설정한 적립률이 있으면 그 값이       │
 │ 우선해요. 가맹점별 적립률은 가맹점 목록에서      │  12 muted
 │ 확인할 수 있어요                              │
 │ ───────────────────────────────────          │
 │ ⏲ 적립률 변경 이력 보기  ›                      │  13/w600 primary
 └──────────────────────────────────┘
```

- 라벨 `Qoin 적립률` + 우측 값(18) + 배지는 값 아래 우측 정렬(좁은 화면에서 줄바꿈 허용).
- 출처 문장: `브랜드에 직접 설정된 값이에요` / `기본 적립률을 따르고 있어요` / `이 브랜드는 기본으로 Qoin 을 적립하지 않아요`. (브랜드 화면이므로 배지 라벨은 `브랜드 설정` / `전역 상속` / `적립 안 함`.)
- 우선순위 안내는 상태와 무관하게 항상: `매장이 따로 설정한 적립률이 있으면 그 값이 우선해요. 가맹점별 적립률은 가맹점 목록에서 확인할 수 있어요`.
- 이력 링크 탭 → `QoinRateHistoryPage(scope: brand, targetId: brandId)`.
- 전체 중단 plate 는 §8-b 와 동일하게 값 아래에 노출.
- 이 화면 AppBar 우측 `수정` 버튼(브랜드 정보 수정)은 **적립률과 무관**하다. 혼동을 막기 위해 적립률 카드에는 어떤 수정 어피던스도 두지 않는다.

## 8-d. 브랜드 — `brand_stores_page` 가맹점 타일

`_BrandStoreCard` 에 **행 하나를 추가**한다 (행2 주소와 행3 scope 배지 사이).

```
 강남점                               [승인됨]
 📍 서울 강남구 …
 ◎ Qoin  5%  [↳ 브랜드 상속]        ⏲ 이력  ›      ← 신규 행
 [브랜드: Q브루어리]              커스텀 관리 ›
```

- 신규 행: `Icons.toll_rounded` 13 muted + `Qoin` 12 muted + gap 6 + 값 15 (위계 §1-a) + gap 8 + `QoinRateSourceBadge`. 오른쪽 끝에 이력 링크 `Icons.history_rounded` 14 + `이력` 12/w500/`textBody` + `chevron_right_rounded` 14. 링크 영역은 **최소 44x44 터치**(행 높이를 44 로 확보, 위아래 기존 gap 은 8 → 4 로 줄여 카드 높이 증가를 약 28px 로 억제).
- **카드 전체는 탭하면 커스텀 관리로 간다 (기존 동작 유지).** 이력 링크는 별도 `InkWell` 이라 이력 링크를 눌러도 카드 탭이 일어나지 않는다. 값·배지 영역은 탭 반응이 **없다** (카드 탭으로 흘러가는 건 기존 동작이므로 건드리지 않는다).
- 링크 라벨을 `이력` 으로 짧게 둔 이유: 한 줄에 값·배지·링크가 들어가야 한다. 접근성 라벨은 풀 문장.
- 값 표기: 이 매장의 **해석된 적립률**. `적립 안 함` 이면 `0%` + warning 배지. 어느 단계가 원인인지는 배지 라벨(`매장 설정`/`브랜드 설정`)이 아니라 `적립 안 함` 이라는 글자가 말하고, 접근성 라벨에 `브랜드에서 설정` / `매장에서 설정` 을 덧붙인다.
- 기존 행3의 `StoreScopeBadge.brand(브랜드명)` 은 **그대로 둔다** (종류 축). 두 배지는 radius(6 vs 999)와 위치(값 행 vs 종류 행)가 다르다.
- 성능: 타일마다 스트림을 만들지 않는다. 페이지 레벨에서 브랜드 값(`myBrandProvider`)과 전역 config 를 **한 번만** 구독하고 타일은 `store.qoinAccrualRate` 와 합쳐 해석한다.
- 이력 링크 탭 → `QoinRateHistoryPage(scope: store, targetId: store.id)`.

## 9-c. 점주·브랜드 이력 화면 `QoinRateHistoryPage(scope, targetId)` (공용, 읽기 전용)

# 12. 접근성 — 적립률 · 출처가 스크린리더로 읽히는 방식

## 기본 규칙 (1차 계승)

- **음수·화살표 기호를 읽게 하지 않는다.** 화살표 `→` 는 `에서 … (으)로` 로 조립한다. `%` 는 `퍼센트`. 하이픈·대시(`—`)는 읽히지 않게 `ExcludeSemantics` 하고 `확인 필요`/`설정 없음` 같은 말로 대체한다.
- 시각 요소(배지·아이콘·chevron)는 `ExcludeSemantics`, 행/카드 단위로 `Semantics(label, excludeSemantics: true)` 를 한 번 만든다.
- 터치 타깃 ≥ 44. 텍스트 1.5x 에서 겹침·잘림 없음: 값은 `FittedBox(scaleDown)`, 이름은 2줄 허용, 필터 칩 행은 가로 스크롤, 다이얼로그는 스크롤.
- 색 단독 전달 금지: 5개 출처 배지는 **라벨 글자 + 아이콘**이 의미를 담고 색은 보조다.

## 조사 `(으)로` 규칙 — 이력 문장 조립용

| 도착 값 | 조사 | 예 |
|---|---|---|
| `…퍼센트` | `로` | `3퍼센트에서 5퍼센트로` |
| `적립 안 함` | `으로` | `5퍼센트에서 적립 안 함으로` |
| `설정 없음` | `으로` | `5퍼센트에서 설정 없음으로` |
| `적립 중` / `적립 중단됨` | `으로` | `적립 중에서 적립 중단됨으로` |

# 14. 개발자 전달 특이사항

1. **카피는 §15 "카피 문자열 일람" 의 글자 그대로.** 특히 확인 다이얼로그 첫 줄 3종, 덮어쓰기 경고, partial 배너, 고객 문구.
2. **범위 줄 문자열은 `QoinScopeLabel` 한 곳에서만 생성**한다. 밴드·다이얼로그·이력·SnackBar 가 각자 조립하면 반드시 어긋난다.
3. **검증 카피는 공용 위젯 2개(`QoinRateInputField`, `QoinRateConfirmDialog`)에만** 존재해야 한다. 페이지 3개에 `validateRateInput` 직접 호출 금지.
4. **출처 배지를 `presentation/common/widgets/qoin/` 에 둔다.** owner/brand 화면이 `presentation/admin/` 을 import 하면 1차 test_report ⑩ 의 역할 간 import 문제가 재발한다. (기존 `StoreScopeBadge` 가 이미 `admin/widgets/` 에 있어 owner·brand 가 import 중인 것은 이번 범위에서 건드리지 않는다.)
5. **상속과 0% 의 구분을 코드로도 구분한다.** UI 모델에서 `부재 / 유효 / 명시 0 / 무효` 4값을 `null`/`0.0` 로 뭉개지 말고 `QoinPolicy.resolveEffectiveRate` 결과 + 각 단계 원본(`EffectiveQoinRate`)으로 전달한다. 배지·사슬·라디오 초기 선택이 모두 이 원본을 쓴다.
6. **명시 0% 는 ③ 카드에서만 만든다.** `QoinRateInputField` 에 0 이 들어오면 1차대로 `tooLow`. 입력란 하한 검사가 소수 자릿수 검사보다 먼저인 1차 순서를 바꾸지 않는다 (`0.03` → `tooLow`).
7. **로딩 중 값을 그리지 않는다.** 매장 목록·읽기 행은 3개 소스(대상·브랜드·전역)가 모두 준비된 뒤에만 숫자를 그린다. 일부만 준비된 상태의 "임시 해석" 금지.
8. **브랜드 저장은 항상 산하 매장 정보 로딩 후.** 로딩/에러 중 저장 버튼 비활성. 확인 다이얼로그의 N, M, Z 는 클라이언트 미리보기이고 결과 카드·이력의 숫자는 서버 응답을 쓴다.
9. **개별 설정이 0곳이면 모드 선택 UI 와 체크박스를 모두 생략**한다 (CF 호출은 `preserve`).
10. **덮어쓰기 체크박스는 다이얼로그를 열 때마다 미체크.** 상태를 페이지에 보관하지 않는다.
11. **일괄 적용 실행 중 `PopScope(canPop: false)`.** partial 의 모든 진입(브랜드 편집·이력·허브)이 같은 `QoinPartialBanner` + 같은 `이어서 적용` 흐름을 쓴다.
12. **오류 분류**: 확정 실패(permission-denied / invalid-argument / not-found)와 결과 불명(deadline-exceeded / unavailable / 네트워크)을 구분해 §6-d 의 문구를 쓴다. 결과 불명에서는 재시도를 권하지 않는다.
13. **허브 부제/배너 실패는 조용히 생략.** 에러 UI 를 만들지 않는다.
14. **`가맹점 타일` 은 타일마다 스트림을 만들지 않는다.** 페이지 레벨 구독 + 합성.
15. **`partial` 조회에 `where status == 'partial'` collection group 쿼리가 필요할 수 있다.** 인덱스는 spec §7.5 에 따라 실측 확정(에뮬레이터 통과는 근거가 아님). 불가하면 허브 배너는 최근 이력 페이지 안에서만 판정하는 축소 동작이 되므로 architect 확인.
16. **customer 쪽 변경은 문자열 교체 + `비율 모름` 분기 삭제뿐.** 1차 `_paused` 와 내역 행은 건드리지 않는다.
17. 1차에서 이미 추출된 provider 가 `presentation/customer/qoin/providers/*` 를 import 하는 문제(1차 test_report ⑩)는 spec §11.4 대로 이번에 공용 위치로 옮긴다. 이 문서의 모든 신규 위젯은 새 위치만 import 한다.

# 16. 완료 기준 (디자인 관점)

- [ ] 관리자 3범위 모두 확인 다이얼로그의 **첫 줄이 범위 + 대상명**이고 18/w800 으로 가장 크다
- [ ] 검증 에러·인상 경고·환산 문구가 **공용 파일 2개에만** 있고 페이지 3개에는 없다
- [ ] 상속 상태에서 **값이 비어 보이지 않는다** (상위 값 노출). `0%` 는 `0%` + warning 배지 + 굵은 값으로 상속과 구분된다
- [ ] `적립 안 함 (0%)` 은 라디오 ③ 으로만 만들어지고 입력란 `0` 은 `tooLow`
- [ ] 입력 `0.03` / `30` 이 3범위에서 모두 차단된다 (1차 방어 유지)
- [ ] 브랜드 덮어쓰기: 영향 매장 수·개별 설정 수·`적립 안 함` 재활성·"되돌리려면 개별 재설정" 이 **확인 전에 모두 보이고**, 체크 전에는 실행 버튼이 비활성
- [ ] 개별 설정 0곳 브랜드는 모드 선택 없이 저장된다
- [ ] partial 시 화면이 ① 무슨 일이 있었나 ② 안전한가 ③ 무엇을 해야 하나 를 이 순서로 말하고 `이어서 적용` 이 브랜드 편집·이력·(허브→이력)에서 닿는다
- [ ] 결과 불명 오류에서 재시도를 권하지 않는다
- [ ] 점주·브랜드 읽기 행 3곳에 **입력란·`수정`·`변경` 라벨·값 chevron 이 없다**. 이력 링크만 별도
- [ ] 읽기 행이 로딩 중 `0%` 나 이전 값을 그리지 않는다
- [ ] 출처 배지 5종이 색 없이도(글자 + 아이콘) 구분된다. 새 배지와 `StoreScopeBadge` 가 한 타일에 있어도 모양(6 vs 999)·위치로 구분된다
- [ ] 고객 plate 에 숫자 퍼센트가 없다. 과거 내역 행은 그대로다
- [ ] 이력 행: 일괄은 1행에 영향 매장 수·덮어쓰기 여부 포함, `설정 없음 → 5%` / `5% → 적립 안 함` 이 읽힌다
- [ ] 스크린리더 라벨에 `→`·`%`·음수 하이픈이 없다 (`에서 … (으)로`, `퍼센트`)
- [ ] `Color(0x…)` 0건, 신규 토큰 0개, 텍스트 1.5x 에서 겹침·잘림 없음

## 잔여 결정 확정 (2026-10-22)

designer 가 §17 에 남긴 10건을 확정한다. **본 절이 design 본문 및 spec 의 해당 제안보다 우선한다.**

### 사용자 직접 확인 (3건)

| # | 항목 | 확정 | 사유 |
|---|---|---|---|
| **D1** | 고객 화면에 "적립 안 하는 매장도 있다" 안내 | **넣지 않음** | 현재 문구(`픽업 완료 시 결제액의 일부가 적립돼요` / `적립률은 매장마다 달라요`)로 충분하다. 0% 매장이 생기면 엄밀히는 부정확하나, 혜택을 소개하기 전에 기대를 낮추는 문구는 역효과다. 매장별 표시(N2)가 들어오면 해소된다 |
| **D2** | 점주 화면에 "적립 비용은 매장 부담" 안내 | **넣지 않음** | 브랜드 설정을 상속받는 가맹점에는 **틀린 문장**이 된다 (H1 은 "브랜드/매장"). 정산 기능이 없는 지금은 부정확한 문장을 두는 것보다 없는 편이 낫다. 정산(N1) 확정 시 추가 |
| **D3** | 승인 전 매장·브랜드를 admin 목록에 노출 | **노출 + 상태 배지** | 승인 전에 적립률을 미리 세팅해두고 승인하는 운영이 가능하다. 숨기면 승인 직후 별도 설정이 필요해 누락 위험이 생긴다 |

| # | 항목 | 확정 | 사유 |

| D4 | 전역 편집을 **별도 페이지로 분리** (spec §12.2 는 허브 포함) | **분리 채택** | 파급이 가장 큰 입력이 허브를 열자마자 노출되면 안 된다. **범위 오입력 방어**의 연장선이다 |

### designer 가 추가로 짚은 것 — 반영 확정

> **덮어쓰기는 admin 이 꺼 둔 `적립 안 함` 매장도 다시 적립하게 만든다.**
