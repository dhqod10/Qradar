# 1. 출처 표기 체계 (4상태 + 1) — `QoinRateSourceBadge`

> ⚠ **개정 2 (2026-10-22)**: `적립 안 함 (0%)` 상태는 `매장에서 중단` / `브랜드에서 중단` 으로 교체됐다 (§18-4). 값 칸은 `사용 안 함`.

## 1-a. 상태 정의

적립률이 **어디서 왔는지** 를 한 단어로 말한다. 해석 결과(`EffectiveQoinRate.source` + 값)에서 결정된다.

| 상태 | 조건 | 배지 라벨 | 아이콘 | 값 표기 | 값 위계 |
|---|---|---|---|---|---|
| 매장 설정 | `source == store` 이고 rate > 0 | `매장 설정` | `Icons.tune_rounded` | `5%` | 명시: `textHeading` w800 |
| 브랜드 설정 | (브랜드 화면에서만) 브랜드 자신의 값이 명시 | `브랜드 설정` | `Icons.tune_rounded` | `5%` | 명시 |
| 브랜드 상속 | `source == brand` 이고 대상이 매장 | `브랜드 상속` | `Icons.subdirectory_arrow_right_rounded` | `5%` | 상속: `textMuted` w600 |
| 전역 상속 | `source == global` | `전역 상속` | `Icons.subdirectory_arrow_right_rounded` | `3%` | 상속 |
| **적립 안 함** | 해석 결과 rate == 0 (store 또는 brand 의 명시적 0) | `적립 안 함` | `Icons.pause_circle_outline_rounded` | `0%` | 명시: `textHeading` w800 |
| 설정 확인 필요 | 해석 결과 INVALID (§6 fail-closed) | `설정 확인 필요` | `Icons.error_outline_rounded` | `—` (대시) | `textMuted` |

- "`브랜드 설정`" 은 브랜드 목록·브랜드 편집·`brand_info_page` 에서 **브랜드 자신의 값**에 쓰고, 매장 쪽에서 같은 값이 흘러오면 `브랜드 상속` 이다. 같은 5% 가 보는 위치에 따라 이름이 다르다 (대상 기준).
- 출처 라벨 4개(`매장 설정 / 브랜드 상속 / 전역 상속 / 적립 안 함`)는 요청서의 4상태와 1:1. `브랜드 설정` 과 `설정 확인 필요` 는 같은 위젯의 파생이다.
- `적립 안 함` 이 **어느 단계에서** 나왔는지는 배지가 아니라 보조 캡션이 말한다: `매장에서 설정` / `브랜드에서 설정`. 목록처럼 공간이 좁은 곳에서는 접근성 라벨에만 넣는다.

## 1-b. 시각 규격

- 높이 22, 가로 패딩 8, **radius 6 (모서리 사각형)**, 아이콘 12 + gap 4 + 라벨 11/w600/`textBody`.
- `StoreScopeBadge` 는 radius 999 알약이다. **모양을 일부러 다르게** 해서 한 타일에 두 배지가 같이 있어도 "종류(알약) / 출처(태그)" 로 구분된다.
- 틴트·아이콘 색은 위 "색상 사용" 표.

## 1-c. "설정 없음(상속)" 과 "적립 안 함(0%)" 이 다르게 보이는 방법 — 한눈 비교

| | 상속 (필드 부재) | 적립 안 함 (명시 0) |
|---|---|---|
| 값 | **상위 값이 그대로 보인다** (`5%`) | `0%` |
| 값 색·굵기 | `textMuted` / w600 | `textHeading` / w800 |
| 배지 | 화살표 아이콘 + 회색/하늘 태그 | 일시정지 아이콘 + 노란 태그 + 테두리 |
| 편집 라디오 카드 | `상위 설정 따르기` — 설명에 **따르게 될 실제 값**(`브랜드 "Q" 의 5% 를 따라요`) | `적립 안 함 (0%)` — 선택 시 카드 전체가 warning 틴트 |
| 우선순위 사슬(§5-b) | 해당 줄이 `설정 없음` 으로 흐리게 | 해당 줄이 `0% · 적립 안 함` 으로 굵게, `적용 중` 표시 |
| 스크린리더 | `5퍼센트, 브랜드 상속` | `적립 안 함, 0퍼센트` |

- **admin 화면 어디에서도 "비어 있는 칸" 을 만들지 않는다.** 상속 상태에도 항상 상위 값이 보이고, 0 에도 항상 `0%` 가 보인다. 대시(`—`)는 해석이 불가능한 INVALID 와 로딩 후 데이터 부재에만 쓴다.

## 1-d. 기존 배지 재사용 판단 — **재사용하지 않는다 (기하만 참고)**

| 기존 | 판단 | 사유 |
|---|---|---|
| `BrandScopeBadge(brandId)` | **재사용 불가** | brandId 로 브랜드명을 비동기 조회해 `브랜드: {이름}` 을 그리는 위젯. "매장이 어떤 브랜드 소속인가" 를 말한다. 적립률 출처와 의미 축이 다르고, 타일마다 브랜드 스트림을 구독하는 비용도 있다 |

- 상태: config 로딩 → 중앙 `CircularProgressIndicator`(1차). 에러 → `QoinLoadError`. 문서 없음 → 첫 저장 변형(1차의 `설정 없음` + `적립은 ‘적립 사용’ 을 켜야 시작돼요` 줄 계승).
- 저장 성공 SnackBar: `전역 기본값을 {rate}% 로 변경했어요`. 페이지에 머문다 (1차 규칙).

## 5-b. 우선순위 사슬 `QoinRateChain`

> ⚠ **개정 2 (2026-10-22)**: `0% · 적립 안 함` 은 `사용 안 함` 으로 교체, 하단에 `다시 켜면 …` 고지 추가 (§18-3).

"왜 이 값이지?" 에 답한다. **매장 편집**은 3줄, **브랜드 편집**은 2줄(브랜드/전역), 전역 편집에는 없음.

```
┌ 지금 적용되는 값 ────────────────┐
│ 매장    설정 없음                  │  muted
│ 브랜드  5%                [적용 중] │  heading w800 + pill
│ 전역    3%                         │  muted (가려짐)
└──────────────────────────────────┘
```

- `surface` plate, radius 12, padding `h14 v12`, 행 간 gap 10. 행: 라벨(12 muted, 폭 44) + 값(14).
- **이기고 있는 줄 하나만** 굵게(`textHeading` w800) + 오른쪽 pill `적용 중`(높이 20, `primaryBright` alpha 0.15, 글자 11/w600/`textBody`). 나머지는 `textMuted` w500.
- 줄 값 표기 (**"비어 보임" 방어의 핵심**):
  - 필드 부재 → `설정 없음` (muted)
  - 명시 0 → `0% · 적립 안 함` (이기는 줄이면 굵게 + `적용 중`)
  - 유효 값 → `5%`
  - 무효 → `확인 필요` (muted + 11px `error` 아이콘)
- 브랜드 미소속(개인 매장): 브랜드 줄 **숨김**.
- **읽기 전용.** 줄이 눌려 보이지 않게 chevron·ripple 없음.

섹션 라벨 `설정 방식` (12/w600 muted, gap 6) 아래 카드 3장, 카드 간 gap 8. 각 카드: `InkWell`, radius 12, padding `h16 v14`, 높이 ≥ 56, 왼쪽 `Radio` 22.

| 카드 | 제목 (15/w600 heading) | 설명 (12 / height 1.4) |
|---|---|---|
| ① 상위 설정 따르기 | `상위 설정 따르기` | 매장: `브랜드 "{이름}" 의 {rate}% 를 따라요` / (브랜드 미소속) `전역 기본값 {rate}% 를 따라요`. 브랜드: `전역 기본값 {rate}% 를 따라요`. **따르게 될 실제 값**을 보여준다. 상위 값이 무효면 `상위 설정을 확인할 수 없어요` 로 카드 **비활성** |
| ② 직접 설정 | `직접 설정` | 매장: `이 매장만의 적립률을 정해요` / 브랜드: `이 브랜드의 적립률을 정해요`. **선택되면 카드 안에 `QoinRateInputField` + 도움말 + `QoinRatePreview` 가 펼쳐진다** |

### 하위 매장 처리 방식 (일괄 적용 1단)

> ⚠ **개정 2 (2026-10-22)**: `그중 적립 안 함 {Z}곳도 다시 적립하게 돼요` 줄은 삭제, 정보 줄로 대체 (§18-5).

표시 조건: **개별 설정이 있는 매장 수 M > 0** 이고 폼이 "변경" 상태(저장 가능 상태)일 때. M == 0 이면 섹션 자체를 숨기고(보존과 동일하므로) 확인 다이얼로그가 `산하 매장 {N}곳 모두에 적용돼요` 로 말한다.

섹션 라벨 `개별 설정이 있는 매장 처리` + 보조 `산하 매장 {N}곳 중 {M}곳이 자기 적립률을 따로 정해 두었어요` (12 muted).

| 카드 | 제목 | 설명 |
|---|---|---|
| ① (기본 선택) | `개별 설정 보존` | `따로 정해 둔 {M}곳은 그대로 두고, 나머지 {N−M}곳에 새 값을 적용해요` |
| ② | `개별 설정 덮어쓰기` | `따로 정해 둔 {M}곳의 설정을 지우고, {N}곳 모두 새 값을 따르게 해요` + 줄바꿈 + `되돌리려면 매장마다 다시 설정해야 해요` |

- **기본 선택은 보존** (비파괴). 덮어쓰기는 의식적으로 눌러야 한다.
- ② 선택 시 카드 테두리 `warning` 1.5px + 제목 앞 `Icons.warning_amber_rounded` 18 `warning`. (`error` 아님)
- 개별 설정 중 `적립 안 함(0%)` 매장이 Z>0 곳이면 ② 설명 아래 한 줄 추가: `그중 적립 안 함 {Z}곳도 다시 적립하게 돼요`.
- 하단 보조 한 줄(11 muted): `영향 매장 수는 이 화면 기준이에요. 실제 적용 결과는 완료 후 이력에서 확인할 수 있어요`.
- 숫자 M·Z 는 클라이언트가 `watchStoresByBrand` 로 센 **미리보기**다. 이력에 남는 값은 서버가 센 값 (spec §4-④).

### 부분 실패 — `status:'partial'` · `QoinPartialBanner`

세 곳에 같은 컴포넌트. **admin 이 해야 할 일을 화면이 말한다.**

```
 ┌ warning 틴트 plate ───────────────┐
 │ ⚠ 일부 매장에는 아직 적용되지 않았어요     │  14/w700 body
 │ 브랜드 "Q브루어리" 의 적립률은 이미 5% 로   │

 │ 계속 쓰고 있어요.                        │
 │ 이어서 적용하면 남은 5곳만 처리돼요.        │  13/w600 body
 │ [ 이어서 적용 ]  [ 나중에 ]               │
 └───────────────────────────────────┘
```

- 말하는 순서가 중요하다: ① **무슨 일이 있었나**(일부 미적용) ② **안전한가**(브랜드 값은 바뀌었고, 남은 매장은 이전 값을 유지 — 이상한 중간 값을 받은 매장은 없다) ③ **무엇을 하면 되나**(이어서 적용). 이 순서가 admin 의 불안(어떤 매장이 어떤 값으로 적립되고 있나)을 먼저 가라앉힌다. spec §4-④ 가 보장하는 사실이다.
- `{12곳 중 7곳}` 은 이력의 `processedCount` 와 처리 대상 수. 대상 수를 모르면 `7곳까지 처리했고` 로 축약.
- 버튼: `이어서 적용`(primary 채움, 높이 44) → `QoinRateConfirmDialog`(동작 `이어서 적용`, 헤더 `브랜드 "Q브루어리" 전체`, 영향 블록 `남은 {n}곳의 개별 설정이 지워져요`, 체크박스는 다시 요구) → 실행 → 결과 카드 또는 다시 partial. `나중에`(텍스트 버튼) → 이번 세션에서 배너만 접음 (이력·허브 배너는 그대로).
- 이어서 적용 **재실패**: SnackBar `이어서 적용하지 못했어요. 잠시 후 다시 시도해주세요`, 배너 유지.
- `status:'in_progress'` 인데 오래 지난 건(고아): 이력 행에서 `적용 중` 대신 partial 과 같은 모양으로 취급한다. 판정 기준 시간은 한 상수로 (잔여 결정 6).

## 9-b. 관리자 이력 화면 `AdminQoinRateHistoryPage`

```
┌ AppBar  ‹  변경 이력 ──────────────┐
│ (전체)(전역)(브랜드)(매장)(미완료 적용)  │  필터 칩 (가로 스크롤, 고정)
│ ┌ 원장형 카드 (헤어라인 구분) ───────┐ │
│ │ 행 … 행 … 행                     │ │
│ └───────────────────────────────┘ │
│ [ 이전 이력 더 보기 ]                │
└───────────────────────────────────┘
```

- 1차 원장 카드와 같은 모양: `surfaceElevated` + `border` + radius 16 한 장 안에 헤어라인 구분(`indent 16`). 행 padding `h16 v14`.
- 필터 칩(단일 선택): `전체` / `전역`(비상 정지 이력 포함) / `브랜드` / `매장` / `미완료 적용`. 칩 규격은 §7-a 필터 칩과 같다.
- 쿼리는 `collectionGroup('qoinRateHistory') orderBy changedAt desc`, 페이지 50건. 하단 버튼 `이전 이력 더 보기`(외곽선, 높이 44, 폭 전체 - 40 마진): 탭하면 50건 더 로드. 로딩 중 버튼 안 인디케이터. 더 없으면 버튼 대신 `모든 이력을 불러왔어요` 12 muted/중앙.
- 필터는 가능한 한 서버 쿼리, 안 되면 로드된 범위 안의 클라이언트 필터. 클라이언트 필터일 때 결과가 비어도 "더 불러오면 있을 수 있음" 이므로 필터 결과 0 이고 더 불러올 수 있으면 `이전 이력 더 보기` 를 **그대로 노출**.
- 허브 배너에서 들어오면 `미완료 적용` 칩이 선택된 채로 열린다.

| 상태 | 표현 |
|---|---|
| Loading | 필터 칩 + 카드 안 skeleton 4행 (좌 원 32, 제목 박스 160x14, 값 박스 90x15, 일시 박스 80x12, `border` 정적 박스) |

## 9-c. 점주·브랜드 이력 화면 `QoinRateHistoryPage(scope, targetId)` (공용, 읽기 전용)

# 10. 고객 Qoin 화면 수정 — `qoin_balance_card.dart` (`_QoinPolicyPlate` 행 1)

**교체 대상**: 정상(비중단) 분기의 주문구 `픽업 완료 시 결제액의 ${rate} 적립` 과 `비율 모름` 분기의 `픽업 완료 시 적립돼요`.

| 조건 | 주문구 (13 / w600 / textBody) | 보조구 (12 / w400 / textMuted / height 1.4) |
|---|---|---|
| 정상 (config 로딩·에러·정상 **모두 동일**) | **`픽업 완료 시 결제액의 일부가 적립돼요`** | **`적립률은 매장마다 달라요. 결제 직후가 아니라, 매장에서 픽업 완료 처리가 되면 반영돼요`** |
| 적립 중단 (1차 그대로) | `지금은 Qoin 적립이 잠시 중단되어 있어요` | `이 기간에 픽업 완료된 주문은 적립 대상에서 빠질 수 있어요` |

- 아이콘·plate 배경·행 구조는 1차 그대로 (정상 `shopping_bag_outlined` / 중단 `pause_circle_outline_rounded` + warning 틴트).
- **숫자가 사라지므로** config 로딩 중 `픽업 완료 시 적립돼요` → `…결제액의 3% 적립` 으로 문구가 바뀌던 깜빡임이 없어진다. `비율 모름` 분기를 삭제한다.
- `적립률은 매장마다 달라요.` 를 **보조구 첫 문장**으로 둔 이유: 주문구는 "적립된다" 는 사실(다른 곳과 동일 위계), 보조구는 한계·조건. 숫자가 없는 이유가 읽는 사람에게 설명된다.
- 중단 분기 판정(`_paused`)은 건드리지 않는다: 전역 `enabled == false` (또는 전역 기본값이 무효/부재) 기준 그대로. 매장·브랜드 0% 는 고객 화면 전역 plate 로 표현할 수 없다 (N2).
- **과거 내역 행의 `결제액 18,000원의 3%` 는 불변**(원장에 박제된 당시 값). 이번 변경 범위가 아니다.
- 접근성: 라벨은 `Semantics(label: '<주문구>. <보조구>', excludeSemantics: true)` 구조 그대로이므로 문자열 교체만으로 반영된다.

# 12. 접근성 — 적립률 · 출처가 스크린리더로 읽히는 방식

## 기본 규칙 (1차 계승)

- **음수·화살표 기호를 읽게 하지 않는다.** 화살표 `→` 는 `에서 … (으)로` 로 조립한다. `%` 는 `퍼센트`. 하이픈·대시(`—`)는 읽히지 않게 `ExcludeSemantics` 하고 `확인 필요`/`설정 없음` 같은 말로 대체한다.
- 시각 요소(배지·아이콘·chevron)는 `ExcludeSemantics`, 행/카드 단위로 `Semantics(label, excludeSemantics: true)` 를 한 번 만든다.
- 터치 타깃 ≥ 44. 텍스트 1.5x 에서 겹침·잘림 없음: 값은 `FittedBox(scaleDown)`, 이름은 2줄 허용, 필터 칩 행은 가로 스크롤, 다이얼로그는 스크롤.
- 색 단독 전달 금지: 5개 출처 배지는 **라벨 글자 + 아이콘**이 의미를 담고 색은 보조다.

## 조사 `(으)로` 규칙 — 이력 문장 조립용

| 도착 값 | 조사 | 예 |
|---|---|---|
| `…퍼센트` | `로` | `3퍼센트에서 5퍼센트로` |
| `적립 안 함` | `으로` | `5퍼센트에서 적립 안 함으로` |
| `설정 없음` | `으로` | `5퍼센트에서 설정 없음으로` |
| `적립 중` / `적립 중단됨` | `으로` | `적립 중에서 적립 중단됨으로` |

# 14. 개발자 전달 특이사항

> ⚠ **개정 2 (2026-10-22)**: **5, 6, 9, 10, 13번 항목은 §18-13 으로 교체/삭제됐다** (5: 4값 → 적립률 3값 + 스위치 4값, 6: 0 입력은 스위치 안내, 9·10: 체크박스, 13: 조용한 생략 폐기).

1. **카피는 §15 "카피 문자열 일람" 의 글자 그대로.** 특히 확인 다이얼로그 첫 줄 3종, 덮어쓰기 경고, partial 배너, 고객 문구.
2. **범위 줄 문자열은 `QoinScopeLabel` 한 곳에서만 생성**한다. 밴드·다이얼로그·이력·SnackBar 가 각자 조립하면 반드시 어긋난다.
3. **검증 카피는 공용 위젯 2개(`QoinRateInputField`, `QoinRateConfirmDialog`)에만** 존재해야 한다. 페이지 3개에 `validateRateInput` 직접 호출 금지.
4. **출처 배지를 `presentation/common/widgets/qoin/` 에 둔다.** owner/brand 화면이 `presentation/admin/` 을 import 하면 1차 test_report ⑩ 의 역할 간 import 문제가 재발한다. (기존 `StoreScopeBadge` 가 이미 `admin/widgets/` 에 있어 owner·brand 가 import 중인 것은 이번 범위에서 건드리지 않는다.)
5. **상속과 0% 의 구분을 코드로도 구분한다.** UI 모델에서 `부재 / 유효 / 명시 0 / 무효` 4값을 `null`/`0.0` 로 뭉개지 말고 `QoinPolicy.resolveEffectiveRate` 결과 + 각 단계 원본(`EffectiveQoinRate`)으로 전달한다. 배지·사슬·라디오 초기 선택이 모두 이 원본을 쓴다.
6. **명시 0% 는 ③ 카드에서만 만든다.** `QoinRateInputField` 에 0 이 들어오면 1차대로 `tooLow`. 입력란 하한 검사가 소수 자릿수 검사보다 먼저인 1차 순서를 바꾸지 않는다 (`0.03` → `tooLow`).
7. **로딩 중 값을 그리지 않는다.** 매장 목록·읽기 행은 3개 소스(대상·브랜드·전역)가 모두 준비된 뒤에만 숫자를 그린다. 일부만 준비된 상태의 "임시 해석" 금지.
8. **브랜드 저장은 항상 산하 매장 정보 로딩 후.** 로딩/에러 중 저장 버튼 비활성. 확인 다이얼로그의 N, M, Z 는 클라이언트 미리보기이고 결과 카드·이력의 숫자는 서버 응답을 쓴다.
9. **개별 설정이 0곳이면 모드 선택 UI 와 체크박스를 모두 생략**한다 (CF 호출은 `preserve`).
10. **덮어쓰기 체크박스는 다이얼로그를 열 때마다 미체크.** 상태를 페이지에 보관하지 않는다.
11. **일괄 적용 실행 중 `PopScope(canPop: false)`.** partial 의 모든 진입(브랜드 편집·이력·허브)이 같은 `QoinPartialBanner` + 같은 `이어서 적용` 흐름을 쓴다.
12. **오류 분류**: 확정 실패(permission-denied / invalid-argument / not-found)와 결과 불명(deadline-exceeded / unavailable / 네트워크)을 구분해 §6-d 의 문구를 쓴다. 결과 불명에서는 재시도를 권하지 않는다.
13. **허브 부제/배너 실패는 조용히 생략.** 에러 UI 를 만들지 않는다.
14. **`가맹점 타일` 은 타일마다 스트림을 만들지 않는다.** 페이지 레벨 구독 + 합성.
15. **`partial` 조회에 `where status == 'partial'` collection group 쿼리가 필요할 수 있다.** 인덱스는 spec §7.5 에 따라 실측 확정(에뮬레이터 통과는 근거가 아님). 불가하면 허브 배너는 최근 이력 페이지 안에서만 판정하는 축소 동작이 되므로 architect 확인.
16. **customer 쪽 변경은 문자열 교체 + `비율 모름` 분기 삭제뿐.** 1차 `_paused` 와 내역 행은 건드리지 않는다.
17. 1차에서 이미 추출된 provider 가 `presentation/customer/qoin/providers/*` 를 import 하는 문제(1차 test_report ⑩)는 spec §11.4 대로 이번에 공용 위치로 옮긴다. 이 문서의 모든 신규 위젯은 새 위치만 import 한다.

# 16. 완료 기준 (디자인 관점)

> ⚠ **개정 2 (2026-10-22)**: 0% / 체크박스 / 조용한 생략 관련 항목은 §18-14 로 교체됐다.

- [ ] 관리자 3범위 모두 확인 다이얼로그의 **첫 줄이 범위 + 대상명**이고 18/w800 으로 가장 크다
- [ ] 검증 에러·인상 경고·환산 문구가 **공용 파일 2개에만** 있고 페이지 3개에는 없다
- [ ] 상속 상태에서 **값이 비어 보이지 않는다** (상위 값 노출). `0%` 는 `0%` + warning 배지 + 굵은 값으로 상속과 구분된다
- [ ] `적립 안 함 (0%)` 은 라디오 ③ 으로만 만들어지고 입력란 `0` 은 `tooLow`
- [ ] 입력 `0.03` / `30` 이 3범위에서 모두 차단된다 (1차 방어 유지)
- [ ] 브랜드 덮어쓰기: 영향 매장 수·개별 설정 수·`적립 안 함` 재활성·"되돌리려면 개별 재설정" 이 **확인 전에 모두 보이고**, 체크 전에는 실행 버튼이 비활성
- [ ] 개별 설정 0곳 브랜드는 모드 선택 없이 저장된다
- [ ] partial 시 화면이 ① 무슨 일이 있었나 ② 안전한가 ③ 무엇을 해야 하나 를 이 순서로 말하고 `이어서 적용` 이 브랜드 편집·이력·(허브→이력)에서 닿는다
- [ ] 결과 불명 오류에서 재시도를 권하지 않는다
- [ ] 점주·브랜드 읽기 행 3곳에 **입력란·`수정`·`변경` 라벨·값 chevron 이 없다**. 이력 링크만 별도
- [ ] 읽기 행이 로딩 중 `0%` 나 이전 값을 그리지 않는다
- [ ] 출처 배지 5종이 색 없이도(글자 + 아이콘) 구분된다. 새 배지와 `StoreScopeBadge` 가 한 타일에 있어도 모양(6 vs 999)·위치로 구분된다
- [ ] 고객 plate 에 숫자 퍼센트가 없다. 과거 내역 행은 그대로다
- [ ] 이력 행: 일괄은 1행에 영향 매장 수·덮어쓰기 여부 포함, `설정 없음 → 5%` / `5% → 적립 안 함` 이 읽힌다
- [ ] 스크린리더 라벨에 `→`·`%`·음수 하이픈이 없다 (`에서 … (으)로`, `퍼센트`)
- [ ] `Color(0x…)` 0건, 신규 토큰 0개, 텍스트 1.5x 에서 겹침·잘림 없음

### designer 가 추가로 짚은 것 — 반영 확정

spec 에 없던 지적이다. 의도치 않게 **돈이 나가기 시작하는 경로**이므로, 확인 다이얼로그에 **별도 줄로 노출**한다 (`Z곳`). 클라이언트가 셀 수 있으므로 추가 쿼리도 필요 없다.

# 18. 개정 2 — `적립 사용` 스위치 분리 (spec §20)

> **이 절이 §1~§17 의 충돌하는 부분을 모두 대체한다.** 근거: spec §20 (Q1 확정). §20 이 §19 를 정정하고 §19 가 §1~§18 을 정정한다는 spec 의 우선순위를 그대로 따른다.
> 뒤집지 않은 확정: **적립률 0 입력 금지 / 끄기 전 숫자 미보존 / 브랜드에도 스위치 / 일괄 적용은 스위치를 건드리지 않음.**
> 신규 색 토큰 0개. 아래 모든 색은 기존 `AppColors` 토큰이다.

## 18-0. 무엇이 바뀌었나 — 충돌 대응표

## 18-1. 용어 — 한 가지만 쓴다

| 쓰는 말 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| **`적립 사용`** | 스위치의 제목. 켜짐 = 적립함 | `적립 안 함 (0%)`, `0%`, `적립 중단`(스위치 상태로는 쓰지 않음. 전역 비상 정지의 `적립 중단됨` 과 혼동되므로) |
| **`사용 안 함`** | 스위치가 꺼진 상태의 값 라벨 (사슬·목록·값 칸) | |
| `적립 사용 안 함` | 위의 문장형 (읽기 행, 이력, 설명문) | |
| `전체 적립 중단` | 전역 비상 정지 (`config/qoin.enabled`). **스위치와 다른 것** | |

- spec 은 토글을 `적립 사용 안 함` 으로 불렀다. **스위치의 제목은 `적립 사용`, 켜짐 = 적립함** 으로 둔다. `적립 사용 안 함` 이라는 제목에 스위치를 켜면 "안 함이 켜진다" 는 이중 부정이 된다. 상태 라벨이 `사용 안 함` 이므로 spec 의 용어는 그대로 화면에 나온다. (사용자 확인 불필요한 표기 판단. 반대 극성이 필요하면 §18-15 에 있다.)
- 전역 비상 정지 카드 제목도 `적립 사용` 이라 **스위치 제목이 겹친다.** 매장·브랜드 스위치는 대상을 제목에 넣어 구분한다: `이 매장 적립 사용` / `이 브랜드 적립 사용`. 비상 정지 카드는 기존 `적립 사용 (비상 정지)` 그대로.

## 18-2. ① 매장·브랜드 편집 화면의 `적립 사용` 스위치

### 18-2.1 배치 — 적립률 폼과 시각적으로 갈라 놓는다

```
 … QoinScopeBand → (partial 배너) → QoinCurrentRateCard → QoinRateChain
 적립률                                      ← 섹션 라벨 12/w600 muted (신규. 폼 전체를 묶는 라벨)
 [안내 plate — 스위치가 꺼져 있을 때만]
 설정 방식  ① 상위 설정 따르기 / ② 직접 설정 ▸ 입력
 (하위 매장 처리 — 브랜드, 조건부)
 사유 (선택)
 [   매장 설정 저장 (52h)   ]                ← 여기서 "적립률 폼" 이 닫힌다
                                              ↕ gap 32 (다른 섹션 간격 20 보다 크다)
 적립 사용                                    ← 섹션 라벨 12/w600 muted
 ┌ QoinAccrualSwitchCard ───────────────┐
 │ (아이콘 22)  이 매장 적립 사용      [Switch] │
 │ 이 매장의 주문은 픽업 완료 시 Qoin 이 적립돼요 │
 │ 위 ‘매장 설정 저장’ 과 별개로 바로 적용돼요   │  11 muted
 └──────────────────────────────────────┘
```

- **저장 버튼 아래, 맨 마지막**에 둔다. 이유 3가지.
  1. 적립률 폼은 "입력 → 저장 버튼" 으로 닫히는 한 덩어리다. 저장 버튼 뒤에 오면 스위치가 그 폼의 일부로 읽힐 수 없다. 둘이 한 묶음으로 보이면 사용자가 다시 "숫자 칸이 0 이면 꺼지는 것" 으로 이해한다.
  2. 커밋 방식이 다르다. 폼은 하단 버튼으로 확정하고, 스위치는 **스위치를 누를 때 그 자리에서 확인 다이얼로그를 거쳐 즉시 확정**한다. 저장 버튼 위에 있으면 "스위치도 저장 버튼에 묶여 있나" 를 매번 헷갈린다. 카드 안에 `위 ‘매장 설정 저장’ 과 별개로 바로 적용돼요` 를 상시 노출한다.
  3. 폼 초안(입력 중인 숫자)은 스위치 조작으로 **지워지지도, 저장되지도 않는다.**
- 시각 분리: 폼은 평면 섹션(라디오 카드·입력창), 스위치는 **독립 카드**(`surfaceElevated` + `border`, radius 16, padding 16). 섹션 라벨도 `적립률` / `적립 사용` 으로 따로 둔다. 브랜드 편집 화면도 같은 순서·같은 위젯이다.
- 상태: 대상 문서 로딩 중에는 카드 skeleton (높이 96, `border` 정적 박스), 스위치 **숨김**. 에러는 페이지 전체 `QoinLoadError` (기존). 값을 모른 채 스위치를 보이지 않는다.

### 18-2.2 `QoinAccrualSwitchCard` (신규 공용 위젯, `admin/qoin/widgets/`)

| | 켜짐 (적립 사용) | 꺼짐 (사용 안 함) |
|---|---|---|
| 카드 배경 / 테두리 | `surfaceElevated` / `border` 1px | `warning` alpha 0.10 / `warning` alpha 0.5 1px (1차 `적립 안 함` 틴트 규격) |
| 아이콘 22 | `Icons.toll_rounded` `primary` | `Icons.pause_circle_outline_rounded` `warning` |
| 제목 15/w700 `textHeading` | 매장 `이 매장 적립 사용` / 브랜드 `이 브랜드 적립 사용` | 동일 |
| 상태 칩 (제목 옆, 높이 20, radius 6, 11/w600/`textBody`) | 없음 | `사용 안 함` (`warning` alpha 0.18) |
| 설명 13/`textBody` | 매장 `이 매장의 주문은 픽업 완료 시 Qoin 이 적립돼요` / 브랜드 `이 브랜드 매장의 주문은 픽업 완료 시 Qoin 이 적립돼요` | 매장 `이 매장은 Qoin 을 적립하지 않아요. 환불로 인한 회수는 계속돼요` / 브랜드 `이 브랜드는 기본으로 Qoin 을 적립하지 않아요. 환불로 인한 회수는 계속돼요` |
| 브랜드 전용 추가 줄 12 muted | `산하 매장 {N}곳` | `산하 매장 중 적립률을 따로 정한 {M}곳은 계속 적립돼요` (M=0 이면 줄 없음. **R06**: 매장 개별 적립률은 브랜드 스위치를 이긴다) |
| 하단 11 muted | `위 ‘매장 설정 저장’ 과 별개로 바로 적용돼요` (브랜드는 `위 ‘브랜드 설정 저장’ …`) | 동일 |
| 스위치 | Material `Switch`, on, 1차 `QoinKillSwitchCard` 의 스위치 색 규칙 재사용 | off |

- **스위치는 낙관적으로 움직이지 않는다.** 탭 → 확인 다이얼로그(§18-2.5) → 확인 → 호출 중에는 스위치 자리에 20x20 인디케이터(스위치 숨김) → 서버 스트림 값이 바뀌면 카드가 바뀐다. 취소·실패 시 스위치는 원래 자리에 그대로다.
- 브랜드 스위치는 **산하 매장 정보 로딩이 끝나기 전에는 비활성**이고 카드 하단에 `산하 매장 정보를 불러오는 중이에요`(11 muted). M 을 모른 채 `계속 적립돼요 {M}곳` 을 말하지 않기 위함이다 (기존 H5 규칙).
- 일괄 적용 실행 중(`PopScope` 덮개)에는 어차피 조작할 수 없다.
- 카드에 `수정`/`변경` 라벨, chevron 을 두지 않는다. 조작 수단은 스위치 하나다.

### 18-2.3 스위치가 꺼졌을 때 적립률 입력란은 **그대로 둔다 (비활성화하지 않는다)**

**판단: 비활성화하지 않는다.** spec 권고와 같다. 근거 5가지.

1. **숫자와 스위치는 독립인 두 축이다 (spec §20.0).** 입력란을 회색으로 만들면 화면이 "스위치 > 숫자 (꺼지면 숫자는 의미 없음)" 이라고 말하게 되고, 이는 곧 "끄는 것 = 숫자를 없애는 것(≈ 0)" 이라는 옛 이해로 돌아간다. 이 개정의 목적을 화면이 스스로 깨게 된다.
2. **실제로 의미 있는 편집이다.** 꺼 둔 매장에 적립률을 미리 정해 두고(`직접 설정 7%`) 나중에 켜는 운영은 정상 흐름이다. 이 숫자는 R04b 에 따라 보존되며 다시 켜면 그대로 적용된다.
3. **일괄 적용은 꺼진 매장의 숫자도 쓰고 지운다 (spec §20.6.1).** 숫자가 시스템에서 계속 읽히고 쓰이는 값인데 화면에서만 잠그면 사실과 다르다.
4. **1차 규칙**: 값이 불분명한 곳에 비활성 입력란을 두지 않는다(§5-c ①, 비활성 입력란 금지).
5. 비활성화의 장점(오해 방지)은 아래의 **안내 plate** 로 얻는다.

대신 꺼져 있을 때 **적립률 섹션 맨 위**(라벨 `적립률` 바로 아래, 라디오 위)에 정보 plate 를 둔다.

```
 ┌ 정보 plate (surface, radius 12, padding h14 v12) ┐
 │ ⓘ 지금은 적립 사용 안 함 상태예요.                │  13/w600 body
 │   적립률을 바꿔도 다시 켜기 전에는 적립되지 않아요.  │  12 muted
 └──────────────────────────────────────────────┘
```

- 아이콘 `Icons.info_outline_rounded` 16 `textMuted`. **`warning` 색이 아니다** — 위험 경고가 아니라 사실 고지이고, 경고색은 스위치 카드 한 곳이 가진다.
- 브랜드가 꺼져 있어 매장이 영향을 받는 경우(매장 화면): 같은 plate 에 `브랜드가 적립 사용 안 함이라, 이 매장에 직접 설정한 적립률만 적용돼요` 한 줄 (R06 의 귀결을 알려 준다).
- 확인 다이얼로그의 비교 블록은 스위치와 무관하게 **"켜져 있다면 적용될 값"** 끼리 비교한다 (`3% → 5%`). 꺼진 상태에서 저장할 때 다이얼로그에 한 줄이 더 붙는다: `지금은 적립 사용 안 함이라, 바꾼 값은 다시 켤 때부터 적용돼요`.

### 18-2.4 적립률 `0` 입력 거부 — **이 화면에서 가장 중요한 문구**

사용자는 "적립을 끄려고 0 을 넣는" 시도를 한다(옛 방식이 그랬고, 직관적으로도 그렇다). 거부는 **막는 것이 아니라 스위치로 안내하는 것**이어야 한다.

| 위치 | 문자열 | 스타일 |
|---|---|---|
| **입력 에러 (0, 0.0, 00 …)** — 매장·브랜드 | **`0% 는 적립률로 입력할 수 없어요. 적립을 멈추려면 이 화면 아래쪽 ‘적립 사용’ 을 끄세요`** | 필드 에러 (`error`, 1차 에러 규격) |
| 에러 바로 아래 행동 링크 (매장·브랜드) | **`적립 사용 끄러 가기`** + `Icons.arrow_downward_rounded` 14 | 12/w600/`primary`, 높이 44, 좌측 정렬 |
| 입력 에러 — 전역 | `0% 는 적립률로 입력할 수 없어요. 전체 적립을 멈추려면 Qoin 설정 화면의 ‘적립 사용’ 을 끄세요` | 링크 없음 (전역에는 이 화면에 스위치가 없다) |
| **사전 안내 (도움말 2째 줄, 매장·브랜드)** | `적립을 멈추려면 0 이 아니라 아래 ‘적립 사용’ 을 끄세요` | 11 muted. 에러가 나기 **전에** 읽히게 상시 노출 |
| 도움말 1째 줄 | 1차 그대로 `0.1 ~ 20% 사이로 입력해요. 3% 는 ‘3’ 으로 입력하세요 (0.03 이 아니에요)` | |

- `적립 사용 끄러 가기` 탭 동작: 스위치 카드로 스크롤(`Scrollable.ensureVisible`)하고 카드 테두리를 `primary` 1.5px 로 1.2초 강조한 뒤 원복. 포커스를 카드 스위치에 옮긴다(스크린리더가 `이 매장 적립 사용, 스위치, 켜짐` 을 읽는다). **스위치를 대신 눌러 주지는 않는다** (돈이 멈추는 동작은 사용자가 직접).
- 문구가 `‘적립 사용’ 을 끄세요` 이고 카드 제목이 `이 매장 적립 사용` 이므로 글자가 이어진다. 카드가 화면 밖일 수 있어 `이 화면 아래쪽` 이라고 위치를 말한다.
- **1차 `tooLow` 와 구분한다.** `0.03` 은 여전히 `tooLow`(`0.1% 이상 입력해주세요. 3% 는 ‘3’ 으로 입력해요`) — 3 을 쓰려다 0.03 을 쓴 실수이고, 안내가 다르다. 구분 기준: **숫자로 파싱한 값이 정확히 0** 일 때만 위 문구. 판정은 `QoinPolicy.validateRateInput` 의 신규 status(`zero`) 한 곳, 카피는 `qoin_rate_input_field.dart` 한 곳 (§2-d 드리프트 규칙 유지).
- **타이밍**: `0.5` 를 입력하는 도중 첫 글자 `0` 에서 에러가 번쩍이지 않게 한다. 1차의 에러 표시 시점 규칙을 따르되, 1차가 즉시 표시라면 **입력이 정확히 `0` 한 글자인 동안은 포커스 중 에러를 숨기고** blur 나 저장 시도에서 표시한다. (`0.`, `0.0` 은 이미 소수점을 찍은 의도이므로 즉시 표시.) 이때 미리보기는 `—`, 저장 버튼은 비활성 (1차 동일).
- 입력란 `0` 을 스위치로 **자동 변환하지 않는다** (입력이 부수효과를 일으키지 않는다).

## 18-3. ② 우선순위 사슬 `QoinRateChain` — `사용 안 함` 과 `다시 켜면`

### 행 값 표기 (교체)

| 상태 | 표기 | 스타일 |
|---|---|---|
| 필드 부재 | `설정 없음` | muted |
| 유효 값 | `5%` | |
| **스위치 꺼짐** | **`사용 안 함`** (앞에 `Icons.pause_circle_outline_rounded` 14 `warning`) | 이기는 줄이면 `textHeading` w800 + `적용 중` pill. 가려진 줄이면 `textMuted` w500 + 뒤에 11 muted `(가려짐)` |

- **`0% · 적립 안 함` 은 사라진다.** 스위치가 꺼진 줄은 **숫자를 보이지 않는다** (`5%` 로 읽히면 안 된다는 spec §20.6.2).
- 스위치가 꺼졌고 그 줄에 **개별 적립률도 있으면** (R04b) 값 아래에 11 muted 보조 줄: `개별 적립률 {r}% 가 설정돼 있어요`. 이 숫자는 이기지 못하는 값이라 작게·흐리게.

### 어느 쪽이 꺼졌는지 — `source` 를 따른다 (R24)

| 상황 | 매장 줄 | 브랜드 줄 | 전역 줄 |
|---|---|---|---|
| 매장만 꺼짐 | `사용 안 함` **적용 중** | `5%` muted | `3%` muted |
| 브랜드만 꺼짐 (매장 개별 적립률 없음) | `설정 없음` muted | `사용 안 함` **적용 중** | `3%` muted |
| **매장·브랜드 둘 다 꺼짐** (R24: `source = store`) | `사용 안 함` **적용 중** | `사용 안 함 (가려짐)` muted | muted |
| 브랜드 꺼짐 + 매장 개별 적립률 유효 (R06) | `10%` **적용 중** | `사용 안 함 (가려짐)` muted | muted |

- 개인 매장은 브랜드 줄이 숨김이다 (기존).

### `다시 켜면` 고지 — 사슬 plate 맨 아래 (**고지 위치 1/2**)

```
┌ 지금 적용되는 값 ────────────────────┐
│ 매장    ⏸ 사용 안 함            [적용 중] │
│ 브랜드  5%                              │
│ 전역    3%                              │
│ ─────────────────────────────────────  │  헤어라인 border
│ ↺ 다시 켜면 브랜드 5% 가 적용돼요          │  13/w600 textBody
│   끄기 전 값이 아니라 지금의 요율이에요      │  12 muted
└─────────────────────────────────────┘
```

- 꺼진 줄이 **하나라도 있을 때만** 헤어라인 아래 블록을 그린다 (켜져 있으면 plate 는 지금 그대로). 아이콘 `Icons.restart_alt_rounded` 16 `textMuted`. `warning` 색 아님.
- **왜 보여 주나**: 일괄 적용이 꺼진 매장의 숫자도 덮고 지우므로(spec §20.6.1), 다시 켜면 **끄기 전 값이 아니라 그 시점의 브랜드·전역 요율**로 적립된다. 이 사실이 화면에 없으면 다시 켤 때 놀란다.
- 문장은 `QoinReenableHint.of(store, brand, global)` **한 함수**가 만들고, 사슬·켜기 다이얼로그가 같은 결과를 쓴다. **"스위치가 켜졌다고 가정하고" 같은 해석 사슬을 한 번 더 돌려** 만든다 (아래 표).

| # | 켰다고 가정한 해석 결과 | 사슬 하단 문장 (13/w600) | 보조 (12 muted) |
|---|---|---|---|
| A | 매장 개별 적립률 유효 | `다시 켜면 이 매장의 개별 적립률 {r}% 가 적용돼요` | — (끄기 전 값이 보존된 경우) |
| B | 브랜드 적립률 유효 (브랜드 켜짐) | `다시 켜면 브랜드 {b}% 가 적용돼요` | `끄기 전 값이 아니라 지금의 요율이에요` |
| C | 전역 (브랜드 없음/적립률 없음) | `다시 켜면 전역 기본값 {g}% 가 적용돼요` | 〃 |
| D | **브랜드가 꺼짐** (R24 뒤쪽) | `다시 켜도 브랜드가 사용 안 함이라 적립되지 않아요` | `브랜드의 ‘적립 사용’ 도 켜야 해요` |
| E | 무효 | `다시 켜도 적립률 설정에 문제가 있어 적립되지 않을 수 있어요` | — |

- A 는 "끄기 전 숫자 미보존" 과 충돌하지 않는다. 미보존은 **0% 센티넬을 옮긴 경우**(개별 숫자가 원래 없음)와 **일괄 적용이 덮은 경우**이고, 매장에 개별 적립률이 실제로 남아 있으면 스위치를 켜도 그 숫자가 적용된다(R04b). 화면이 지금 보이는 사실 그대로를 말한다.
- **브랜드 줄이 꺼져서 매장이 멈춘 경우**(매장 화면, 매장 스위치는 켜짐): 하단 블록이 다른 말을 한다.
  - `브랜드가 사용 안 함이라 이 매장은 적립하지 않아요` (13/w600)
  - `이 매장만 적립하려면 ‘직접 설정’ 으로 적립률을 정하세요 · 브랜드를 다시 켜면 {브랜드 b% / 전역 g%} 가 적용돼요` (12 muted)
- 브랜드 편집 화면: A 없음. B(브랜드 적립률 있음) → `다시 켜면 브랜드 {b}% 가 적용돼요`, C(없음) → `다시 켜면 전역 기본값 {g}% 가 적용돼요`, E 동일.
- 일괄 적용이 중간에 값을 바꾸면 이 문장도 실시간(스트림)으로 따라간다. 스냅샷을 쓰지 않는다.
- 접근성: 사슬 전체를 한 번 읽는다. `지금 적용되는 값. 매장은 사용 안 함, 적용 중. 브랜드는 5퍼센트. 전역은 3퍼센트. 다시 켜면 브랜드 5퍼센트가 적용돼요`.

### `QoinCurrentRateCard` (상단 큰 숫자)

- 꺼진 상태: 값 자리 `사용 안 함` 24/w800 `textHeading` (앞에 pause 아이콘 22 `warning`), 배지 `매장에서 중단` / `브랜드에서 중단` (§18-4), 환산 줄 `결제 10,000원 → 적립 없음` 로 대체. **`5%` 를 큰 숫자로 보이지 않는다.**
- 스위치 카드와 헤드라인이 같은 말(`사용 안 함`)을 하게 된다. 이는 의도적인 반복이다 (화면 상단·하단 어느 쪽을 읽어도 같은 결론).

## 18-5. ③ 일괄 적용 다이얼로그 — 경고·체크박스 제거, 정보 줄, 사후 확정 고지

### 하위 매장 처리 방식 섹션 (1단, `AdminQoinBrandRateEditPage`)

- 카드 ② `개별 설정 덮어쓰기` 설명의 `그중 적립 안 함 {Z}곳도 다시 적립하게 돼요` 줄을 **삭제**한다.
- 섹션 하단(기존 `영향 매장 수는 이 화면 기준이에요…` 위)에 **정보 줄**을 추가한다 (K>0 일 때만): `적립 사용 안 함 {K}곳은 어느 쪽을 골라도 적립이 시작되지 않아요`. 스타일: 아이콘 `Icons.info_outline_rounded` 14 `textMuted` + 12 `textBody`. 경고색 아님.

### 확인 다이얼로그 (2단) — 보존·덮어쓰기 공통

영향 블록 아래에 **정보 줄** 하나(K>0 일 때만). 경고 plate 가 아니다.

```
 ⓘ 적립 사용 안 함 3곳은 새 값을 받아도 적립이 시작되지 않아요     13 body
   (이 화면 기준이에요. 실제 수는 완료 후 알려드려요)              11 muted
```

- 문자열: `적립 사용 안 함 {K}곳은 새 값을 받아도 적립이 시작되지 않아요` + `이 화면 기준이에요. 실제 수는 완료 후 알려드려요`.
- **spec §20.12-3 의 예시 문구 `…3곳은 영향을 받지 않아요` 를 그대로 쓰지 않는다.** 덮어쓰기에서는 꺼진 매장의 **개별 적립률도 지워진다**(스위치만 안 건드린다). "영향을 받지 않는다" 는 그 매장에 대해 틀린 문장이 된다. 사실은 "적립이 시작되지 않는다" 이다. (결정을 뒤집은 것이 아니라 같은 사실의 정확한 표현이다.)
- 아이콘 `Icons.info_outline_rounded` 16 `textMuted`, 배경 없음(plate 아님). 경고 plate 의 `warning` 틴트와 시각적으로 갈라, 이 줄이 **위험 고지가 아니라 안내**임을 보인다.
- K 는 클라이언트가 `watchStoresByBrand` 로 센 **미리보기**다 (1차 규칙). 확정 수치는 완료 카드(아래).
- **체크박스 삭제.** `덮어쓰고 적용` 은 처음부터 활성이다. 다이얼로그를 열 때마다 미체크로 시작한다는 §14-10 도 함께 삭제.
- 덮어쓰기 경고 plate(`개별 설정 {M}곳이 지워져요`, 1~3줄)는 **그대로 유지**한다 — 이것은 Z 와 무관하게 여전히 사실이다 (M곳의 개별 적립률이 지워진다). 단 plate 안의 `· 그중 적립 안 함 {Z}곳도 다시 적립해요` 줄은 **삭제**. 체크박스가 없어졌으므로 마찰은 (a) 첫 줄 범위·대상명 18/w800 (b) plate (c) 버튼 라벨이 동사 그대로 `덮어쓰고 적용` 인 것 세 가지로 진다.
- **브랜드 자신이 꺼져 있을 때** (R06 의 귀결): 덮어쓰기 plate 에 줄을 하나 더한다.
  `브랜드가 적립 사용 안 함이라, 개별 적립률이 지워진 {M}곳도 적립이 멈춰요`
  브랜드가 꺼진 상태에서 개별 적립률이 있던 매장은 계속 적립하고 있었는데(R06), 그 숫자가 지워지면 브랜드의 `사용 안 함` 을 따르게 되기 때문이다. 이 줄은 사실이므로 경고 plate 안에 둔다(`warning`).
  보존 모드에서 브랜드가 꺼져 있으면 정보 줄 하나: `이 브랜드는 지금 적립 사용 안 함이에요. 새 값을 적용해도 다시 켜기 전에는 적립되지 않아요`.

### 완료 — 결과 카드 (**사후 확정 수치는 여기에만**)

```
 ┌ 결과 카드 ───────────────────────────────┐
 │ ✓ 적용을 마쳤어요                      [×]  │
 │ 새 적립률 5%                               │
 │ 적용된 매장 12곳 · 초기화된 개별 설정 3곳     │  13 body
 │ ⓘ 적립 사용 안 함 3곳은 적립이 시작되지 않았어요 │  13 body (K>0 일 때만)
 │ [ 이력 보기 › ]                            │
 └──────────────────────────────────────────┘
```

- K 는 **서버가 돌려준 `disabledUntouchedCount`** (일괄 적용 후에도 적립되지 않는 매장 수). 클라이언트 미리보기가 아니다. 문구: `적립 사용 안 함 {K}곳은 적립이 시작되지 않았어요`. K=0 이면 줄 없음.
- 미리보기와 서버 수가 다르면 서버 값만 쓴다 (기존 규칙). 다이얼로그의 "실제 수는 완료 후 알려드려요" 가 이 약속이다.
- 카드의 `새 적립률` 줄에서 `새 설정 적립 안 함 (0%)` 변형은 **삭제**. 남는 것은 `새 적립률 {rate}%` / `새 설정 상위 설정 따르기`.
- 보존 모드: `적용된 매장 {n}곳 · 개별 설정 {M}곳은 그대로예요` 아래에 같은 K 줄.
- partial 배너·실행 중 덮개·실패 SnackBar 는 변경 없음.

## 18-6. ④ 점주·브랜드 읽기 행 — 스위치 꺼짐 표기 (**읽기 전용, 쓰기는 admin 전담**)

모든 variant 에서 **편집 어피던스 0** 원칙(§8 서두) 그대로. 스위치(`Switch` 위젯)를 읽기 행에 **그리지 않는다** — 그리면 조작할 수 있어 보인다. 상태는 텍스트와 아이콘으로만.

| variant | 꺼짐 표기 |
|---|---|
| `block` (`my_store_page`) | 라벨 `Qoin 적립률` → 값 **`적립 사용 안 함`** (20/w800 `textHeading`, 앞에 pause 아이콘 18 `warning`) + 배지 `매장에서 중단` / `브랜드에서 중단`. 출처 문장 아래 표. 안내 `변경이 필요하면 관리자에게 문의해 주세요` 유지. **`다시 켜면 …` 고지는 두지 않는다** (점주가 바꿀 수 없는 정보이고, 관리자 판단 영역) |
| `summary` (`brand_info_page`) | 값 **`적립 사용 안 함`** 18/w800 + 배지. 출처 문장 아래 표 |
| `tile` (`brand_stores_page` 가맹점 타일) | `Qoin` + **`사용 안 함`** 15/w800 (pause 아이콘 13 `warning`) + 배지 `매장에서 중단` / `브랜드에서 중단`. 이력 링크 위치 그대로 |

출처 문장 (§8-b 표의 `적립 안 함` 두 줄을 **교체**):

| 상태 | 점주 (`block`) | 브랜드 (`summary`) |
|---|---|---|
| 매장 스위치 꺼짐 | `이 매장은 Qoin 을 적립하지 않아요` | — |
| 브랜드 스위치 꺼짐 | `브랜드 설정에 따라 이 매장은 Qoin 을 적립하지 않아요` | `이 브랜드는 기본으로 Qoin 을 적립하지 않아요. 적립률을 따로 정한 매장은 계속 적립해요` |

- 브랜드 `summary` 의 두 번째 문장은 R06 의 사실이다 (매장 개별 적립률은 브랜드 스위치를 이긴다). 항상 노출하는 우선순위 안내와 겹치지 않도록, 꺼짐일 때는 위 문장이 우선순위 안내의 `매장이 따로 설정한 적립률이 있으면 그 값이 우선해요` 를 **대신**한다 (가맹점 목록 안내 문장은 유지).
- 꺼짐인데 개별 적립률이 있는 매장(R04b, 매장 스위치 꺼짐)에서 점주 `block` 은 개별 적립률 숫자를 **보이지 않는다.** 값이 `적립 사용 안 함` 이라는 것만 말한다 (숫자를 보이면 "5% 인데 왜 안 되지" 가 생긴다).
- 전체 중단 plate(`현재 전체 적립이 중단되어 있어요`)는 그대로 병기 가능하다 (두 plate 가 서로 다른 사실).
- 로딩/에러 상태는 §8-e 그대로 (`적립 사용 안 함` 을 로딩 중에 그리지 않는다 — `0%` 금지 규칙의 계승. 스위치도 3개 소스가 준비된 뒤에만 판정).
- 접근성: 점주 `Qoin 적립률 적립 사용 안 함, 매장에서 중단. 이 매장은 Qoin 을 적립하지 않아요. 변경이 필요하면 관리자에게 문의해 주세요`. 값 영역은 `button: false` 유지.

### (d) 이력 값 라벨·필드 이름 정리

- 전역 비상 정지는 `field: 'globalEnabled'` (기존 `'enabled'` 의 개명). 표기는 이전과 같다(`적립 중 → 적립 중단됨`, 범위 아이콘 `power_settings_new_rounded`). 판독 측은 `'enabled'` 도 같은 것으로 읽는다(spec §20.1.2).
- `source` 값 `app_direct` / `migration` / `callable` / `direct` 의 변경자 표기: `direct`(Console) = `변경자 알 수 없음 (직접 수정)`, `app_direct` = 변경자 정상 표기 (spec §19.3).
- 값 라벨 `0 → 적립 안 함` **삭제**. 만약 미지의 숫자 0 이 이력에 있으면 `알 수 없는 값` 으로 폴백한다(미지값 관대 처리). 조사 규칙 추가: `사용 안 함` → `으로`, `사용` → `으로` (`사용에서 사용 안 함으로`, `사용 안 함에서 사용으로`), `확인 필요` → `로`.
- 이력 필터 칩에 스위치 전용 칩은 **두지 않는다** (칩 5개 유지). `전역/브랜드/매장` 범위 칩으로 충분하고 칩이 늘면 가로 스크롤이 길어진다.
- Empty/Loading/Error 는 §9-b/§9-c 그대로.

## 18-8. ⑥ 허브 — partial 배너와 `최근 변경` 의 에러 상태 (**조용히 생략 금지**)

### 결함 판정 (test_report H-3 수용)

현행은 에러·로딩에서 배너를 그리지 않는다. 그러면 **"중단 없음" 과 "알 수 없음" 이 화면상 같다.** 이 배너는 중단된 일괄 적용을 알리는 **유일한 상시 표면**이므로 안전 측 실패가 아니다. 기존 §4 표의 `조용히 생략`, §14-13 `허브 부제/배너 실패는 조용히 생략` 을 **폐기**한다.

### partial 배너 3상태 + 데이터 상태

데이터 출처는 `brands` 스트림의 `qoinBulkStatus` 포인터(spec §19.5 D-1, `qoinAdminBrandsProvider`). 판정: `partial`, 또는 `in_progress` 이면서 `qoinBulkAt` 이 기준 시간(5분 상수)보다 오래된 건.

| 상태 | 표시 | 비고 |
|---|---|---|
| **Loading** | 배너 자리에 skeleton 1개 (높이 56, radius 14, `border` 정적 박스). **배너를 그리지도, "없음" 으로 읽히게 비우지도 않는다** | 스트림은 브랜드 목록과 공유라 대개 즉시 끝난다. skeleton 이 깜빡이는 시간이 곧 "아직 모름" |
| **Error** | 에러 배너 (아래) | |
| **없음** (스트림 정상 + 미완료 0건) | **아무것도 그리지 않는다.** 이 상태가 "중단 없음" 이다 | 로딩·에러가 각자 보이는 모양을 가지므로, 비어 있음 = 확인된 없음 으로 읽힌다. 별도 안심 문구는 두지 않는다 (정상 상태에 노이즈를 더하지 않음) |
| 데이터 (1건 이상) | 기존 허브형 배너 (§6-d) | 탭 동작은 아래 |

**에러 배너**

```
 ┌ error 틴트 plate ───────────────────────┐
 │ ⓘ 일괄 적용 상태를 확인하지 못했어요          │  14/w700 body
 │ 끝나지 않은 일괄 적용이 있는지 알 수 없어요.    │  12 muted
 │ 브랜드별 적립률에서 직접 확인해주세요          │
 │                         [ 다시 시도 ]        │  12/w600 primary, 높이 44
 └─────────────────────────────────────┘
```

- 틴트 `error` alpha 0.10, 아이콘 `Icons.error_outline_rounded` 18 `error`, **글자 `textBody`/`textMuted`**. warning 이 아니라 error 인 이유: partial 배너(warning)는 "알려진 운영 상태" 이고 이것은 **관측 실패**(데이터가 깨졌을 때의 error 용법과 같음, 색상 표의 `설정 확인 필요` 선례).
- `다시 시도` 는 provider 를 invalidate 한다. 두 번 눌러도 중복 호출이 생기지 않게 진행 중에는 버튼 안 인디케이터.
- 배너가 허브 최상단(전역 카드 위) 위치에 그려지므로 **에러를 못 볼 수 없다.**
- `permission-denied` 도 같은 배너 (admin 허브라 드물다). 인덱스 오류 문자열은 노출하지 않는다(기존 규칙).

**데이터 배너의 탭 동작 변경**: 기존은 이력 화면 `미완료` 필터였다. 포인터 기반 판정에서는 이력 쿼리(인덱스 의존)를 거치지 않는 편이 맞다.
- 1건: 해당 **브랜드 편집 화면**으로 이동 (거기에 `이어서 적용` 이 있는 `QoinPartialBanner` 가 있다).
- 2건 이상: **브랜드별 적립률 목록**으로 이동 (행의 `적용 중단됨` 태그로 찾는다).
- 배너 본문(`브랜드 "{이름}"` / `브랜드 "{이름}" 외 {n}건`)과 제목은 기존 그대로. 이력 화면의 `미완료 적용` 필터 칩은 유지(이력 쪽 진입은 타일 탭).

### `변경 이력` 타일의 부제 (`최근 변경`) 3상태 + 데이터

| 상태 | 부제 | 비고 |
|---|---|---|
| **Loading** | skeleton 바 120x12 (`border` 정적 박스) | |
| **Error** | **`이력을 불러오지 못했어요`** 12/w600/`error` + 앞에 `Icons.error_outline_rounded` 12 `error`. 우측 chevron 자리에 텍스트 버튼 **`다시 시도`** (12/w600 `primary`, 터치 영역 최소 44x44) | 행의 나머지를 탭하면 이력 화면이 열리고, 거기서 자체 에러 UI(`QoinLoadError`)를 본다. 즉 **두 진입점 모두 에러를 말한다** |
| **없음** | `변경 이력이 없어요` | 에러와 글자·색이 달라 구분된다 |
| 데이터 | `최근 변경 10월 22일 14:35` | |

- 위 에러 부제의 `다시 시도` 버튼은 행 탭(내비게이션)과 별도 `InkWell` 이어야 한다 (버튼을 눌러도 이력 화면이 열리지 않음).
- 타일 3개 중 **브랜드·매장 부제**는 기존대로 에러 시 생략한다. 이 둘은 개수 안내(편의 정보)이고, 그 값이 없다고 해서 중단·장애를 숨기지 않는다. 판단 기준: *생략했을 때 사용자가 안전하다고 오해할 수 있는가.* partial 배너·최근 변경 에러는 그렇다(그래서 보이고), 개수 부제는 아니다(그래서 생략).
- 상태 요약 표(§11)의 허브 행은 **전역·비상 정지 / partial 배너 / 최근 변경** 3영역 독립 상태로 갱신한다.

## 18-9. ⑦ (임시) 마이그레이션 카드 — `AdminQoinMigrationCard`

> **이 UI 는 임시다. 마이그레이션 0건 확인 후 정리 커밋(spec §20.4.5)에서 파일째 삭제된다.** 정리 비용을 0 에 가깝게 하려고 최소 구성으로 둔다. 카드의 어떤 요소도 다른 화면에 의존·노출되지 않는다.

### 배치와 격리

- 허브 **맨 위**(partial 배너 위)에 카드 1장. 1회성 작업이 앞에 있어야 놓치지 않는다. 정리 후에는 자리가 사라지고 아래 요소가 그대로 올라온다(레이아웃 의존 없음).
- 구현은 **한 파일** `admin/qoin/widgets/admin_qoin_migration_card.dart` + 허브의 마운트 한 줄. 상태·provider·UseCase 호출도 그 파일 안에 둔다(공용 위젯에서 재사용하지 않는다). 정리 커밋 = 파일 삭제 + 마운트 한 줄 삭제 + repository 메서드 `migrateZeroRates` 삭제.
- 카드 우측 상단에 알약 `임시` (높이 20, `textMuted` alpha 0.12, 11/w600/`textBody`). 이 카드가 영구 기능이 아님을 admin 에게도 알린다.
- 규격: `surfaceElevated` + `border`, radius 16, padding 16, 허브 다른 카드와 gap 20. 제목 15/w700 `textHeading`: **`Qoin 설정 이전`**.

**실행 확인 다이얼로그** (`QoinDialogShell`)

| 요소 | 내용 |
|---|---|
| 제목 18/w800 | `Qoin 설정을 이전할까요?` |

| 본문 13 | `곳마다 변경 이력이 남아요` |
| 보조 12 muted | `방금 확인한 목록 기준이에요. 그사이 바뀐 곳은 건너뛰어요` (서버가 실행 시점에 다시 센다) |
| 버튼 | `취소` / `이전 실행` (primary 채움. 체크박스 없음 — 의도가 명확한 1회성이고 멱등) |

**결과**

```
 ┌ 결과 (primaryBright 0.10 틴트 + 테두리 0.30) ┐
 │ ✓ 이전을 마쳤어요                                │  14/w700
 │ 옮긴 곳 4곳                                      │  13 body  (= migrated)
 │ 건너뛴 곳 0곳                                    │  13 body  (= skipped; 이미 이전됨)

 └──────────────────────────────────────┘
```

- `건너뛴 곳` 이 0 보다 크면 12 muted 한 줄: `이미 옮겨진 곳은 건너뛰어요` (멱등 설명). 0 이면 이 줄과 `건너뛴 곳` 줄 모두 숨김.
- 마지막 안내 12 muted (항상): `‘다시 확인’ 에서 대상이 없다고 나오면 이 카드는 이후 업데이트에서 사라져요`.
- `옮긴 곳` 이 dry-run 대상 수와 다르면(`migrated + skipped ≠ 확인한 수`) 숫자 아래에 `확인했던 수와 달라요. 다시 확인해 주세요` (12/w600 warning 틴트 plate 없이 글자만 `textBody`) 를 붙인다.

### 접근성·상태 요약

- 인디케이터 상태는 `Semantics(liveRegion: true)` 로 낭독. 결과는 `Semantics(label: 이전을 마쳤어요, 옮긴 곳 4곳, 건너뛴 곳 0곳)`.
- loading/error/empty 매핑: loading = 확인 중·실행 중, error = 확인 실패·실행 실패, empty = 대상 0건.

## 18-13. 개발자 전달 특이사항 (§14 의 증분)

1. **스위치는 폼 저장 버튼에 묶이지 않는다.** 폼 초안(입력 중인 숫자·사유·라디오)은 스위치 조작·결과로 초기화·저장되지 않는다. 서버 스트림이 스위치 값을 바꿔도 초안은 덮어쓰지 않는다 (1차 규칙 계승).
2. **`QoinReenableHint` 는 해석을 한 번 더 돌려서 만든다.** "스위치를 켠다고 가정한 해석 결과" 가 필요하다 — `QoinPolicy.resolveEffectiveRate` 에 `storeSwitch: enabled` 로 치환한 입력을 다시 넣는다 (진리표의 R04b/R24 를 그대로 재사용 가능). 사슬과 켜기 다이얼로그가 **같은 함수의 같은 결과**를 써야 한다. 문장을 사슬과 다이얼로그가 각자 조립하지 않는다.
3. **R06 (매장 개별 숫자 > 브랜드 스위치)와 R24 (매장 스위치 > 브랜드 스위치) 가 화면에 영향을 준다.** 브랜드 끄기 다이얼로그의 `계속 적립돼요 {M}곳`, 브랜드 덮어쓰기 plate 의 `적립이 멈춰요 {M}곳`, 사슬 `(가려짐)` 이 모두 이 규칙에서 나온다. M 은 클라이언트가 `watchStoresByBrand` 로 센 미리보기다.
4. **0 입력**: `QoinPolicy.validateRateInput` 에 `zero` status 를 추가하고(파싱값 == 0), 에러 카피는 `qoin_rate_input_field.dart` 한 곳. `0.03` 은 계속 `tooLow`. 스위치 카드 키를 `GlobalKey` 로 받아 `적립 사용 끄러 가기` 가 `Scrollable.ensureVisible` 한다 (필드 위젯이 페이지의 스크롤 컨텍스트에 의존하지 않게 콜백 파라미터로 받는다). 전역 폼은 콜백이 null → 링크 없음.
5. **3상태 렌더(허브)**: partial 배너와 최근 변경 부제는 `AsyncValue.when(loading, error, data)` 를 **셋 다 구현**한다. `asData?.value == null → SizedBox.shrink()` 패턴 금지 (tester 가 grep 대상으로 삼을 것).
6. **마이그레이션 카드는 한 파일**에 격리하고 허브 마운트 한 줄만 둔다. 공용 위젯·공용 provider 를 만들지 않는다. 정리 커밋 삭제 대상: 이 파일, 마운트 한 줄, repository/datasource 의 `migrateZeroRates`, 관련 UseCase.
7. **일괄 정보 줄·체크박스**: `QoinRateConfirmDialog` 에서 체크박스 상태·`_acknowledged` 류 변수와 `Z`(overriddenStopped) 계산을 삭제한다. K(`disabledUntouched` 미리보기)는 `watchStoresByBrand` 의 `qoinAccrualEnabled == false` 수.
8. **배지 상태**: `QoinRateSourceBadge` 의 `disabled` 는 `source` 에 따라 라벨 2종(`매장에서 중단` / `브랜드에서 중단`). 값 칸(`사용 안 함`)은 배지가 아니라 값 라벨 유틸이 그린다.
9. **읽기 행 3곳**: 스위치를 이미 `StoreEntity`/`BrandEntity` 의 읽기 전용 필드로 받아 해석에 넣는다. 읽기 행에 `Switch` 위젯 금지.
10. **이력**: `bulkHistoryId` 가 없는 `clearByBulk` 행은 링크만 숨긴다. 모르는 `field`/`source`/`op` 값은 한 줄 폴백(`알 수 없는 변경`)으로 렌더하고 앱이 죽지 않게 한다.
11. 색은 전부 `AppColors` 토큰. 신규 토큰 0개. `Color(0x…)` 0건.

## 18-14. 완료 기준 — 갱신 (§16 의 해당 항목을 대체)

- [ ] `적립 사용` 스위치가 적립률 폼의 **저장 버튼 아래 독립 카드**이고 `적립률` / `적립 사용` 섹션 라벨이 따로 있다
- [ ] 스위치를 꺼도 **적립률 입력란은 비활성화되지 않는다.** 꺼짐 안내 plate 가 있다
- [ ] 적립률에 `0` 을 입력하면 **스위치로 안내하는 문구 + `적립 사용 끄러 가기`** 가 나오고 저장은 비활성이다. `0.03` 은 여전히 `tooLow` 다
- [ ] 사슬에서 꺼진 줄이 `5%` 가 아니라 `사용 안 함` 이고, R24 대로 매장이 이긴다
- [ ] 꺼진 매장·브랜드에 `다시 켜면 … 가 적용돼요` 가 사슬과 켜기 다이얼로그에서 **글자 그대로 같다**. 브랜드가 꺼져 있으면 `다시 켜도 …적립되지 않아요` 로 달라진다
- [ ] 일괄 적용 다이얼로그에 **경고 줄(Z)과 체크박스가 없고**, 정보 줄이 있다. 확정 수치 K 는 완료 카드에만 있다
- [ ] 점주·브랜드 읽기 행이 `적립 사용 안 함` 으로 표기되고 `Switch`·chevron·`수정` 이 없다
- [ ] 이력에 `적립 사용 여부` / `이전` / `일괄 적용으로 초기화` 행이 렌더되고 매장 이력의 `clearByBulk` 에서 브랜드 이력으로 연결된다
- [ ] 허브 partial 배너와 `최근 변경` 이 **로딩 / 에러 / 없음** 을 서로 다르게 그린다 (`SizedBox.shrink()` 로 에러를 삼키는 코드 0건)
- [ ] 마이그레이션 카드가 dry-run → 실행 → 결과 순서이고, 실행 실패 후 곧바로 재실행이 불가능하며(dry-run 으로 복귀), 한 파일에 격리돼 있다
- [ ] 삭제 목록(§18-12)의 문자열이 `lib/` 에 0건 (grep)
- [ ] `Color(0x…)` 0건, 신규 토큰 0개, 텍스트 1.5x 에서 겹침·잘림 없음
