## 핵심 디자인 결정

| # | 결정 | 사유 |
|---|---|---|
| 1 | 검색 화면은 **한 개의 세로 스크롤 목록**에 `매장` 섹션 → `메뉴` 섹션을 이어 붙인다. 탭/세그먼트로 나누지 않는다 | spec 이 "섹션 분리"를 확정했고, 탭으로 나누면 한쪽이 로딩/실패일 때 사용자가 다른 탭을 못 본다. 한 목록이면 **매장이 먼저 보이고 메뉴가 뒤따라 붙는다** — 매장 즉시·메뉴 지연이라는 데이터 성질과 화면 순서가 일치한다 |
| 2 | **중간 상태(매장 완료 / 메뉴 로딩)를 정상 상태로 설계**한다. 메뉴 섹션 헤더는 먼저 그리되 **건수 없이** `메뉴` + 작은 인디케이터 + `메뉴를 찾고 있어요`, 아래에 skeleton 2행 | 가장 흔한 상태다(spec §2.2: 매장은 즉시, 메뉴는 첫 시도에서 0.3~1.5초). `메뉴 (0)` 이나 빈 상태를 먼저 보이면 "없다" 로 오독한다 |
| 3 | 메뉴 결과 행에 **가격 자리를 만들지 않는다.** 대신 `메뉴명 / 매장명 · 거리 / 카테고리 태그` 로 채운다 | spec §2.1 (override 미반영 가격 오표시 방지). 빈 자리를 두면 구현이 채운다 — 행 레이아웃 자체에 가격이 들어갈 칸이 없게 한다 |
| 4 | 메뉴 행의 **카테고리 태그** + 탭하면 **그 카테고리 탭이 선택된 매장 메뉴 화면**으로 간다 (D3-a) | "내가 찾은 메뉴" 가 어느 탭에 있는지를 **이동 전에** 알려 준다 (§메뉴 결과 → 매장 화면 참조) |
| 5 | 한쪽이 0건이면 **섹션 헤더·목록은 숨기되**, 그 자리에 **한 줄 안내**(`'{질의}' 와 일치하는 메뉴가 없어요`)를 둔다 | spec §3.2(헤더 숨김)와 §3.5(빈 문구)를 둘 다 만족한다. 한 줄 안내가 없으면 "메뉴는 안 찾았나?" 하는 의문이 생긴다 |
| 6 | 메뉴 **부분 실패**는 결과 행을 유지한 채 섹션 하단에 `일부 매장의 메뉴를 불러오지 못했어요` + `다시 시도`. 결과가 0건이어도 이 줄은 남긴다 | 0건 + 부분 실패를 "확정적 없음" 으로 읽히지 않게 한다 (R2 ⓑ) |
| 7 | 메뉴 인덱스 전체 실패는 **메뉴 섹션만** 에러. 매장 섹션은 건드리지 않는다 | spec §11 · 사용자 요구 |
| 8 | 최근 검색어는 **질의가 비었을 때** 보인다. 기록 시점은 **키보드 `검색` 제출 또는 결과 탭**이다 (타이핑 중 debounce 값은 기록하지 않는다) | spec 은 시점을 정하지 않았다. 매 debounce 마다 기록하면 `아`, `아이`, `아이스` 가 모두 쌓인다 |
| 9 | 홈 `맞춤 추천` 은 5건 + 헤더 전체 건수 유지 + **하단 `N곳 더 보기` 버튼**을 추가해 더보기 동기를 만든다 | 헤더 우측 `전체보기` 텍스트 버튼만으로는 스크롤 끝에서 눈에 띄지 않는다. 5건이 끝나는 자리에서 바로 다음 행동을 준다 |
| 10 | 매장 카드(`RecommendedStoreCard`)는 **재사용**하고 `subtitle`(nullable) 한 칸만 추가한다 | 검색 맥락에서 "왜 이 매장이 걸렸나" 가 주소 매칭일 때만 필요하다 (§검색 결과의 매장 카드) |
| 11 | 텍스트 **하이라이트(매칭 글자 강조)는 하지 않는다** | 매칭이 공백 무시·소문자화 정규화 위에서 일어나 원문 글자 위치로 되돌리는 매핑이 오차를 낸다. 틀리게 강조하느니 하지 않는다 |
| 12 | 새 색상 토큰 없음 | 아래 색상 사용 |

# 1. 표면 인벤토리 (R2)

> 규칙: 한 사실 = 한 행, 그 사실을 말하는 **모든 화면을 전수 열거**. ⓑ(출처 읽기 실패 시 보이는 것)가 빈 칸이면 미설계. 새 화면이 같은 사실을 말하면 행을 추가한다.

## 1-a. 사실 F1 — 매장 목록(검색 결과 · 추천 · 미리보기)

판정 출처는 **`storeSnapshotProvider` 하나**다 (spec §9.3). 아래 모든 표면이 이 한 스냅샷의 파생이다.

| # | 표면 | ⓐ 판정 출처 | ⓑ 출처 읽기 실패 시 사용자에게 보이는 것 | ⓒ 복구 동작 |
|---|---|---|---|---|
| F1-1 | `SearchPage` 매장 섹션 | `searchStoreResultsProvider` ← 스냅샷 | **검색 영역 전체**가 에러 블록(`매장 정보를 불러올 수 없어요`)으로 대체된다. 메뉴 섹션도 같은 스냅샷에서 후보를 뽑으므로 **함께 숨긴다**(메뉴만 따로 "없음" 으로 읽히는 상태를 만들지 않는다). 입력창·최근 검색어는 유지 | `다시 시도` → `storeSnapshotProvider` invalidate |
| F1-2 | 홈 `맞춤 추천` 미리보기 | `recommendedStoresPreviewProvider` ← 스냅샷 | 섹션 에러 UI(기존). **헤더에 건수를 그리지 않는다**(`맞춤 추천` 만) | `다시 시도` → 같은 invalidate |
| F1-3 | `RecommendedStoresPage` 목록 | `recommendedStoresFullProvider` ← 스냅샷 | 목록 자리 에러 블록. 카테고리 칩·정렬 토글은 **유지**(스냅샷과 무관한 UI 상태). 건수 줄은 숨김 | `다시 시도` |
| F1-4 | 홈 `맞춤 추천` 헤더 건수 `(n)` | `recommendedStoresFullProvider.length` | **그리지 않는다** (`0` 으로 말하지 않는다). 로딩 중에도 동일 | 섹션 `다시 시도` |
| F1-5 | 홈 `전체보기` / 하단 `N곳 더 보기` 노출 | 같은 provider `length > recommendedPreviewCount` | 데이터가 없는 동안(로딩·에러)은 **숨김** — "5곳 이하라서 숨김" 과 "모름" 이 겹치지만 어느 쪽이든 누를 수 있는 목적지가 없다. 에러 UI 의 `다시 시도` 가 복구를 맡는다 | — |
| F1-6 | `RecommendedStoresPage` 건수 줄 `전체 n곳` | 같은 provider | 숨김 (로딩 skeleton 으로 대체) | F1-3 |

- 건수와 `전체보기` 노출은 **같은 provider 의 `length` 한 곳**에서 만든다 (R1). 화면이 리스트를 직접 세어 따로 판정하지 않는다.

## 1-b. 사실 F2 — 메뉴 검색 결과 / 메뉴 인덱스 상태

판정 출처는 **`menuSearchIndexProvider`(세션 keepAlive)** 하나. 상태는 `gated`(질의 <2글자) · `loading` · `error`(전체 실패) · `partial`(일부 출처 실패 + 일부 성공) · `data`.

| # | 표면 | ⓐ 판정 출처 | ⓑ 출처 읽기 실패 시 사용자에게 보이는 것 | ⓒ 복구 동작 |
|---|---|---|---|---|
| F2-1 | `SearchPage` 메뉴 섹션 (결과 행) | `menuSearchResultsProvider` ← 인덱스 + 질의 | 전체 실패: 메뉴 섹션이 **인라인 에러 카드**(`메뉴를 불러오지 못했어요`)로 대체되고 **매장 섹션은 그대로**. 부분 실패: 결과 행 유지 + 하단 `일부 매장의 메뉴를 불러오지 못했어요` | `다시 시도` → 메뉴 인덱스만 invalidate (스냅샷 아님) |
| F2-2 | `SearchPage` 메뉴 섹션 헤더 건수 `메뉴 (n)` | 같은 결과 길이 | **그리지 않는다** (로딩 중: 인디케이터 + `메뉴를 찾고 있어요`, 에러: 헤더만 `메뉴`). `메뉴 (0)` 으로 말하지 않는다 | F2-1 |
| F2-3 | 통합 빈 상태 `'{q}' 와 일치하는 매장이나 메뉴가 없어요` | **하나의 판정 함수** `resolveSearchView(storeAsync, menuAsync, normalizedQuery)` | 메뉴가 `loading`/`error` 이면 통합 빈 상태를 **절대 그리지 않는다** (매장 0건 + 메뉴 미확정 = 아직 모름). 메뉴가 `partial` 이면 통합 빈 상태 아래에 부분 실패 줄을 덧붙인다 | F2-1 |
| F2-4 | 1글자 질의의 메뉴 자리 안내 | 질의 길이 (`gated`) | 해당 없음 (읽기 없음) — 안내문이 곧 상태 | 한 글자 더 입력 |
| F2-5 | 섹션 하단 범위 안내 `가까운 매장 30곳의 메뉴에서 찾았어요` | 상수 `menuSearchStoreLimit` / `searchRadiusKm` | 에러·로딩에서는 **그리지 않는다** (찾지 못한 상태에서 "찾았어요" 금지) | — |
| F2-6 | 메뉴 행 → 매장 메뉴 화면 이동 후 | `StoreMenuPage` 자체 로딩/에러 (기존) | 기존 매장 메뉴 화면의 에러·빈 상태 (`_ErrorView`, `_EmptyView`). 검색 쪽에서 특별히 다루지 않는다 | 기존 `다시 시도` |

## 1-c. 사실 F3 — 최근 검색어

| # | 표면 | ⓐ 판정 출처 | ⓑ 출처 읽기 실패 시 | ⓒ 복구 |
|---|---|---|---|---|
| F3-1 | `SearchPage` 질의 0글자 영역 | `recentSearchesProvider` (**세션 메모리**) | **읽기 실패가 존재하지 않는다**(네트워크·디스크 없음). 비어 있으면 안내 문구만 | — |

## 1-d. 사실 F4 — 거리 기준 (위치)

| # | 표면 | ⓐ 판정 출처 | ⓑ 위치 확정 실패/거부 시 | ⓒ 복구 |
|---|---|---|---|---|
| F4-1 | 모든 매장 카드·메뉴 행의 거리 | 스냅샷의 `distanceKm` | 위치 거부 → 폴백(서울 시청) 기준 거리. 홈의 기존 SnackBar 안내가 이미 있다 (spec §3.5). `distanceKm == null` 이면 `-` (기존 카드 규칙). 검색 화면에 별도 안내를 더하지 않는다 | 홈의 위치 권한 흐름 |
| F4-2 | 위치 미확정(pre-permission 다이얼로그 전) | `userLocationProvider` 로딩 | 스냅샷이 위치를 기다린다 → F1 의 **로딩** 상태와 동일 (skeleton). 홈이 먼저 위치를 확정시키므로 검색 화면에서 이 상태가 길게 보이는 경로는 드물다 | — |

## 1-e. 사실 F5 — 이 매장이 이 메뉴를 파는가 (검증에서 추가, tester 지적)

같은 사실을 **검색 결과 행 · 매장 화면 목록 존재 · 안내 띠 · 품절 배지**가 각자 말한다. 판정이 갈리면 "검색에 걸렸는데 매장이 빈 화면", "팔고 있는데 판매하지 않는다는 띠" 가 생긴다. 판정은 **한 함수**(`isMenuShownOnStoreScreen` — `visible` + 활성 메인 카테고리)로 모은다.

| # | 표면 | ⓐ 판정 출처 | ⓑ 출처 읽기 실패/미확정 시 보이는 것 | ⓒ 복구 |
|---|---|---|---|---|
| F5-1 | 검색 결과 행 존재 | `menuSearchResultsProvider` — 인덱스 행 중 `isMenuShownOnStoreScreen` 통과분 | 활성 카테고리를 모르는 동안은 **행을 그리지 않고 로딩**(나중에 사라질 행을 먼저 보이지 않는다). 카테고리 목록 실패 시 메뉴 섹션 에러 | 메뉴 `다시 시도`(인덱스 + 활성 카테고리 둘 다 invalidate) |
| F5-2 | 매장 메뉴 화면 목록 | `filteredMenuItemsProvider` — 같은 함수. 폴백 판정(`effectiveMain`)도 **보이는 메뉴의 카테고리만** 후보 | 활성 카테고리 미도달이면 목록 보류(기존) | 기존 |
| F5-3 | `검색한 메뉴 / 판매하지 않는 메뉴일 수 있어요` 띠 | **머지 목록 전체**(`allItems`)에서 같은 함수로 id 를 찾는다. 카테고리 탭·서브카테고리 필터와 무관 | 활성 카테고리 미도달이면 **띠를 그리지 않는다**(모르면 말하지 않는다) | 닫기 `×` |
| F5-4 | 카드 품절 배지 (L5) | `MenuItemCard.soldOut` (기존, 변경 없음) | 해당 없음 | — |

- 띠가 알리는 것은 **L2(머지 목록에 없음)만**이다. 품절(L5)은 F5-4 의 카드 배지가 알린다.
- 범위 안내(F2-5)는 고정 숫자가 아니라 **인덱스가 실제로 찾아본 매장 수**를 말한다 (`가까운 매장 {n}곳(10km 이내)의 메뉴에서 찾았어요`, 0곳이면 `10km 이내에 메뉴를 찾아볼 매장이 없어요`). 둘째 줄은 L1 을 한 구절로 포함한다: `가격, 판매 여부, 매장 한정 메뉴는 매장 화면에서 확인해 주세요`.

## 3-c. 질의 상태별 본문 (view-model)

모든 상태는 **하나의 판정 함수** `resolveSearchView(storeAsync, menuAsync, normalizedQuery)` 가 enum 으로 결정하고 위젯은 렌더만 한다 (R1). 정규화 후 길이 기준.

### 질의 0글자 (초기 · 공백뿐 포함)

```
 최근 검색어                                  전체 삭제
 앱을 닫으면 지워져요                                      ← 11 muted (§3-g)
 ┌──────────────────────────────────────┐
 │ 🕘  아이스 아메리카노                      ×   │  48h
 │ 🕘  강남                                  ×   │
 └──────────────────────────────────────┘

   두 글자 이상 입력하면 메뉴도 찾아요         ← 13 muted
```

- 최근 검색어가 **있으면**: 위 목록 + 그 아래에도 안내 문구(작게)를 두지 않는다 (목록이 주인공). 안내 `매장 이름, 주소, 메뉴로 찾아보세요` 는 **목록이 비었을 때만** 중앙 안내로 쓴다. 목록이 있을 때는 입력창 힌트가 같은 역할을 한다.
- 헤더 행: `최근 검색어` 15/w700/`textHeading` 좌, 우측 `전체 삭제` 13/w600/`info`(터치 44 높이). `전체 삭제` 는 **확인 없이** 즉시 비운다 (복구 비용이 0 에 가깝다).
- 항목 행: 높이 48. 좌 `Icons.history_rounded` 18 `textMuted`, 텍스트 14/w500/`textBody`(1줄 말줄임), 우 `×` `Icons.close_rounded` 18 `textMuted`(터치 44x44). 행 탭 → 입력창에 채우고 재검색(키보드 유지), 맨 앞으로 끌어올림. 행 배경 없음, 항목 사이 헤어라인 없음(간격 0, 행 높이로 구분).
- 항목 `×` 탭 → 해당 항목만 삭제. 최대 10건(상수 `recentSearchLimit`), 같은 질의는 중복 없이 맨 앞.
- 로딩/에러 상태 없음 (§1-c).

### 3-d. ★ 중간 상태 — 매장 완료 / 메뉴 로딩

가장 흔한 상태이므로 상세 규격을 둔다.

```
 매장 (3)                                       ← SectionTitle (18/w700) 건수 확정
 ┌ RecommendedStoreCard ──────────────┐
 ├ RecommendedStoreCard ──────────────┤
 └ RecommendedStoreCard ──────────────┘
                                                   gap 24
 메뉴      ◌ 메뉴를 찾고 있어요                  ← 헤더 행: 제목 18/w700 + 인디케이터 14 + 12 muted 문구
 ┌ shimmer 행 72h ────────────────────┐
 └ shimmer 행 72h ────────────────────┘
```

| 요소 | 규격 |
|---|---|
| 매장 섹션 | 완전한 최종 상태. **메뉴가 도착해도 위치·높이가 변하지 않는다** (메뉴는 아래에만 붙는다) |
| 메뉴 헤더 | `메뉴` (SectionTitle 규격 18/w700/`textHeading`) 뒤에 gap 10 + `CircularProgressIndicator` 14x14 strokeWidth 1.5 `primary` + gap 6 + `메뉴를 찾고 있어요` 12/w500/`textMuted`. **건수를 쓰지 않는다** |
| 메뉴 skeleton | 2행, 각 높이 72 radius 16, `Shimmer.fromColors(base: surface, highlight: surfaceElevated)` (홈 `_RecommendedLoading` 패턴), 행 간 gap 10 |
| 도착 시 전환 | skeleton → 결과 행 교체. 페이드 150ms. 매장 섹션과 **스크롤 위치는 유지**한다 (사용자가 매장 카드를 보다가 메뉴가 붙어도 화면이 튀지 않는다) |
| 접근성 | `Semantics(liveRegion: true, label: '메뉴를 찾고 있어요')`. 도착하면 `메뉴 {m}개` 한 번 낭독 |
| 질의가 바뀌면 | 매장은 즉시 재필터, 메뉴 인덱스는 **캐시이므로 로딩 없이** 즉시 재필터 (두 번째 질의부터 이 상태는 나타나지 않는다 — 인덱스가 처음 빌드되는 첫 시도에만 보인다) |

### 매장 섹션 규격

- 헤더: `SectionTitle(title: '매장 ({n})')`. `n` = 일치 매장 전체 수.
- 카드: `RecommendedStoreCard` 재사용(§3-g). 카드 간 gap 12. 탭 → `StoreMenuPage(store)` (기존) + 최근 검색어 기록.
- **표시 상한 없음**(스냅샷 ≤100). 이름 매칭이 주소 매칭보다 항상 위(spec §3.2) — 구분 라벨/헤어라인은 넣지 않는다. 주소만 매칭된 카드는 `subtitle` 로 이유를 드러낸다.

### 메뉴 섹션 규격

- 헤더: `SectionTitle(title: '메뉴 ({총 일치 수})')`. 총 일치 수 = 상한 적용 전 건수.
- 행 `MenuSearchResultTile` — §4.
- 행 간 gap 10. **최대 30행**(상수 `menuSearchResultLimit`). 일치가 30 초과면 행 목록 아래:
  `메뉴 {총}개 중 30개만 보여드려요. 검색어를 더 구체적으로 입력해 보세요` (12/w500/`textMuted`, 좌측 정렬).
- 섹션 **맨 아래 고정 안내(F2-5)**: `가까운 매장 {30}곳의 메뉴에서 찾았어요` (12/`textMuted`) + 둘째 줄 `가격과 판매 여부는 매장 화면에서 확인해 주세요` (12/`textMuted`). 숫자는 상수 보간. 결과 행이 1개 이상이거나 `메뉴 0건 한 줄 안내` 일 때 노출한다. 로딩·에러 때는 노출하지 않는다.
  - spec 의 고정 문구는 `가까운 매장 30곳의 메뉴에서 찾았습니다` 이다. 앱 전반 톤(`~해요`)과 맞추려 어미만 `찾았어요` 로 바꿨다. 의미 동일. 원문 유지가 필요하면 알려 달라(§8 N2).
- 부분 실패 줄(상태 7·12): 범위 안내 **위**에 한 줄:

```
 ⚠ 일부 매장의 메뉴를 불러오지 못했어요                 [다시 시도]
```

### 3-e. 통합 빈 상태 (상태 10 · 12)


## 3-g. 검색 결과의 매장 카드 — 재사용 판단

**결론: `RecommendedStoreCard` 를 그대로 재사용하고, 선택 파라미터 `String? subtitle` 한 개만 추가한다** (기본 null = 현행 레이아웃 불변).

- 기존 카드는 높이 96 고정, 이름(14/w700) + 거리(13)를 `spaceBetween` 으로 배치한다. 검색에서 필요한 새 정보는 단 하나 — **주소만 매칭된 매장의 "왜 걸렸나"**.
- `subtitle` 이 있으면 이름과 거리 **사이**에 한 줄: `Icons.location_on_outlined` 없이 텍스트만 12/w500/`textMuted`, 1줄 말줄임 (주소). 세 줄 합계가 카드 내용 영역(96−20=76)에 들어가므로 높이 96 유지.
- **언제 채우나**: 이름이 매칭되지 않고 **주소로만** 매칭된 매장에만 `store.address`. 이름이 매칭된 카드에는 `subtitle` 을 주지 않는다 (현행과 동일 모양).
- `RecommendedStoresPage` 와 홈 미리보기는 `subtitle` 을 쓰지 않는다 (변경 없음).
- 텍스트 1.5x 에서도 이름 1줄·주소 1줄·거리 1줄은 `FittedBox`/말줄임으로 겹치지 않게 한다 (기존 카드 규칙).
- 접근성: 기존 카드에 `subtitle` 이 있을 때 읽기 순서를 `이름, 주소, 거리` 로 한다.

# 4. 메뉴 결과 행 `MenuSearchResultTile` (신규)

## 4-a. 구성 — 가격 자리 없음

> ⚠ **2차 개정(§13-1)**: 가격 **하나**만 해제되고 품절 배지가 추가됐다. 할인·별점·리뷰 수·옵션 최저가는 계속 금지. 이 절의 "가격 자리 없음" 은 이력이다.

```
 ┌───────────────────────────────────────────────┐
 │ ┌────┐  아이스 아메리카노                        ›   │
 │ │ 56 │  Q브루어리 강남점 · 1.2km                     │
 │ └────┘  [커피]                                      │
 └───────────────────────────────────────────────┘
```

| 영역 | 규격 |
|---|---|
| 컨테이너 | `GestureDetector`+`InkWell`. 최소 높이 **72**, 텍스트 스케일에 따라 커짐(고정 높이 금지). 배경 `AppColors.surfaceElevated`, 테두리 `AppColors.border` 1px, radius 16. **그림자 없음**(매장 카드와 구분 — 메뉴 행은 한 단계 가벼운 면). padding `h12 v10` |
| 이미지 | 56x56, radius 12, `CachedNetworkImage` fit cover. URL 없음/실패 → `AppColors.surface` 배경 + `Icons.restaurant_menu_outlined`(없으면 `Icons.local_cafe_outlined`) 24 `textMuted`. 로딩 중 shimmer(`surface`/`surfaceElevated`) |
| 1행 | **메뉴명** 15/w700/`textHeading`, 1줄 말줄임 |
| 2행 | `{매장명} · {거리}` 13/w500/`textBody`, 1줄 말줄임(**매장명이 줄고 거리는 항상 보인다** — `Row[Flexible(매장명), 거리]`). 거리가 null 이면 ` · ` 와 거리를 생략 |
| 3행 | **카테고리 태그**: 높이 20, 가로 padding 8, radius 6, 배경 `AppColors.surface`, 글자 11/w600/`textBody`. 라벨 = `mainCategoryCode` 의 표시명(활성 메인 카테고리 목록 `mainCategoriesActiveProvider` 로 해석). **해석 실패(로딩 전·비활성·미지 코드)면 태그를 그리지 않는다** — 코드 문자열을 그대로 노출하지 않는다 |
| 우측 | `Icons.chevron_right_rounded` 20 `textMuted` |
| **없는 것** | 가격, 할인, 품절 배지, 장바구니/주문 버튼, 별점, 영업 상태. **어떤 숫자도 자리 예약하지 않는다** |

- 한 행 = (메뉴 × 매장). 같은 메뉴가 여러 매장에 있으면 **매장별 행**이므로 2행의 매장명이 행을 구분한다. 같은 매장의 같은 이름 메뉴가 중복되면(출처 중복) 안 생기도록 인덱스에서 dedupe (developer).
- 행 사이 연속 동일 메뉴명이 반복될 때 메뉴명을 숨기는 그룹핑은 하지 않는다 (단순 유지, 거리순 정렬 후 가나다).
- 탭 → §5. 눌림 피드백: 배경 `primary` alpha 0.04 (카드 규격의 인터랙션 톤 유지).

## 4-b. 왜 이 구성인가 (가격 대신 무엇을 보이는가)

사용자가 행에서 알아야 하는 것은 ① **무엇**(메뉴명, 이미지) ② **어디서**(매장·거리) ③ **눌렀을 때 어디로 가는지**(카테고리 태그)다. 가격·판매 여부는 `menuOverrides` 를 읽지 않아 틀릴 수 있으므로 행이 약속하지 않고, 섹션 하단 고정 안내가 "가격과 판매 여부는 매장 화면에서" 라고 말한다. 3행의 카테고리 태그는 이동 후 화면의 **어떤 탭**에 이 메뉴가 있는지를 이동 전에 알려 주는 유일한 요소다.

## 4-c. 접근성

`Semantics(button: true, label: '{메뉴명}, {매장명}, {거리}, {카테고리} 카테고리. 탭하면 매장 메뉴 화면으로 이동', excludeSemantics: true)`. 이미지·chevron 은 `ExcludeSemantics`. 거리 표기는 `DistanceCalculator.formatKm` 결과를 그대로 읽는다. 터치 영역은 행 전체(≥72).

# 5. 메뉴 결과 → 매장 화면: "찾은 메뉴" 를 알아보게 하는 방법

> ⚠ **2차 개정(§13-4)**: 메뉴 결과 탭은 **상세 직행**(매장 화면을 깔고 그 위에)으로 바뀌었다. 안내 띠는 "매장에 없다" 분기에서만 쓰인다.

D3-a (확정): 탭 → `StoreMenuPage(store, initialMainCategoryCode: hit.mainCategoryCode)`. **메뉴 상세 직행 금지.** 카드까지의 스크롤·하이라이트는 spec 비범위(F4).

## 5-a. 기본안 (spec 범위 안, 추가 파라미터 0)

사용자가 "내가 찾은 그 메뉴" 를 알아보도록 **세 곳**에 단서를 둔다.

| 시점 | 단서 |
|---|---|
| 이동 **전** (결과 행) | 3행 카테고리 태그 `커피` — "이 탭으로 갑니다" 를 예고 |
| 이동 **직후** (매장 화면) | **해당 메인 카테고리 탭이 선택된 상태**로 열린다 (`MainCategoryTabs` 의 선택 탭 = 태그와 같은 글자). 사용자는 태그와 선택 탭이 같은 글자임을 보고 위치를 안다 |
| 매장 화면 안 | 그 탭의 메뉴 그리드(2열)에서 **메뉴 이름으로 눈으로 찾는다.** 한 탭 안의 메뉴는 보통 수십 개 이하 |

- 한계: 탭 안의 수십 개 카드 중 어느 것인지는 사용자 눈에 맡긴다. 해당 메뉴가 `excluded`(L2) 거나 품절(L5)일 때 사용자는 "왜 없지?" 에 대한 설명을 받지 못한다. → 아래 확장안.

## 5-b. 확장안 (사용자 확인 필요 — §8 N1, 기본값은 **기본안**)

D3 는 "(b) 를 지금 올리라고 하면 범위에 넣을 수 있다" 고 했다. 스크롤을 빼고 **표시만** 더하면 비용이 작다.

- `StoreMenuPage` 에 nullable 파라미터 1개 추가: `highlightMenuItemId`. (`initialMainCategoryCode` 와 같은 성격, 기존 호출부 미지정 = 현행)
- 해당 메뉴가 그리드에 **있으면**: 그 카드에 `AppColors.primary` 1.5px 테두리 (기존 카드 테두리 `border` 1px 를 대체). 스크롤 이동은 하지 않는다.
- 그리드 위(카테고리 헤더 바로 아래)에 안내 띠 1개: 높이 40, radius 12, 배경 `AppColors.primaryBright` alpha 0.12, 아이콘 `Icons.search_rounded` 16 `primary` + 텍스트 `검색한 메뉴  {메뉴명}` 13/w600/`textBody` + 우측 `×`(44, 닫으면 테두리도 해제).
- 해당 메뉴가 그리드에 **없으면** (excluded / 해당 탭에 없음): 띠 문구가 `이 매장에서는 판매하지 않는 메뉴일 수 있어요` 로 바뀐다 (`warning` 아이콘 `Icons.info_outline_rounded` 16, 글자 `textBody`). **이것이 spec 한계 L2·L5 를 사용자에게 정직하게 알리는 유일한 지점이다.**
- 매칭은 이름이 아니라 **`menuItemId`** 로 한다 (병합 목록의 id 가 마스터 id 와 같다).
- 추천: **확장안 채택**. 기본안은 "찾던 메뉴가 없는 매장" 을 사용자가 스스로 의심해야 하고, 그 경우가 spec 이 인정한 한계(L2)다.

## 5-c. 이동 시 주의 (developer 로 전달)

- `selectedMainCategoryProvider` 는 **전역 Notifier(family 아님)** 이고 `null = 첫 카테고리 stream 도착 시 자동 선택` 이다. `initialMainCategoryCode` 는 **첫 build 이전에 적용**되고, 다른 매장 화면으로 상태가 새지 않아야 한다.
- 매장에 해당 카테고리 메뉴가 없으면(탭 disabled) 초기 선택을 **무시하고 기존 자동 선택**으로 폴백한다.

## 6-a. 화면 구성


# 10. 개발자 전달 특이사항

1. **상태 판정은 한 함수**: `resolveSearchView(storeAsync, menuAsync, normalizedQuery)` → enum(§3-c 12상태 + 0글자·1글자). 위젯이 `AsyncValue` 를 직접 조합해 "없음" 을 판정하지 않는다. 특히 **통합 빈 상태는 이 함수만** 만든다 (메뉴 로딩/에러에서 금지).
2. **건수 표기**: 로딩·에러에서 `(0)`/`(n)` 을 그리지 않는다 (`메뉴` 만). 홈 `맞춤 추천 (n)` 도 동일.
3. 메뉴 섹션의 **로딩 → 결과** 전환이 매장 섹션의 레이아웃·스크롤을 건드리지 않게 한다 (같은 `ListView` 안에서 메뉴 영역만 교체).
4. 메뉴 재시도는 **메뉴 인덱스만** invalidate, 매장 재시도는 스냅샷 invalidate (spec §3.5). 부분 실패 재시도 중에도 기존 결과 행은 유지한다.
5. **최근 검색어 기록 시점**: 키보드 제출 또는 결과 탭. debounce 반영만으로는 기록하지 않는다. 공백 정규화 후 빈 질의는 기록하지 않는다. 표시용 원문은 trim 한 입력 그대로.
6. 메뉴 행 카테고리 태그는 `mainCategoriesActiveProvider` 로 라벨을 해석하고, 해석 실패 시 **태그를 그리지 않는다**(코드 노출 금지). 이 provider 는 기존 `store/widgets/main_category_tabs.dart` 가 쓰는 것과 같다.
7. 메뉴 행에 가격·할인·품절 등 **어떤 숫자 필드도 만들지 않는다.** `MenuSearchHitEntity` 에도 가격 필드 없음 (spec §4.1). 위젯 코드 리뷰 시 `price`/`Price` 문자열 grep 0건.
8. `RecommendedStoreCard` 에 `subtitle` 을 추가할 때 **기본 null 일 때 레이아웃이 한 픽셀도 바뀌지 않아야 한다** (홈 회귀). 세 줄 배치는 `subtitle != null` 일 때만.
9. `StoreMenuPage.initialMainCategoryCode` 는 전역 Notifier(`selectedMainCategoryProvider`)를 쓰므로 첫 build 전 적용 + 다른 매장으로 상태 누수 방지 + 매장에 해당 카테고리 없으면 기존 자동 선택으로 폴백 (§5-c).
10. 홈 에러 UI 가 예외 원문 `$e` 를 노출하는 것을 이번에 같이 고친다(§2-b). 3곳(홈·검색·전체보기)이 같은 문구를 쓴다.
11. 색은 전부 `AppColors` 토큰. `Color(0x…)` 0건. 신규 토큰 0개.

## 13-1. ① 검색 메뉴 행 — 가격과 품절

### 근거 (spec §15.5)

같은 메뉴가 **매장별로 여러 행**으로 나오는 화면에서 가격이 없으면 사용자는 행을 **거리로만** 고른다. 가격은 장식이 아니라 행을 고르는 축이다. 1차의 금지 이유("우리가 보여줄 가격이 틀릴 수 있다")는 2단계가 override 를 읽으면서 사라졌다. **해제하는 것은 가격 하나뿐이다.**

### 행 구성 (`MenuSearchResultTile` 개정)

```
 ┌────────────────────────────────────────────────┐
 │ ┌────┐  아이스 아메리카노                            ›  │  15/w700 heading
 │ │ 56 │  Q브루어리 강남점 · 1.2km                        │  13/w500 body
 │ └────┘  4,500원  [품절]  [커피]                        │  ← 3행: 가격 · 품절 배지 · 카테고리 태그
 └────────────────────────────────────────────────┘
```

| 영역 | 규격 |
|---|---|
| 컨테이너 | 1차와 동일 (최소 높이 72, `surfaceElevated`, 테두리 `border`, radius 16, padding `h12 v10`, 그림자 없음) |
| 1행 메뉴명 | 15/w700/`textHeading`, 1줄 말줄임. **품절이면 `textMuted`** |
| 2행 | `{매장명} · {거리}` 13/w500/`textBody` (1차 그대로). 품절이면 `textMuted` |
| **3행 (개정)** | `Wrap(spacing: 6, runSpacing: 4)` 안에 **① 가격 ② 품절 배지(조건부) ③ 카테고리 태그(해석될 때만)**. 폭이 모자라면 줄바꿈 |
| ① 가격 | **`PriceFormatter.formatKrw(basePrice)` 결과를 그대로 쓴다.** 접미사·접두사(`부터`, `~`, `₩`, `원~`, 할인가 병기) **금지.** 글자 13/w700. 색: 정상 `AppColors.primary`(매장 화면 `MenuItemCard` 가격과 같은 색·굵기), 품절 `AppColors.textMuted`. 매장 화면 카드와 **글자 그대로 같은 문자열**이어야 한다 |
| ② 품절 배지 | 높이 20, 가로 padding 8, radius 999, 배경 `AppColors.textHeading` alpha 0.85, 글자 `품절` 11/w700/`AppColors.onPrimary`. (`MenuItemCard._soldOutOverlay` 의 pill 과 **같은 색 규칙**이고 크기만 행에 맞춘 것) 품절일 때만 |
| ③ 카테고리 태그 | 1차 그대로 (높이 20, `surface`, 11/w600/`textBody`). 해석 실패면 그리지 않는다 |
| 썸네일 | 56x56 (1차 그대로). **품절이면 위에 `AppColors.background` alpha 0.7 덮개**(카드 오버레이와 같은 톤). 글자는 올리지 않는다(56px 에서 읽기 어렵고, 배지가 글자를 맡는다) |
| 우측 | chevron 20 `textMuted` (1차 그대로) |

- **품절 행도 숨기지 않는다.** 매장 화면이 품절 카드를 숨기지 않는 것과 같은 기준이다(`isMenuShownOnStoreScreen` 은 품절을 보지 않는다). 정렬도 그대로(거리 오름차순 → 메뉴명) — 품절을 아래로 내리지 않는다.
- **탭**: 정상·품절 **모두** 상세로 간다(U2, §13-4). 품절 행을 비활성(탭 불가)으로 만들지 않는다. 눌림 피드백은 1차와 동일(`primary` alpha 0.04).
- 가격은 **검증된 행에만** 있다. 검증 못 한 행(2단계 실패 매장)은 **행 자체가 없다**(spec R6). "가격만 비우고 행은 남기기" 금지 — 1차가 막은 구멍이 다시 열린다.

### 계속 금지 (이 절이 다시 못 박는다)

**할인 · 별점 · 리뷰 수 · 옵션 최저가 · 옵션 추가금 · 평점/등급 숫자 · 재고 수량 · 영업 상태** 칸을 행에 **만들지 않는다. 자리도 예약하지 않는다.** `MenuSearchHitEntity` 에 추가되는 필드는 `basePrice` 와 `soldOut` 둘뿐이다(spec §15.12). 위젯 코드 리뷰 시 `price` 가 `basePrice` 외의 값(`discount`, `minOptionPrice` 등)과 함께 쓰이면 반려.

### 접근성

`Semantics(button: true, excludeSemantics: true, label: '{메뉴명}, {가격 읽기}, {품절이면 "품절"}, {매장명}, {거리}, {카테고리} 카테고리. 탭하면 메뉴 상세로 이동')`. 가격 읽기는 `4,500원`. 품절은 가격 **뒤**에 읽는다(`… 4,500원, 품절, Q브루어리 강남점 …`). 덮개·chevron 은 `ExcludeSemantics`.

### 상태 · 인벤토리 영향

- 로딩/에러/부분 실패/빈 상태는 1차 §3-c 12상태 **그대로**다 (§13-5). 새 상태 없음.
- 헤더 `메뉴 ({n})` 의 n 의 의미가 바뀐다(spec R5): **검증을 통과한 일치 수** = "실제로 살 수 있는(또는 품절로 보이는) 수". R4 상한(10곳)으로 잘린 분은 n 에 넣지 않고 기존 `isTruncated` 안내(`검색 범위를 좁혀 보세요`)만 띄운다.

```
┌ ImageHeader (4:3) ─────────────────────────┐
│  [←]                                [♡]       │  ← 뒤로가기·즐겨찾기는 그대로 위에 남는다
```

### 영역별 명세 (`soldOut == true`)

| 영역 | 설계 |
|---|---|
| **이미지 헤더** | 이미지 위에 **`품절` 오버레이**: `DecoratedBox(color: AppColors.background alpha 0.7)` + 중앙 pill(배경 `AppColors.textHeading` alpha 0.85, 글자 `품절` **14**/w700/`AppColors.onPrimary`, padding `h16 v8`, radius 999). **카드 `_soldOutOverlay` 와 같은 톤·같은 색 규칙**이고 글자·여백만 큰 화면에 맞춘 것이다. 상단 그라데이션·뒤로가기·즐겨찾기 버튼은 **오버레이 위에** 그대로 남는다(z 순서: 이미지 < 오버레이 < 그라데이션 < 버튼) |
| **공용 위젯화** | `_soldOutOverlay` 를 `presentation/common/` 의 `SoldOutOverlay`(파라미터 `fontSize`, `padding`)로 올려 **카드·상세가 같은 코드**를 쓴다. 두 곳의 색·투명도가 어긋나지 않게 하는 것이 목적이다(공용화 판단: **올린다**) |
| **메뉴명 / 가격** | 메뉴명 `textMuted`(22/w800 유지), 가격 `textMuted`(18/w700 유지, 평소 `primary`). 카드의 `soldOut ? textMuted : …` 규칙과 같다 |
| **안내 plate** (신규) | 가격 아래 gap 12. `AppColors.surface` 배경, radius 12, padding `h14 v12`. 아이콘 `Icons.info_outline_rounded` 16 `textMuted` + 글자 **`지금은 품절이에요. 다시 판매되면 담을 수 있어요`** 13/w500/`textBody`. **경고색(`warning`/`error`)을 쓰지 않는다** — 품절은 이상 사건이 아니라 일시적 상태다. 설명 문장 아래 헤어라인(`border`)은 기존 `_InfoSection` 의 구분선을 그대로 쓴다 |
| **옵션 그룹 영역** | 전체를 `Opacity(0.45)` + `IgnorePointer`. 그룹 제목·항목은 **읽을 수는 있게** 남긴다(어떤 옵션이 있는 메뉴인지 보는 것은 정보다). 접근성: 영역에 `Semantics(label: '품절이라 선택할 수 없어요', enabled: false)` 로 묶고 개별 항목 낭독은 `ExcludeSemantics` 로 줄이지 **않는다**(읽을 수는 있어야 한다). `primeRequiredDefaults` 자동 선택은 그대로 돌아도 무해하다 |
| **수량 스테퍼** | **비활성.** `QuantityStepper` 에 `enabled`(기본 true) 파라미터를 추가: `false` 이면 −/+ 버튼과 숫자를 `textMuted`·alpha 0.45 로 낮추고 탭을 무시한다. 레이아웃 불변 |

| **즐겨찾기(♡)** | **품절과 무관하게 동작을 유지한다.** 색·동작 변경 없음. 품절은 일시적이고, 즐겨찾기는 "나중에 다시 볼 메뉴" 라는 의도와 맞다 |
| **실시간 전환** | 상세는 `watchById` 스트림이다. 보고 있는 도중 **품절 ↔ 판매로 바뀌면** 위 상태가 즉시 따라 바뀐다. 도중에 `_busy`(담는 중)였다면 진행 중인 요청은 끝내되 성공 후의 화면은 새 상태를 따른다. 별도 토스트/SnackBar 를 띄우지 않는다(화면 변화가 곧 알림) |

### 상태 (loading / error / empty)

| 상태 | 표현 |
|---|---|
| Loading | 기존 `_LoadingView` 그대로 (품절을 모르는 동안 **`담기` 를 그리지 않는다** — 기존도 `detailAsync.maybeWhen(data:…)` 로 바텀 바를 숨긴다) |
| Error | 기존 `_ErrorView`. **override 스트림 실패를 "마스터 가격 + 판매 중" 으로 폴백하지 않는다**(§13-7 F5-9). 실패면 에러 화면 |
| Empty / 판매 안 함 | `null` → `_DeletedView` (§13-3) |

### 접근성

- 이미지 오버레이·pill 은 `ExcludeSemantics`, 대신 상단 정보 영역이 `메뉴명, 품절, 가격` 순으로 읽힌다(`Semantics(label: '아이스 아메리카노, 품절, 4,500원')`).
- 버튼 `Semantics(button: true, enabled: false, label: '품절, 담을 수 없어요')`.
- 안내 plate 는 일반 텍스트로 읽힌다.

## 13-3. ③ `_DeletedView` — 문구와 액션

### 지금 무엇을 보여주는가 (코드 확인)

`menu_item_detail_page.dart` 의 `_DeletedView`: 아이콘 `Icons.search_off_rounded` 56 `textMuted` + `메뉴를 찾을 수 없어요` 16/w700/`textHeading` + 텍스트 버튼 `뒤로가기`(= `maybePop`). **"삭제됨" 과 "이 매장이 안 팖(excluded)" 을 구별하지 않는다.** D13 이후 override `excluded` 이면 `watchById` 가 `null` 을 돌려 이 화면으로 온다.

### 이 화면에 오는 경로

| 경로 | 빈도 |
|---|---|
| 검색 행 탭 → 매장 화면이 목록 확정 → 있으면 상세 / 없으면 상세 **안 열림** (띠) | 정상 경로에서는 이 화면에 오지 않는다 (spec §15.7) |
| **상세를 보고 있는 도중** override 가 `excluded` 로 바뀌었거나 메뉴가 삭제됨 | 드묾 |
| 즐겨찾기·재주문·딥링크 등 **다른 진입점**에서 이미 내려간 메뉴를 연다 | 가장 현실적 |

→ 검색 맥락 전용 문구를 만들지 않는다. 세 경로 **모두에 참인** 문구여야 한다. "삭제됨" 과 "안 팖" 을 구별하는 정비는 spec F9(후속)이다.

### 개정 명세

| 요소 | 규격 |
|---|---|
| 아이콘 | `Icons.storefront_outlined` 56 `AppColors.textMuted` (검색 실패 아이콘 `search_off` 에서 교체 — 검색이 아니라 "이 매장" 이야기이므로) |
| 제목 | **`이 매장에서는 판매하지 않는 메뉴예요`** 16/w700/`textHeading`, 중앙, 최대 2줄 |
| 설명 | **`메뉴가 내려갔거나 판매가 중단됐을 수 있어요`** 13/w500/`textMuted`, 중앙 (제목과 gap 8) |
| 주 액션 | **`매장 메뉴 보기`** — 채움 버튼, 높이 48, 폭 최소 200, radius 12, 배경 `AppColors.primary`, 글자 `AppColors.onPrimary` 15/w600. 동작: 이 화면 바로 아래 스택이 **그 매장의 `StoreMenuPage` 이면 `Navigator.pop`** (뒤로가기와 같은 결과지만 **명시적 출구**를 준다). 아니면(즐겨찾기 등에서 직접 열린 경우) 그 매장의 `StoreMenuPage` 를 이 화면 **대신** push-replace |
| 보조 액션 | 텍스트 버튼 **`뒤로가기`** 13/w600/`textMuted`(기존 유지) |
| 매장 정보 없음 | 주 액션에 필요한 `StoreEntity` 를 얻지 못하면(스냅샷에 없음 등) **주 액션을 숨기고 `뒤로가기` 만** 남긴다 |

- 이 화면에는 `담기`/장바구니/즐겨찾기 등 **구매·저장 동선이 없다**(바텀 바도 `null` — 기존 동작).
- 색은 `warning`/`error` 를 쓰지 않는다 — 사용자의 잘못이나 장애가 아니라 정상 운영 변화다.
- 접근성: 제목·설명이 한 번에 읽히도록 `Semantics(container: true)`; 버튼 `매장 메뉴 보기, 버튼`.

## 13-4. ④ 메뉴 결과 탭 → 상세 직행 · 전환이 두 번 깜빡이지 않게

### 목적지 (spec §15.8 · U2 — 1차 §5 대체)

| 상황 | 동작 |
|---|---|
| 매장이 그 메뉴를 판다 (정상 · 품절 포함) | 매장 화면을 깔고 **그 위에 상세**. 뒤로가기 1회 → 매장 화면(그 카드 `highlight` 유지), 2회 → 검색 화면 |
| 매장에 없다 | **상세로 올리지 않는다.** 매장 화면에 머물고 안내 띠 `이 매장에서는 판매하지 않는 메뉴일 수 있어요`(1차 구현 유지) |

- 매장 결과(메뉴가 아닌) 탭은 **1차 그대로**(매장 화면까지만).
- 결과 행의 카테고리 태그는 **유지**한다. 직행하더라도 뒤로가기로 매장 화면에 돌아오면 그 탭이 선택돼 있고(`initialMainCategoryCode`), 태그는 "이 메뉴가 속한 탭" 을 알려 준다. 다만 접근성 문구의 끝은 `탭하면 메뉴 상세로 이동` 으로 바뀐다.

### 문제

검색 → **매장 화면(`StoreMenuPage`)** → **상세** 가 **연달아 쌓인다.** 사용자는 한 번의 이동으로 기대한다. 아무 처리가 없으면 다음이 보인다.

1. 매장 화면이 슬라이드로 들어온다(애니메이션 1)
2. 매장 메뉴 목록 stream 이 로딩이면 매장 화면의 **shimmer** 가 비친다
3. 목록이 확정되면 상세가 또 슬라이드로 올라온다(애니메이션 2)

→ 한 번의 탭에 **화면 3장이 번쩍인다.** 이것이 "두 번 깜빡임" 이다.

### 해법 — 중간 매장 화면을 "보이지 않게" 깐다

**원칙: 사용자에게 보이는 이동은 `검색 → 상세` 슬라이드 하나뿐이다. 중간의 매장 화면은 상세가 완전히 덮을 때까지 화면에 그려지지 않는다.**

| 단계 | 명세 |
|---|---|
| **(1) 중간 매장 화면의 라우트** | 메뉴 결과 탭으로 여는 `StoreMenuPage` 라우트는 **전환 애니메이션이 없다** — `PageRouteBuilder(transitionDuration: Duration.zero, reverseTransitionDuration: 표준(≈300ms), opaque: false)`. 매장 결과 탭 등 **다른 진입은 기존 `MaterialPageRoute` 그대로**(바꾸지 않는다) |
| **(2) 대기 중 그리기** | `autoOpenMenuItemId` 가 **대기 중**(목록 미확정)인 동안 매장 화면은 **아무것도 그리지 않는다**(투명, 배경색도 칠하지 않음). 그래서 **검색 화면이 그대로 보인다.** 매장 화면의 기존 shimmer(`_LoadingShimmer`)는 이 모드에서 **그리지 않는다** |
| **(3) 대기 피드백** | 탭 후 **250ms 가 지나도** 목록이 확정되지 않으면 검색 화면 위에 `AppColors.background` alpha 0.6 스크림 + 중앙 `CircularProgressIndicator` 28(`primary`). 250ms 안에 끝나면 아무것도 보이지 않는다(대개 이 경우 — 매장 메뉴 stream 이 곧바로 첫 값을 준다). 동시에 눌린 행은 눌림 색 유지 |
| **(4) 목록 확정 → 상세 push** | spec §15.8 의 `ref.listen` 이 "목록이 data 이고 id 가 `isMenuShownOnStoreScreen` 통과로 목록에 있음" 을 확인한 **그 프레임**에 상세를 **표준 push 애니메이션**(`MaterialPageRoute`)으로 올린다. 이것이 사용자에게 보이는 **유일한 이동**이다. 검색 화면이 슬라이드로 밀리고 상세가 들어온다 |
| **(5) 상세가 덮은 뒤에 비로소 매장 화면이 그려진다** | 매장 화면은 `ModalRoute.of(context).secondaryAnimation` 이 **완료(`completed`)** 되거나 **역방향으로 시작**(사용자가 상세에서 뒤로 스와이프)되면 그때 `_revealed = true` 로 내용(목록)을 그린다. 상세가 전부 덮은 뒤라 사용자는 매장 화면이 생기는 순간을 보지 못한다 |
| **(6) 상세 → 뒤로** | 상세가 표준 pop 으로 나가며 **완성된 매장 화면(shimmer 아님, 강조 카드 `highlight` 유지)** 이 드러난다. 한 번 더 뒤로 → 매장 라우트가 **표준(≈300ms) 역방향 전환**으로 나가 검색 화면이 돌아온다(`reverseTransitionDuration` 이 0 이 아닌 이유) |
| **(7) 상세를 올리지 않는 분기 (매장에 없다)** | 목록 확정 후 id 가 목록에 **없으면** 매장 화면이 **200ms 페이드 인**으로 나타나고 안내 띠가 보인다(바로 나타나는 대신 페이드 — 검색 화면이 갑자기 다른 화면으로 바뀌는 느낌을 줄인다) |
| **(8) 자동 push 는 1회** | spec §15.8 그대로 `_autoOpened` 플래그. 상세에서 뒤로 나온 뒤 다시 열리지 않는다 |

### 폴백 (품질 보증 사다리)

| 상황 | 동작 |
|---|---|
| 정상 | 위 (1)~(6) |
| 목록 확정이 **오래** 걸림(예: 3초 이상 / 에러) | 스크림+인디케이터를 유지하다 **3초가 넘으면 중단**하고 매장 화면을 `reveal` 해 기존 매장 화면 상태(shimmer 또는 에러)를 그대로 보여 준다. 자동 push 는 **그 뒤 목록이 확정되는 순간 그대로 시도**한다(이 경우에 한해 두 번의 전환이 보일 수 있다 — 드문 저속 네트워크 경로로 수용) |
| 위 비-투명 라우트 기법이 플랫폼에서 문제를 일으킬 때 | **최소 보장**: 중간 매장 라우트만 `Duration.zero` 로 하고(애니메이션 1 제거) 대기 중 shimmer 대신 `AppColors.background` 단색을 그린다. 보이는 것은 `검색 → (단색) → 상세 슬라이드` 가 되어 한 번의 깜빡임이 남는다. developer 는 이 단계로 떨어지면 `implementation.md` 에 기록 |

### 수용 기준 (tester)

- 정상 네트워크에서 메뉴 행 탭 → **매장 화면의 shimmer 가 한 프레임도 보이지 않는다.**
- 탭부터 상세가 덮을 때까지 **보이는 슬라이드 애니메이션이 1회**(상세).
- 상세에서 뒤로 → **완성된 매장 화면**(강조 카드 유지), 한 번 더 뒤로 → 검색 화면(질의·스크롤 위치 유지).
- 상세에서 뒤로 나온 뒤 상세가 **다시 열리지 않는다.**
- 매장에 없는 메뉴: 상세 없이 매장 화면 + 띠, 페이드 인.

### 접근성

스크림이 뜨는 동안 `Semantics(liveRegion: true, label: '메뉴로 이동하고 있어요')`. 상세가 열리면 상세 제목이 낭독 포커스를 받는다(기본 라우트 동작).

## 13-5. ⑤ 2단계 로딩 — **새 표현을 만들지 않는다**

spec §15.13: 2단계는 기존 상태에 매핑된다. **1차 §3-c 의 12상태·§3-d 중간 상태 규격이 그대로 유효하다.**

| 2단계 상황 | 화면 (1차 상태 그대로) |
|---|---|
| 1단계(인덱스) + 2단계(override) **진행 중** | `s3`/`s8` — 메뉴 헤더 `메뉴` + 14px 인디케이터 + `메뉴를 찾고 있어요` + **shimmer 2행**. **두 단계를 사용자에게 구분해 보이지 않는다** |
| 2단계 끝 | shimmer → **검증된 행으로 한 번만** 교체(페이드 150ms) |
| 2단계 일부 매장 실패 | `s7`/`s12` — 부분 실패 줄(`일부 매장의 메뉴를 불러오지 못했어요` + `다시 시도`). **실패 매장의 행은 없다**(R6) |
| 2단계 전멸 | `s6`/`s11` — 메뉴 인라인 에러 카드 |
| 검증 후 0건(전부 excluded) | `s5`/`s10` — `'{질의}' 와 일치하는 메뉴가 없어요`. **"있었는데 걸렀다" 를 설명하지 않는다** |
| R4 상한(10곳)으로 잘림 | 기존 `isTruncated` → `검색 범위를 좁혀 보세요` |

- **R1 의 시각적 의미**: 1단계 행을 **먼저 그리지 않는다.** 행이 먼저 뜨고 나중에 사라지거나 가격이 바뀌는 것을 막는다. 사용자는 shimmer → 완성된 행만 본다. 1차 `menuSearchResultsProvider`(활성 카테고리를 모를 때 행을 보류)와 같은 선례다.
- 체감 지연: 2단계는 1~3쿼리·1라운드트립(100~300ms 추가). 같은 shimmer 가 약간 길어지는 것뿐이다.
- **재시도 중 직전 값 유지(`hasValue` 우선)** 규칙은 그대로: 이미 검증된 행은 부분 실패 재시도 중에도 지우지 않는다(R1 과 충돌하지 않는다 — R1 은 *검증 전 행을 처음부터 그리지 말라*, 이쪽은 *검증된 행을 지우지 말라*).
- 질의가 바뀌어도 2단계는 매장 캐시로 즉시(0쿼리) — 새 매장이 일치하는 질의에서만 shimmer 가 잠깐 돌아온다.

## 13-6. D9 — 매장 화면 품절 카드 탭 허용 (라이브 동작 변경)

규칙을 하나로: **"품절은 볼 수 있고 담을 수 없다."** 검색 행·매장 카드 **둘 다** 탭하면 상세로 간다.

| 항목 | 명세 |
|---|---|
| 카드 탭 | `MenuItemCard` 의 `onTap: soldOut ? null : onTap` → **항상 `onTap`**. 품절 카드도 상세로 간다 |
| 시각 | 기존 품절 카드 처리 **그대로**: 이미지 `_soldOutOverlay`(→ 공용 `SoldOutOverlay`), 이름·가격 `textMuted`. 변경 없음 |
| "눌릴 수 있지만 품절" 신호 | 오버레이 pill `품절` 이 **상태를 말하고**, 카드 테두리·그림자는 정상 카드와 같다(눌림 피드백 있음). 비활성처럼 보이게 **흐림(opacity)을 더하지 않는다** — 탭 가능한 카드를 흐리게 하면 "눌리지 않는 카드" 로 오독된다 |
| 눌림 피드백 | 정상 카드와 동일(`GestureDetector` → 이미 탭 영역 있음; 눌림 효과가 없는 기존 카드와 같은 수준 유지) |
| 접근성 | 품절 카드 `Semantics(button: true, label: '{메뉴명}, 품절, {가격}. 탭하면 메뉴 상세로 이동')`. (기존에는 비활성이라 `button` 이 아니었다) |
| 상세 도착 후 | §13-2 의 품절 상태 |

- 이 변경은 **검색과 무관한 라이브 화면 변경**이다. 근거(spec D9): 같은 메뉴가 검색에서는 열리고 매장 화면에서는 안 열리는 불일치를 남기지 않는다. 장바구니·결제의 품절 검증 부재(spec F8)는 이 변경과 별개로 남는다 — 상세에서 `담기` 를 막는 것이 UI 의 최선이다.

## 13-7. ⑥ 표면 인벤토리 보강 (R2) — 1차 FAIL 의 근본 원인은 행 누락이었다

> 1차 검증 FAIL-1·FAIL-2 는 "이 매장이 이 메뉴를 파는가" 를 말하는 표면이 표에 없어서 판정 출처가 검증되지 않은 채 구현된 것이었다(§1-e 가 그때 추가됨). 이번 개정은 **같은 사실에 가격·품절·상세가 표면으로 더해진다.** 아래 행을 **§1-e F5 에 이어 추가**한다. ⓑ 가 빈 칸인 행은 없다.

**단일 판정 원칙**: 가격·품절·"판다/안 판다" 는 **`applyOverrideForCustomer` + `isMenuShownOnStoreScreen` 이라는 두 순수 함수만** 통과한 값이다(spec §15.2). 아래 모든 표면이 같은 두 함수의 결과를 말한다. 화면이 `priceOverride`/`soldOut`/`excluded` 원시 필드를 직접 읽어 따로 판정하지 않는다.

| 1차 행 | 개정 |
|---|---|
| F2-1 메뉴 섹션 결과 | ⓑ 에 **2단계 실패**를 추가(위 F5-1). 부분 실패/전체 실패의 화면은 1차와 같다 |
| F2-2 `메뉴 (n)` | n = 검증 통과 수. 로딩·에러에서 숨김 규칙 불변 |
| F2-3 통합 빈 상태 | 불변. 단 **2단계 진행 중에도 통합 빈 상태 금지**(로딩) |
| F2-5 범위 안내 | 불변. (tester 가 올린 "실제 검색 매장 수와 문구 불일치" 는 spec 쪽 결정 사항이며 이 문서에서 다시 열지 않는다) |
| F2-6 메뉴 행 → 이동 후 | **개정**: 이동 후 화면은 상세(또는 띠가 있는 매장 화면). `StoreMenuPage` 자체 에러/빈 상태는 기존 |

### 교차 일관성 (한 사실 = 같은 값)

같은 (매장, 메뉴)에 대해 **검색 행 가격 == 매장 카드 가격 == 상세 가격 == 담기 합계의 기본가** 가 성립해야 한다(검색 행이 몇 분 낡은 경우 상세가 서버 값으로 덮인다 — spec §15.7 L4 축소). 품절 판정도 세 표면에서 같다. tester 의 교차 검증 항목이다.

## 13-9. 개발자 전달 특이사항 (2차 변경분)

1. **구현 순서는 spec §15.14 를 따른다.** 1·2(`applyOverrideForCustomer` 추출, `watchById` 머지)는 라이브 화면을 건드리므로 UI 작업(이 절)보다 **먼저 끝내고 검증**한다. 이 절은 그 이후를 전제로 한다.
2. **행에 가격 외 숫자 필드를 만들지 않는다.** `MenuSearchHitEntity` 에 `basePrice`/`soldOut` 외 추가 금지. 가격 표기는 `PriceFormatter.formatKrw(basePrice)` **한 곳**(매장 카드와 같은 호출). 접미사·`부터`·`~` 금지 (`grep` 대상).
3. **품절 오버레이를 `presentation/common/` 의 `SoldOutOverlay` 로 올린다.** `MenuItemCard`, 메뉴 상세 이미지 헤더, 검색 행 썸네일(덮개만)이 같은 색 규칙을 쓴다.
4. 상세 `_BottomAction` 의 판정 순서 **`soldOut` → `_busy` → required 미선택**. 품절은 토스트를 띄우지 않는다. `_onAddPressed` 에도 `soldOut` 즉시 return.
5. `QuantityStepper` 에 `enabled` 파라미터(기본 true) 추가. 옵션 영역은 `Opacity + IgnorePointer`(읽기는 가능).
6. `MenuItemCard` 의 `onTap` null 처리를 제거(D9). 카드 `Semantics` 를 `button: true` 로.
7. **전환(§13-4)**: 메뉴 결과 탭 전용 라우트는 `PageRouteBuilder`(`transitionDuration: Duration.zero`, `reverseTransitionDuration` 표준, `opaque: false`). **다른 진입은 `MaterialPageRoute` 그대로.** 대기 중 매장 화면은 **아무것도 그리지 않는다**(shimmer 포함), `secondaryAnimation` 완료/역방향에서 `reveal`. 자동 push 는 `ref.listen` 으로 목록 data 확정 프레임에 1회(`_autoOpened`).
   - 라우트 `opaque: false` 인 동안 아래 검색 화면이 계속 그려지므로, 매장 화면이 `reveal` 되면 **불투명 배경(`AppColors.background`)** 으로 그려 아래가 비치지 않게 한다.
   - 폴백 사다리(§13-4)와 "최소 보장 단계로 떨어졌을 때 `implementation.md` 에 기록" 을 따른다.
8. `_DeletedView` 의 `매장 메뉴 보기`: 아래 스택이 같은 매장의 `StoreMenuPage` 면 `pop`, 아니면 push-replace. `StoreEntity` 를 얻지 못하면 주 액션 숨김.
9. 상세 override 스트림 실패는 **에러 화면**(F5-7). 마스터 값 폴백 금지.
10. **검색 행은 검증 못 한 매장의 행을 그리지 않는다**(R6). 가격·품절을 비워서 행만 남기는 분기를 만들지 않는다.
11. 인벤토리 F5-5~F5-12 가 구현과 일치해야 한다. 새 표면(예: 홈 `자주 찾는 메뉴` 등이 이후 같은 사실을 말하게 되는 경우)이 생기면 표에 행을 추가한다.
12. 색은 전부 `AppColors` 토큰. `Color(0x…)` 0건, 신규 토큰 0개. `Colors.transparent` 는 기존 코드가 이미 쓰는 범위(그라데이션 끝)에서만.

## 13-10. 사용자 확인 / spec 과의 긴장점 (spec §15 는 뒤집지 않았다)

**사용자 결정이 필요한 새 항목: 없다.** 아래는 화면에서 드러난 사실을 올리는 것이다.

| # | 사항 | 이 문서의 처리 |
|---|---|---|
| T1 | **검색 행 가격이 상세와 다를 수 있다.** 행은 세션 캐시된 1단계 + 방문 단위 2단계라 몇 분 낡을 수 있고, 상세는 실시간 구독이다(spec L4 축소) | 화면은 별도 표시 없이 상세 값이 이긴다. 사용자가 "행에서는 4,500원이었는데 상세는 4,800원" 을 볼 수 있다. 빈도는 낮고 주문은 상세 값으로 가므로 수용. 마음에 걸리면 행 가격 옆 `~` 같은 표기는 **spec 이 접미사를 금지**했으므로 하지 않았다 |
| T2 | **장바구니·결제 품절 검증 부재(spec F8).** 상세에서 `담기` 를 막아도, 담은 뒤 품절된 메뉴는 결제까지 간다. 이번에 D9 로 품절 상세에 들어갈 수 있는 경로가 늘어난다 | UI 는 상세 `담기` 비활성까지 한다. 서버 검증은 spec F8(출시 전 점검 권장) — 이 문서에서 다룰 수 없다 |
| T3 | **뒤로가기 2회**: 검색 → (상세) → 매장 화면 → 검색. 매장 화면을 거쳐야 검색으로 돌아간다 | spec U2 가 "뒤로가기 → 매장 화면" 을 확정했다. 변경하지 않음 |
| T4 | **전환 해법이 비-투명 라우트/`secondaryAnimation` 에 기댄다.** 플랫폼별 미세 차이(iOS 스와이프 백 도중)로 매장 화면이 일찍 비칠 수 있다 | 폴백 사다리를 명세했다(§13-4). 정상 경로 수용 기준이 깨지면 developer 가 최소 보장 단계로 떨어뜨리고 기록 |
| T5 | **품절 행이 거리순에 섞여 위에 올 수 있다**(품절 매장이 가까우면) | 정렬 규칙은 spec 대로 거리→이름. 품절을 아래로 내리는 정렬은 **하지 않았다**(spec 비범위). 필요하면 후속 |
| T6 | `_DeletedView` 가 "삭제됨" 과 "안 팖" 을 구별하지 못한다 | spec F9(후속). 문구는 두 경우 모두에 참이도록 썼다 |
| T7 | 1차의 섹션 하단 둘째 줄 `가격과 판매 여부는 매장 화면에서 확인해 주세요` 가 2차에서 거짓이 되어 삭제한다 | 이 문서가 삭제를 명세. 구현이 남기면 반려 |

## 13-11. 완료 기준 (2차, 디자인 관점)

- [ ] 검색 행에 **가격이 있고** `PriceFormatter.formatKrw` 결과 그대로다(접미사 없음). 매장 카드·상세 가격과 같은 문자열
- [ ] 행에 **할인·별점·리뷰 수·옵션 최저가 칸이 없다**
- [ ] 품절 행: 썸네일 덮개 + `품절` 배지 + 이름·가격 `textMuted`, **숨겨지지 않고 탭된다**
- [ ] 상세 품절: 이미지 오버레이 · 안내 plate · 옵션 비활성 · 수량 비활성 · 하단 `품절` 비활성(토스트 없음) · 즐겨찾기 유지
- [ ] 매장 카드 품절도 **탭 허용**, 상세에서 같은 품절 상태
- [ ] 메뉴 행 탭 → **매장 화면 shimmer 가 비치지 않고** 보이는 슬라이드가 **1회**
- [ ] 상세 → 뒤로 → 완성된 매장 화면(강조 카드 유지) → 뒤로 → 검색 화면. 상세 재열림 없음
- [ ] 매장에 없는 메뉴: 상세 없이 매장 화면 + 띠(페이드 인)
- [ ] `_DeletedView`: `이 매장에서는 판매하지 않는 메뉴예요` + `매장 메뉴 보기`
- [ ] 2단계 중 메뉴 섹션은 **shimmer → 검증된 행으로 한 번에 전이**(행이 떴다 사라지지 않음). 새 로딩 표현 없음
- [ ] 인벤토리 F5-1~F5-12 의 ⓑ 가 구현과 일치한다. 상세에서 override 실패를 마스터 가격으로 폴백하지 않는다
- [ ] `Color(0x…)` 0건, 신규 토큰 0개, 텍스트 1.5x 에서 겹침·잘림 없음
