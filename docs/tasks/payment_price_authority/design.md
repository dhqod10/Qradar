- 색상: 전부 `AppColors` 토큰. `Color(0x...)` / `Colors.white` / `Colors.black` 을 쓰지 않는다.

## 0. 이 설계의 한 줄

> 금액이 안 맞아 서버가 거절해도, 카트는 스스로 가격을 갱신하지 않으므로 **다시 눌러 봐야 같은 거절**이다. 이 디자인은 그 루프에 **탈출구 두 개**를 만든다 — (1) 거절 화면의 주 버튼이 **카트를 최신 가격으로 다시 읽어 담는 동작**이고, (2) 거절당하기 **전에** 카트가 가격 변동을 먼저 보여 준다.
> 고객은 범인이 아니다. 금액 불일치의 대부분은 가격이 그 사이 바뀐 것이다. 문구는 끝까지 그쪽을 가정한다.

## 1. DQ1~DQ6 답변 요약

| DQ | 답 | 상세 |
|---|---|---|
| **DQ1** 주 버튼 | **최신 가격으로 다시 담기.** 누르면 신선 읽기로 카트를 재가격하고 **적용한 뒤** 카트로 보낸다. 단순 pop 이 아니다. 재가격이 달라진 게 없으면 "달라진 게 없어요" 변형으로, 재가격 자체가 실패하면 **이 화면에 머물며** 인라인 오류와 재시도를 보인다 | §4.2, §4.4 |
| **DQ2** 숫자 | Q6=ⓒ 에 따라 **거절 화면에는 금액 숫자가 없다.** 숫자는 카트에서 보인다: 라인의 이전가 취소선 + 현재가, 상단 배너의 합계 이전 → 현재. 숫자는 서버 문자열이 아니라 **UseCase 가 계산한 int 를 앱이 포맷**한다(D4 예외가 필요 없다) | §5 |
| **DQ3** 알림 방식 | **배너(합계) + 라인 표시(어느 메뉴) 둘 다.** 다이얼로그는 쓰지 않는다(카트 화면 안에서 끝나는 일이다). 단 **체크아웃에서 결제 탭 시점에 발견된 변동**만 시트로 알린다(이미 결제 화면 안이므로 되돌아갈 곳이 없다) | §5.1~5.4 |
| **DQ4** 오름/내림 | **같지 않다.** 오름은 warning 톤 + 카트에서 멈춰 고객이 새 금액을 확인하고 다시 누르게 한다. 내림은 info 톤. 섞이면 중립 문구. 둘 다 숫자를 보여 주고, 둘 다 **자동으로 결제를 진행하지 않는다** | §5.2 |
| **DQ5** 옵션 지목 단위 | **두 단계.** 거절 화면은 **메뉴 단위**(토큰이 menuItemId 만 싣는다). 카트는 클라이언트가 읽은 값으로 **옵션 라벨 단위**까지 표시한다. 클라이언트가 옵션을 특정하지 못하면 메뉴 행 단위 문구로 내려간다 | §4.3, §5.5 |
| **DQ6** 조작자와 같은 화면 | **그대로 같은 화면.** 문구는 선량한 쪽을 가정하고, 화면에는 서버가 계산한 금액·판정 근거를 **하나도 싣지 않아** 조작자에게 새로 알려 주는 정보가 없다. 두 사람 모두 복구 버튼으로 **정상 가격**에 도달한다 | §2 P6 |

## 2. 설계 판단

### P1. 거절 화면의 주 버튼은 "실제로 복구하는 동작"이다 (DQ1)

- 거절 화면이 `Navigator.pop()` 을 주 버튼으로 삼으면 카트가 그대로라 같은 거절이 반복된다(spec §7-2). 선행 design §3.1 이 "다시 시도" 를 금지한 것과 같은 판단이다.
- 주 버튼 '최신 가격으로 다시 담기' 의 동작은 **UI 가 계산하지 않고** `ValidateCheckoutUseCase`(`reportFailure: true`)로 신선 읽기를 하고, 결과를 `ApplyRepricedCartUseCase`(신규, 도메인)로 카트에 **적용**한 뒤 카트로 이동하는 것이다. presentation 은 금액을 계산하지 않는다(spec §15).
- 보조 버튼 '카트로 돌아가기' 는 pop 이다. 이것이 함정이 되지 않는 이유: 카트의 '결제하기' 탭이 **진입 재가격**(R9)을 하기 때문이다. 그러나 진입 재가격은 N3 에 따라 실패하면 무음이므로 **혼자서는 탈출구가 못 된다.** 그래서 주 버튼이 "실패를 정직하게 알리는" 명시적 경로를 맡는다.

### P2. 루프 차단기 — 재가격해도 소용없는 경우를 화면이 안다

재가격 후에도 서버가 거절하는 경우가 있다(조작, 가격이 오갔다 되돌아옴, 클라·서버 산식 불일치 버그). 이때 같은 버튼이 같은 동작을 반복하면 두 번째 루프다. 규칙:

| 상황 | 화면 |
|---|---|
| 재가격 결과 **카트가 바뀌었다** | 적용 → 카트로 이동 → 배너 (§5) |
| 재가격 결과 **카트가 이미 최신이다**(바뀐 라인 0, 옵션 문제 0) | 거절 화면이 **"달라진 게 없어요" 변형**으로 바뀐다 (§4.2 변형 N). 주 버튼은 '카트로 돌아가기'(재결제 시도), 보조는 '카트 비우고 메뉴 보러가기' |
| 재가격을 이미 **한 번 적용했는데** 같은 카트가 또 PRICE_MISMATCH | **처음부터 변형 N** 을 보인다(재가격 버튼을 다시 주지 않는다). 판별: 메모리 전용 `priceRepricedCartSignatureProvider`(카트 구성 서명 = menuItemId + 수량 + 옵션 id 목록의 해시)가 현재 카트 서명과 같음 |
| 재가격 읽기 **실패** | 이 화면에 머문다. 인라인 오류 + 버튼 라벨 '다시 불러오기' (§4.2) |

- **최후 탈출구는 항상 '카트 비우고 메뉴 보러가기'** 다. 카트를 비우고 메뉴 상세에서 다시 담으면 `computeCartAmount`(R7)가 담는 시점의 현재 가격으로 라인을 만든다. 어떤 원인이든 이 경로는 막히지 않는다.
- 변형 N 문구는 "잠시 후 다시" 가 **풀릴 수도 안 풀릴 수도 있음**을 정직하게 말한다(§4.2).

### P3. 문구 금지어와 톤

- 금지어: 조작, 비정상, 위조, 변조, 부정, 의심. 가드 테스트가 문자열 상수 전수에서 이 6개를 막는다('이상' 은 '~ 이상' 용례가 많아 가드 대상에서 뺀다). 사유를 가정하는 문장도 쓰지 않는다('잘못 입력', '수정하셨' 등).
- 주어는 **가격** 이다. "가격이 바뀌었어요", "옵션이 바뀌었어요". 고객의 행동이 아니라 상황이 원인이다.
- "가격이 안 맞아요" 로 끝나는 문구 금지(미완성). 모든 문구는 고객이 다음에 누를 버튼을 가리키며 끝난다.

### P4. 금액 숫자는 거절 화면에 없다 (Q6=ⓒ, 다시 열지 않는다)

- 토큰은 id 만 싣는다. 거절 화면은 어떤 금액도 그리지 않는다.
- 이 화면이 "얼마가 됐는지" 를 말하지 못하는 대가는 **주 버튼의 라벨과 본문이 "카트에서 바뀐 금액을 보여 준다" 고 약속**하는 것으로 갚는다(§4.2 본문).

### P5. 금액 변동 알림은 "확인됨" 신호가 아니다 (N1·N2 유지)

- 가격 변동 배너·라인 표시는 **무언가 달라졌을 때만** 나타난다. 달라진 게 없거나 확인을 못 했을 때는 둘 다 **아무 표시가 없고 구분되지 않는다.**
- `CartLineAvailability` 에 `verified` / `ok` / `priceChecked` 같은 값을 **추가하지 않는다.** 가격 변동은 availability enum 이 아니라 **별도 값 객체**(`CartLinePriceChange`)로 둔다 — enum 에 섞으면 "정상" 이 "확인됨" 처럼 읽히는 경로가 생긴다.
- 내림(가격 하락)을 초록(`AppColors.success`)으로 칠하지 않는다. 초록은 선행 design 의 "재고·판매 가능 확인" 금지 색 규칙과 충돌해 "검증 통과" 로 읽힌다. 내림은 info 톤.

### P6. 조작자와 선량한 고객이 같은 화면을 본다 (DQ6)

- 서버가 둘을 구분하지 못하므로(spec §7-2) 구분하는 문구를 쓰지 않는다. 선량한 쪽을 가정해도 **조작자에게 새로 알려 주는 정보가 없다**: 화면에는 서버 계산액, 차이, 어느 검사가 깨졌는지 등이 전혀 없다. 있는 것은 "카트에 담긴 메뉴 이름" 과 "가격이 바뀌었다" 뿐이다.
- 조작자도 복구 버튼으로 얻는 것은 **정상 가격의 카트**뿐이다. 이 화면이 조작자에게 열어 주는 새 길은 없다.
- 반복 거절(P2 변형 N)은 오류 코드 캡션을 보인다. 이는 선량한 고객이 문의할 때 필요하다.

### P7. 모드용 UI 는 만들지 않는다

- `PAYMENT_PRICE_MODE` 는 서버 설정이다. admin 앱에 토글·화면·배지를 만들지 않는다. 클라이언트는 현재 모드를 모르고 알 필요도 없다 — `off` / `shadow` 에서는 거절이 오지 않을 뿐 화면은 같다.
- 재가격(R9)은 모드와 무관하게 **항상** 동작한다(선검증이므로). shadow 에서도 카트는 갱신된다.

## 3. 표면 인벤토리 — 선행 design §2 에 이어지는 사실 5·6 행

> 선행 design §2 의 사실 1~4 에 **더하는** 행이다. 행 번호는 5-n, 6-n. 규칙은 같다: ⓑ 가 빈 칸이면 미설계. 구분: 신규/변경/기존/서버.
> 선행 design §2 와 §3.1 말미에도 이 문서로 이어진다는 포인터를 넣었다.

| # | 표면 | ⓐ 판정 출처 | ⓑ 출처 읽기 실패 시 보이는 것 | ⓒ 복구 동작 | 구분 |

| 요소 | 문구 |
|---|---|
| 헤드라인 | 선택하신 옵션이 바뀌었어요 |
| 돈 줄 | 아직 결제되지 않았고, 요금도 청구되지 않았어요 |
| 본문 | 아래 메뉴에서 고르신 옵션을 지금은 선택할 수 없어요. 카트에서 어떤 옵션인지 확인하고 다시 골라 주세요. |
| 보조 본문 | 옵션이 바뀌면 가격도 함께 바뀔 수 있어요. 다시 고른 뒤 카트에서 새 금액을 확인해 주세요. |
| 목록 헤더 | 옵션을 다시 골라야 하는 메뉴 |
| 주 버튼 | 카트에서 확인하기 |
| 보조 버튼 | 닫기 (텍스트, 주 버튼과 같은 pop) |

- **왜 주 버튼이 재가격이 아닌가**: 옵션 위반은 **고객이 골라야 하는 선택**(필수 그룹이면 대체 항목을 직접 고른다)이라 자동으로 고칠 수 없다. 주 버튼은 그 선택이 가능한 곳(카트의 해당 행)으로 데려가는 것이 복구다. 반대로 `PRICE_MISMATCH` 는 값만 바꾸면 되므로 자동 적용이 가능하다. 이 차이는 의도다.
- 목록 카드: 선행 §3.5 위젯, 행 아이콘 `Icons.tune_rounded` 16 `textMuted`. 이름은 카트의 `menuItemName`. **옵션 이름은 이 화면에 없다**(토큰에 옵션 id 가 없고, 두 번째 해석 경로를 만들지 않는다 — spec §9-1).
- 지목 단위(DQ5): 이 화면은 메뉴 단위. 본문이 "카트에서 어떤 옵션인지 확인" 이라고 **다음 화면이 옵션 단위로 알려 준다고 약속**한다(§5.5).
- 주 버튼 동작: pop 직전에 `paymentRejectedMenuIdsProvider` 에 id 기록(선행 D6) — 종류는 `optionRejected`(§5.5 의 폴백 캡션용). 카트 진입 자동 선검증이 이 id 의 옵션 위반을 **옵션 라벨까지** 특정하면 §5.5 의 옵션 단위 표시로 대체된다.
- 상태 empty: 전부 해석 실패 → 목록 카드 없이 본문 '선택하신 옵션이 바뀐 메뉴가 있어요. 카트에서 확인해 주세요.'

## 5. 카트·체크아웃의 가격 변동 UI

### 5.0 언제 재가격하고 언제 알리는가

재가격은 `ValidateCheckoutUseCase` 한 곳이 한다. 호출 시점은 선행 design 의 선검증 시점과 **같다**(카트 진입 1회, 앱 포그라운드 복귀, 카트 결제하기 탭, 체크아웃 결제 탭, 빠른 재주문 후 카트 진입). 새 호출 시점을 만들지 않는다.

| 시점 | 변동 발견 시 |
|---|---|
| 카트 자동 선검증 (진입·포그라운드 복귀) | **카트에 적용하고 배너·라인 표시** (§5.1~5.2). 결제로 넘어가지 않으므로 멈출 일이 없다 |
| 카트 '결제하기' 탭 | 이미 배너로 보여 준 변동 외에 **새로 발견된 변동**이 있으면 §5.3 에서 **멈춘다**. 새 변동이 없으면 체크아웃으로 진행 |
| 체크아웃 '결제하기' 탭 | §5.4 시트 (적용 후 결제는 시작하지 않는다) |
| 읽기 실패·타임아웃 | **무음. 재가격 없음, 결제 진행** (N3, spec §8.2). 서버가 거절하면 §4.2 로 간다 |

"이미 보여 준 변동" 의 판별: `cartPriceChangesProvider` 가 현재 카트의 해당 라인을 이미 들고 있고 적용된 가격과 이번 결과가 같다.

### 5.1 카트 라인 (`cart_line_tile.dart`) 가격 변동 표시

입력 추가: `CartLinePriceChange? priceChange` — `{ int before, int after }` (라인 합계 기준). **`CartLineAvailability` enum 은 건드리지 않는다**(P5). 단 옵션 위반은 availability 에 `optionUnavailable` 값을 **추가한다**(위반이며 "확인됨" 의미가 아니다, N2 위반 아님).

가격 변동이 있는 라인의 금액 영역 (기존 `PriceFormatter.formatKrw(item.lineTotal)` 자리):

```
Column(crossAxisAlignment: end)
  Text(이전 금액)   12 / w400 / AppColors.textMuted / lineThrough
  Text(현재 금액)   기존 스타일 (w700 / textHeading)
```

- 행 하단 캡션 (선행 §4.1 캡션 줄과 같은 슬롯, 같은 `AnimatedSize 200ms`):

| 방향 | 문구 | 스타일 |
|---|---|---|
| 올랐을 때 (after > before) | 가격이 올랐어요 | 12 / w600 / `AppColors.warning` |
| 내렸을 때 | 가격이 내려갔어요 | 12 / w600 / `AppColors.info` |

- 아이콘 없음(화살표 아이콘을 쓰면 "상승/하락 차트" 로 읽혀 과하다). 방향은 글자가 말한다.
- 스테퍼·삭제는 **막지 않는다**(가격 변동은 위반이 아니다).
- 접근성: 금액 영역 `Semantics(label: '가격이 {before}원에서 {after}원으로 바뀌었어요')`, 취소선 텍스트는 `ExcludeSemantics`.
- 가격 변동 캡션과 선행 캡션(품절·판매 중단 등)이 겹치면 **품절·판매 중단이 이긴다**(그 라인은 어차피 결제 불가라 금액이 의미 없다). 옵션 위반과 겹치면 옵션 위반이 이긴다(서버 우선순위와 같다).

### 5.2 카트 상단 가격 변동 배너 (신규 `CartPriceChangeBanner`)

위치: 카트 목록 맨 위, **기존 `CartAvailabilityBanner` 위**(둘이 함께 뜰 수 있다). 컨테이너 규격은 선행 §4.2 와 같다(padding 14, 반경 16, 아이콘 18, 제목 14 / w700, 본문 13).

표시 조건: `cartPriceChangesProvider` 에 1건 이상.

| 변형 | 톤 | 제목 | 본문 |
|---|---|---|---|
| 오른 라인만 | `AppColors.warning` alpha 0.08 배경 / alpha 0.35 border, 아이콘 `Icons.price_change_outlined` | 메뉴 가격이 올라 카트 금액을 새로 맞췄어요 | 바뀐 가격으로 카트를 다시 담았어요. 아래 금액을 확인하고 결제해 주세요. |
| 내린 라인만 | `AppColors.info` alpha 0.08 / alpha 0.35 | 메뉴 가격이 내려 카트 금액을 새로 맞췄어요 | 바뀐 가격으로 카트를 다시 담았어요. 아래 금액을 확인하고 결제해 주세요. |
| 섞임 | `AppColors.warning` 톤 | 메뉴 가격이 바뀌어 카트 금액을 새로 맞췄어요 | 바뀐 가격으로 카트를 다시 담았어요. 아래 금액을 확인하고 결제해 주세요. |

금액 행 (본문 아래 10px): `Row(mainAxisAlignment: spaceBetween)`
- 좌: 합계 (13 / w500 / `textBody`) 라벨 '합계'
- 우: `{이전 합계}  →  {현재 합계}` — 이전은 13 / `textMuted` / lineThrough, 화살표는 문자 '→' (아이콘 아님), 현재는 15 / w700 / `textHeading`
- 숫자는 `PriceFormatter.formatKrw(int)`. **서버가 준 문자열을 쓰지 않는다**(D4 유지, 예외 불필요). 이전 합계는 재가격 직전 카트의 `subtotal`, 현재 합계는 적용 후 `subtotal`.

버튼: 우측 정렬 TextButton **확인했어요** (13 / w700 / `AppColors.primaryBright`, 터치 44). 탭 → `cartPriceChangesProvider` 비움 → 배너와 라인 표시가 `AnimatedSize` 로 사라진다. **"확인했어요" 는 사용자가 읽었다는 표시이지 가격이 검증됐다는 표시가 아니다.** 사라진 뒤에 어떤 문구도 남기지 않는다.

- `Semantics(liveRegion: true)` — 화면에 새로 나타날 때 스크린리더가 읽는다.
- 배너 소거 시점: '확인했어요', 카트 비우기, 해당 라인 삭제(그 라인 몫만), 결제 성공, 앱 재시작. **수량을 바꾸면 소거하지 않는다**(가격 변동은 단가의 사실이다).

### 5.3 카트 '결제하기' 탭에서 새 변동이 발견되면 (멈춤)

선행 §4.3 의 ③④ 를 확장한다. 탭 → 스피너 → 신선 선검증(3초):

| 결과 | 동작 |
|---|---|
| 옵션 위반 / 품절 / 판매 중단 / 매장 불가 | 선행 §4.3 ④ 와 같다 (체크아웃으로 가지 않고 첫 위반 행으로 스크롤). 옵션 위반 라인은 §5.5 |
| **가격 변동 (새로 발견)** | 카트에 적용 → 배너 + 라인 표시 → **체크아웃으로 가지 않는다** → 첫 변동 행으로 스크롤(`Scrollable.ensureVisible`, 250ms). 토스트·다이얼로그 없음 |
| 변동 없음 / 읽기 실패 | 기존대로 체크아웃으로 push |

- **멈추는 이유**: 금액이 바뀐 상태로 결제 화면에 들어가면 고객이 "내가 본 금액" 과 다른 금액을 결제하게 된다. 카트에서 한 번 멈춰 새 금액을 보여 주고, 고객이 **한 번 더 탭하는 것이 동의**다. 이 한 번의 탭은 다음 신선 선검증도 겸한다(변동이 없으면 통과).
- 오름·내림·섞임 모두 같은 규칙으로 멈춘다(규칙 하나 = 분기 하나 적음). 내림만 있을 때 멈추지 않는 안은 Q-D1.
- 멈춘 뒤 '결제하기' 버튼은 평소와 같다. 배너가 합계를 보여 주므로 버튼 라벨을 바꾸지 않는다.

### 5.4 체크아웃 '결제하기' 탭에서 변동이 발견되면 (시트)

선행 §4.4 시트를 재사용한다(핸들·반경·패딩 동일). 이 시점은 이미 체크아웃 안이고 Toss 창 직전이다.

우선순위: **옵션 위반 > 가격 변동**(서버 사유 우선순위와 같다). 품절/중단/매장 불가가 있으면 선행 시트가 우선이다.

**가격 변동 시트**

| 요소 | 문구 / 규격 |
|---|---|
| 제목 | 결제 금액이 바뀌었어요 |
| 본문 | 메뉴 가격이 바뀌어 금액을 새로 맞췄어요. 결제는 아직 시작되지 않았어요. |
| 합계 행 | '합계' 라벨 + 이전(취소선, textMuted) → 현재(15 / w700) — §5.2 와 같은 포맷 |
| 변동 목록 카드 | 선행 §3.5 카드 재사용, 헤더 '가격이 바뀐 메뉴'. 행: 메뉴 이름(좌, Expanded, 2줄 말줄임) + 우측 `{이전} → {현재}` (13, 이전 취소선 muted / 현재 w700). 전부 열거, 시트 본문 스크롤 |
| 주 버튼 | 새 금액으로 계속하기 |
| 라인 버튼 | 카트에서 확인하기 |

- **카트 적용은 시트가 뜨는 순간 이미 끝나 있다**(시트를 아래로 밀어 닫아도 stale 상태가 남지 않는다 — 이 설계의 핵심 안전 장치). 시트는 알림이다.
- '새 금액으로 계속하기': 시트 닫기 → **체크아웃에 머문다.** 합계·결제 버튼 라벨이 새 금액으로 갱신된 것을 고객이 보고 직접 다시 탭한다. **자동 결제하지 않는다.**
- '카트에서 확인하기': 시트 닫기 → 체크아웃 pop → 카트(배너·라인 표시 있음).
- 시트 바깥 탭/스와이프: 시트만 닫는다. `_processing` 해제.
- "그래도 이전 금액으로 결제" 는 **없다**(서버가 거절한다).

**옵션 위반 시트** (선행 §4.4 시트의 새 변형)

| 요소 | 문구 |
|---|---|
| 제목 | 옵션을 다시 골라야 해요 |
| 본문 | 아래 메뉴에서 고르신 옵션을 지금은 선택할 수 없어요. 결제는 아직 시작되지 않았어요. |
| 목록 헤더 | 옵션을 다시 골라야 하는 메뉴 |
| 주 버튼 | 카트에서 옵션 다시 고르기 |
| 라인 버튼 | 이 메뉴 빼기 (여러 개면 '이 메뉴 모두 빼기') |

- 주 버튼: 시트 닫기 → 체크아웃 pop → 카트(해당 행에 §5.5 표시).
- 라인 버튼: 선행 '이 메뉴 빼기' 동작과 같다.

### 5.5 옵션 위반 행 (DQ5 — 옵션 라벨 단위)

`CartLineAvailability.optionUnavailable` — 클라이언트의 `resolveSelectableOptions` 가 **어떤 selectedOption 이 불가인지 특정**한 경우.

- 옵션 요약 줄(`item.selectedOptions.map(label).join(' · ')`)을 `Text.rich` 로 바꿔, 불가 옵션 라벨만 `AppColors.error` + 취소선으로 칠한다. 나머지 라벨은 기존 스타일.
- 행 하단 캡션: 선택할 수 없는 옵션이 있어요 (12 / w600 / `AppColors.error`)
- 행 가격은 **재계산하지 않고 담은 가격 그대로** 둔다(불가 옵션이 낀 라인은 유효한 가격이 없다). 합계 아래 선행 §4.3 의 보조 줄 문구를 이 경우에도 쓴다: 확인이 필요한 메뉴 N개가 포함된 금액이에요 (11 / `textMuted`; 선행 문구 '품절·판매중단 메뉴 N개가 포함된 금액이에요' 를 '확인이 필요한 메뉴 N개가 포함된 금액이에요' 로 일반화).
- 행 동작: 스테퍼 비활성(`IgnorePointer`, 선행 soldOut 과 같음). 버튼 두 개 — 캡션 오른쪽 `Row`:

| 버튼 | 스타일 | 동작 |
|---|---|---|
| 다시 고르기 | TextButton 13 / w700 / `AppColors.primaryBright`, 터치 44x44 | 해당 라인을 카트에서 제거하고 그 메뉴의 `menu_item_detail_page` 를 push. 고객은 그 자리에서 옵션을 다시 골라 담는다. 취소하고 돌아오면 라인은 이미 빠져 있다 — **원래 결제가 불가능했던 라인이므로 잃는 것이 없다.** 확인 다이얼로그 없음 |
| 빼기 | 선행 §4.1 '빼기' 와 동일 | `onRemove` |

- 메뉴 상세가 `_DeletedView` 면(메뉴 자체가 사라짐) 선행 그대로 '매장 메뉴 보기' 가 복구다.
- **클라이언트가 옵션을 특정하지 못하는 경우**(서버만 지목했고 클라 선검증은 정상/실패): 선행 `rejectedByServer` 행 상태를 쓴다. 캡션만 다르다: 직전 결제에서 옵션이 바뀐 메뉴예요. 지금은 다시 바뀌었을 수 있어요 (12 / w500 / `AppColors.warning`). 스테퍼는 활성, '빼기'·'다시 고르기' 노출.
- **카트 배너**: 선행 `CartAvailabilityBanner` 의 변형 1개 추가 —

| 변형 | 제목 | 본문 |
|---|---|---|
| 옵션 위반 | 옵션을 다시 골라야 하는 메뉴가 있어요 | 표시된 메뉴의 옵션을 다시 고르거나 빼고 결제해 주세요. |

  버튼 '다시 확인' 은 선행과 같다.

### 5.6 상태 (카트·체크아웃 가격 변동)

| 상태 | 정의 |
|---|---|
| loading | 자동 선검증 중: **표시 없음** (N1). 카트 결제하기 탭 / 체크아웃 결제 탭: 버튼 스피너 (선행과 동일) |
| error | 자동 선검증 실패: **표시 없음, 라인은 담은 가격 그대로** (N3). 거절 화면의 재가격 실패: §4.2 인라인. 카트 '다시 확인' 실패: 선행 SnackBar |
| empty | 재가격 결과로 카트가 비는 일은 없다(가격만 바꾼다). 품절 제거는 선행 UI. 모든 라인이 옵션 위반이어도 카트는 비지 않는다 |
| 변동 없음 | **표시 없음.** 배너도 문구도 없다. 이것이 '확인됨' 이 아닌 이유는 확인 실패와 구분되지 않기 때문이다 (P5) |

## 6. 사용자 확인이 필요한 결정 (Q)

spec Q1~Q8 로 확정된 것은 다시 열지 않았다. 아래는 이 디자인이 새로 만든 갈림길이다. **추천안을 문서에 반영해 두었으므로** 사용자가 바꾸면 해당 절을 고친다.

### Q-D1. 가격이 **내려가기만** 했을 때도 카트에서 멈추는가 (§5.3)

| 안 | 내용 | 대가 |
|---|---|---|
| **ⓐ 오름·내림·섞임 모두 멈춘다 (추천, 반영됨)** | 규칙 하나. 새 변동은 항상 카트에서 한 번 보여 주고 한 번 더 탭 | 가격이 내려가 고객에게 이득인데도 한 번 더 누르게 한다. 분기가 적고 "조용히 바뀌는 것은 사고다" 에 가장 충실하다 |
| ⓑ 내림만이면 멈추지 않고 체크아웃으로 진행 | 체크아웃에 '가격이 내려갔어요' 알림을 따로 둬야 한다 | 마찰은 줄지만 체크아웃에 알림 표면이 하나 더 필요하고 테스트 경우가 는다 |

### Q-D2. 오류 코드 캡션(선행 Q2)을 변형 N 에도 보이는가 (§4.2)

선행 Q2 는 갈래 C 와 갈래 A 기본 문구 화면에서만 코드를 보이기로 했다. 변형 N 은 갈래 B(알려진 사유)이지만 **"재가격해도 안 풀리는 경우" 라 고객이 문의할 가능성이 가장 높은 화면**이다.

| 안 | 내용 | 대가 |
|---|---|---|
| **ⓐ 변형 N 에 PRICE_MISMATCH 코드 캡션 (추천, 반영됨)** | 형식 검증을 통과한 토큰만. 원문이 아닌 식별자 | 선행 Q2 의 허용 범위를 한 화면 늘린다. 선행 Q2=ⓑ(전혀 노출 안 함)였다면 이 줄을 뺀다 |
| ⓑ 노출 안 함 | 변형 N 의 보조 본문에서 '오류 코드와 함께' 문구도 뺀다 | 문의 때 식별 수단이 사라진다 |

### Q-D3. 사용자가 직접 누르는 재가격의 타임아웃 (§4.2)

| 안 | 내용 | 대가 |
|---|---|---|
| ⓐ 3초 (자동 선검증과 동일) | 규칙 하나 | 느린 망에서 사용자가 직접 요청한 동작이 실패하기 쉽다 |
| **ⓑ 5초 (추천, 반영됨)** | | 직접 누른 동작은 기다릴 의사가 있다. 5초를 넘기면 인라인 오류로 정직하게 알린다 |

## 7. 개발자 / 테스터 전달 사항

### 7.1 개발자

- **신규 위젯**: `CartPriceChangeBanner`, `CheckoutPriceChangedSheet`(+ 옵션 위반 변형, 선행 `CheckoutBlockedSheet` 확장 가능), 거절 화면 변형 N, 카트 행의 가격 변동 영역·옵션 라벨 `Text.rich`. 메뉴 목록 카드는 **선행 위젯 재사용**(아이콘만 파라미터).
- **신규 도메인**: `ApplyRepricedCartUseCase` — 재가격 결과(라인별 새 `unitPriceWithOptions`/`lineTotal`)를 로컬 카트에 반영하고 `CartLinePriceChange` 목록을 반환. presentation 이 금액을 계산하지 않는다(spec §15 레이어 규칙).
- **신규 provider (모두 메모리 전용, 앱 재시작 시 소거)**: `cartPriceChangesProvider`(라인별 `{before, after}`), `priceRepricedCartSignatureProvider`(String?). 소거 시점은 §5.2 와 §2 P2.
- **`CartLineAvailability`**: `optionUnavailable` 값만 추가. `verified` / `ok` / `priceChecked` 추가 금지 (선행 N2 가드가 이미 막는다 — 가드 테스트에 새 값 이름 3개를 추가).
- **`PaymentFailure`**: `reason` 에 2개 추가. 선행 가드 "알려진 사유 각각이 표의 헤드라인·버튼을 가진다" 가 8개를 요구한다 — 변형 N 은 같은 reason 의 화면 변형이므로 **헤드라인·버튼 표에 별도 행**(변형 N)을 넣는다.
- **가드 테스트 추가 제안**:
  - 거절 화면과 카트 가격 변동 문구에 **조작 / 비정상 / 위조 / 변조 / 부정 / 의심** 이 없다(문자열 상수 전수).
  - 거절 화면 문구 상수에 **백틱 문자가 없다**(선행 F-04 재발 방지).
  - `PRICE_MISMATCH` / `OPTION_UNAVAILABLE` 거절 화면에 **원 단위 숫자가 없다**(정규식 `\d{1,3}(,\d{3})*원` 이 거절 화면 문구에 매치되지 않음 — Q6=ⓒ 고정). 금액 숫자는 카트 위젯에서만.
  - `PRICE_MISMATCH` 주 버튼 콜백이 `Navigator.pop` 단독이 아니다(재가격 호출을 포함) — 위젯 테스트로: 버튼 탭 시 UseCase 호출 1회 + 성공 시 pop.
  - 재가격 읽기 실패 시 **pop 이 호출되지 않고** 인라인 오류가 보인다.
  - 변형 N 에는 '최신 가격으로 다시 담기' 버튼이 없다.
  - 가격 변동 표시 위젯에 `AppColors.success` 사용 0건.
  - admin 앱에 `PAYMENT_PRICE_MODE` 참조 0건 (P7 — 모드 UI 없음).
- **재사용**: `SoldOutOverlay` 는 이번에 쓰지 않는다(가격 변동·옵션 위반은 품절이 아니다). `PriceFormatter.formatKrw` 로 모든 금액 포맷.
- **자동 선검증의 재가격 적용 위치**: 카트 진입·포그라운드 복귀 호출의 결과도 `ApplyRepricedCartUseCase` 로 적용한다. 단 **읽기 실패는 아무것도 적용하지 않고 아무 표시도 하지 않는다.**
- 문서 갱신 제안: 선행 design 에 포인터를 넣었다(§2, §3.1 말미). `role_flows.md` 변경 없음(새 화면·진입점 없음).

### 7.2 테스터

- **무한 루프 탈출**: 카트에 담은 뒤 점주가 메뉴 가격을 바꾼다 → 결제 → 거절 화면 → '최신 가격으로 다시 담기' → 카트에 배너·라인 표시 → '결제하기' → **결제 성공**. 이 경로가 PASS 여야 한다. (선행 FAIL 패턴: 표에 그 행이 없었다 — 이 경로가 표 6-3·6-4·6-5 에 있다.)
- 재가격 버튼을 **네트워크 차단 상태에서** 눌러 이 화면에 머무는지, 인라인 오류와 '다시 불러오기' 가 뜨는지, 카트로 이동하지 않는지.
- 재가격 후에도 거절되는 경우(점주가 카트 담은 직후 결제 직전에 다시 바꿈) → 두 번째 거절이 **변형 N** 인지, 그 화면에 재가격 버튼이 없는지, '카트 비우고 메뉴 보러가기' 로 새로 담아 결제가 성공하는지.
- 오름 / 내림 / 섞임 각각의 배너 제목·톤과 라인 취소선·캡션. 내림에 초록이 쓰이지 않았는지.
- 체크아웃 결제 탭에서 변동 발견 시 시트가 뜨고, 시트를 **스와이프로 닫아도** 합계가 새 금액인지(적용 선행).
- 옵션 비활성 후 결제 → 거절 화면 메뉴 이름 → 카트에서 **불가 옵션 라벨만** 취소선인지, '다시 고르기' 가 라인 제거 + 메뉴 상세 이동인지.
- 거절 화면 전 문구에 금액 숫자가 없는지(목록 카드 포함).
- 모든 문구에서 조작/비정상/위조 계열이 없는지, 화면에 백틱이 출력되지 않는지.
- 빠른 재주문(옛 단가 역산) → 카트 진입 시 배너가 뜨고 금액이 현재 가격과 일치하는지.
- 가격 변동이 없을 때 **어떤 가격 표시도 없는지**(N1 — 통과를 암시하는 요소 금지).
